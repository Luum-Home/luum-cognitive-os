## Decision

Three decisions to slim the SO: (D1) agents verify TARGETED (only files they touched) while the orchestrator verifies GLOBAL (full suite) once at Stop; (D2) reduce context overhead — silence the self-install banner on cache-hit, migrate `~/.claude/CLAUDE.md` to a compact ref-key index, and collapse four overlapping per-Agent-launch advisory hooks into one merged preamble; (D3) reduce resource consumption — lazy-start non-essential MCP servers, rotate JSONL metrics by size/age, merge three post-Agent completion-gate hooks into one, and promote the `lean` efficiency profile as adaptively selectable default.

## Why

Three measured debt classes: (1) test verification was unbounded — with 3 parallel agents per sprint each inheriting `pytest tests/unit/` as its acceptance criterion, the full suite ran 3x redundantly, and the literal command was hard-coded across ≥7 skill manifests rather than defined in one place; (2) context overhead was opaque and large — CLAUDE.md alone was ~6,031 estimated tokens loaded on every session and sub-agent, and four `PreToolUse Agent` hooks (blast-radius, scope-proportionality, project-gotchas, completeness-check) fired on every agent launch with ~40-60% heuristic overlap between pairs; (3) resource consumption grew silently — JSONL metrics were unbounded append-only (~8.7 MiB, no rotation), 27 hook entries were registered in `.claude/settings.json`, and a 49-minute debugging session on 2026-04-17 was measurably extended by hook noise. This ADR is explicitly planning + measurement only, producing a measured baseline and three feature-flagged decisions carved into three parallelizable implementation phases.

## Consequences

Positive: eliminates 3x redundant full-suite runs per sprint (targeted vs. global split); CLAUDE.md target ≤1,200 tokens (later corrected from an initially-infeasible ≤400 target per ADR-027a); per-Agent-launch context target ≤400 tokens (down from 525-1,175); idle MCP RSS target ≤150 MiB (down from ~630 MiB); JSONL growth capped at ≤20 MiB steady state; hook runtime p95 target ≤120ms (down from ~210ms).

Negative/trade-offs: `.claude/settings.json` and `scripts/apply-efficiency-profile.sh` are contended files that require serialized ownership (Phase 3 as designated lock owner, with Phases 1 and 2 filing PRs against it) — Path A (Phase 3 first, then Phases 1+2 in parallel) was chosen over strict serialization for an estimated 25-30% wall-clock savings; every measurement carries explicit uncertainty (MCP RSS ±10-20%, hook-runtime percentiles ±20-30% due to non-uniform `hook-health.jsonl` schema, per-agent-launch token counts are a bounded heuristic not an exact measurement).

## Status & current state

Accepted 2026-04-21, implementation_status "implemented" — WS1-WS3 shipped and included in v0.12.0 (commits `8dc4a6e`, `9bd895b`, `15d67eb`). Resolved and corrected by addendum ADR-027a (CLAUDE.md token target corrected from ≤400 to ≤1,200 as the lower figure was mathematically infeasible given session-mandatory inline decisions; the `scripts/compact-claude-md.py` migration helper was removed as redundant with the `EXCLUDED_RULES` mechanism already shipped in `hooks/self-install.sh`). ADR-027 Phase 3 (resource work) was explicitly blocked pending ADR-028's observability Phases A+B landing first, to avoid repeating the orphan-leak failure class blind.
