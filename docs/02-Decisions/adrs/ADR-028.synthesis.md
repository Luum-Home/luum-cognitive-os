## Decision

Establish a 6-pillar SO Reliability & Observability Framework: (D1) runtime observability (metrics census, process registry + reaper, sub-agent heartbeat, unified `so-vitals` dashboard), (D2) contract tests for hooks (orphan/FD/RAM/latency assertions), (D3) a read-only systematic hook audit, (D4) systematic fixes via canonical patterns across parallel sonnet agents, (D5) SLOs + error budget + incident runbook + emergency kill-switch, (D6) chaos engineering suite.

## Why

Bug 1: the disabled baseline block in `hooks/session-init.sh:120-128` ran the full pytest suite backgrounded on every SessionStart via `( … ) &`; children inherited file descriptors and were never reaped, producing 190 orphaned `session-init.sh`, 187 orphaned `pytest`, and 49 orphaned `pre-commit-gate.sh`/`coverage-report.sh` processes (~300 MiB) — authored with good intent (WS11 anti-confirmation-bias) but no hook test asserted "leaves the system clean," only exit-code and stdout. Bug 2: `git reflog` showed repeated `reset: moving to HEAD` entries during a window when symlink fixes were in flight — the culprit hook was never identified, only worked around. Bug 3: `.git/index.lock` held ~2h by a dead process from a crashed hook chain, blocking all commits. The common thread: the SO spawns, never reliably reaps, sometimes destroys, and emitted no runtime telemetry that would have surfaced any of the three within a session — a framework-level gap, not three isolated bugs.

## Consequences

Positive: single dashboard (`so-vitals.sh`) for agents/processes/orphans/MCP RSS/JSONL rotation/hook p50-p95; contract tests would have caught the historical `session-init.sh` orphan bug as a regression fixture; SLO catalogue makes "healthy vs. degraded" measurable with an error budget; emergency kill-switch restores minimal mode in ≤3s.

Negative/trade-offs: heartbeat writes add per-agent overhead (mitigated by overwrite-only strategy); contract tests risk flakiness on slow CI (20% SLO tolerance, demote-after-3-flakes policy); Bug 2's root cause (the git-reset-cascade hook) remained unidentified at ADR acceptance time, gated as a BLOCKER prerequisite before the D3 audit could safely run; reaper auto-kill of unregistered orphans defaults OFF to avoid killing legitimate long-running work.
