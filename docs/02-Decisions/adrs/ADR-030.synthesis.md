## Decision
Wire two opt-in, advisory-only auto-trigger mechanisms, neither of which replaces manual invocation. Q1: a `UserPromptSubmit` hook (`hooks/session-wrapup-trigger.sh`) regex-matches closure phrases ("close the session", "we are done", "wrap up the session", etc.) and emits an `AUTO-TRIGGER:` line in `additionalContext` instructing the orchestrator to invoke `/session-wrapup` before any other action (unless the user countermanded it in the same message) — enforced via a rule added to `templates/agent-preamble.md`. Q2: a post-commit hook writes a breadcrumb (`.cognitive-os/runtime/commit-nudge`); the next `SessionStart` surfaces a banner ("Commits since last wrapup: N") if a same-day commit is recorded; `/session-wrapup` deletes the breadcrumb as its last step. Q2 is explicitly NOT a direct trigger — git hooks can't invoke skills mid-commit — it's a delayed nudge at the next session start. A "Q2-hard" variant (git hook directly invokes the skill) was considered and rejected as requiring a daemon/API/auth architecture lift not worth it for a convenience feature.

## Why
Because Claude Code hooks cannot read raw conversation transcripts (a prior ADR proposal to read `.cognitive-os/sessions/*/transcript.jsonl` was found to be incorrect — those files don't exist), whether the orchestrator actually *honours* the Q1 auto-trigger can't be unit-tested directly. The ADR adopts a log-then-reconcile approach instead: `hooks/session-wrapup-trigger.sh` logs every AUTO-TRIGGER emission and `hooks/skill-invocation-logger.sh` logs every Skill tool call, then `tests/integration/test_auto_trigger_honoured.py` pairs emissions with subsequent invocations within a 60-second window to compute a compliance rate.

## Consequences
Positive/testable paths exist for both mechanisms (Q1 via 5+ regex-variant unit tests plus the honour-compliance integration test; Q2 via a fully hermetic tmp_path integration test simulating git commits and session-init banner surfacing). Negative/residual risks: R-A over-trigger (regex false positives like "close **this file**" — mitigated by whole-word match + negative lookahead, measured over 2 weeks, tighten if >5%); R-B banner noise if the user commits many times daily (mitigated by a 24h staleness cap); R-C orchestrator disobedience (fails open — worst case the skill just isn't invoked, same as before this ADR — detected via the compliance-rate integration test, but "user countermanded" is indistinguishable from "orchestrator ignored" at this measurement layer).

## Status & current state
Status: accepted / implementation_status: partial. All listed acceptance checkboxes are marked done (hook exists and is registered, ≥5 behavioral tests pass, preamble has the AUTO-TRIGGER honour rule, post-commit hook extended, session-init extended, SKILL.md clears the nudge, ≥6 hermetic integration tests pass). The `partial` classification reflects that the post-commit banner is inherently a deferred/delayed trigger (not a direct one) and that a true externally-invoked `/session-wrapup` would require daemon/API/auth work intentionally out of scope for this ADR. The honour-compliance test only starts accumulating data after the two hooks are wired, so historical sessions aren't retroactively testable, and the compliance threshold (80%) currently only logs a warning to engram rather than hard-failing — tuning is deferred pending 2 weeks of data.
