## Decision
Introduce a `HarnessAdapter` abstraction under `lib/harness_adapter/`: an ABC with `detect_harness`/`parse_event`/`emit_canonical`, a canonical event schema (`AgentStart`, `AgentEnd`, `ToolUse`, `TokenUsage`, `HeartbeatTick`), a `dispatch.handle_event` module that shell hooks/watchers call with raw payloads, a reference Claude Code adapter that preserves legacy side effects byte-compatibly, and a passive-file-watcher POC adapter for Aider. Existing hooks (`hooks/native-agent-heartbeat.sh`) become thin shims forwarding stdin to dispatch.

## Why
Two partial capture mechanisms already existed in the tree (native-agent-heartbeat.sh + ClaudeExecutor) with no schema convergence between them — the debt was real, not hypothetical. Each consumer (SLO dashboards, cost reports, error-learning pipeline) had to re-parse harness-specific shapes. The codebase already hinted at harness-abstraction intent (`ORCHESTRATOR_MODE`, session banner, README roadmap) but only Claude Code was actually wired, so adding a new harness or a CC hook-schema version change would require a rewrite rather than an additive change.

## Consequences
- Positive: adding a new harness means one new adapter file + one line in `dispatch.ADAPTERS`, no touch to SLO/cost/rule logic; canonical events are pure dataclasses, unit-testable without running a harness; existing `agent-heartbeat.jsonl` readers see no regression (integration test 4/4 passing).
- Negative: each harness adapter requires ongoing maintenance as its payload schema drifts (mitigated by graceful degradation to empty event list); downstream readers now depend on the canonical schema, so changes require ADR amendments and a deprecation window; a two-stream transition period writes both legacy and canonical JSONL (~20 bytes/event extra, bounded by existing rotation policy).

## Status & current state
Accepted, implementation_status: partial. Rollout is phased v0.13→v0.15.0: v0.13 (this ADR) ships the base + CC adapter + Aider POC with both streams written; v0.14 migrates cost-events.jsonl capture to the same layer; v0.15.0 deprecates the legacy stream with a read-side shim. As of this ADR, the Executor becoming its own capture-source adapter is explicit future work, not yet done.
