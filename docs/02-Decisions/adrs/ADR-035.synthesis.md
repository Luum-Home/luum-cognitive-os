## Decision
A 3-layer defense-in-depth. Layer 1 (this ADR, implemented): `hooks/session-start-worktree-nudge.sh` fires on SessionStart, detects a non-main worktree by checking whether `.git` is a file (worktree link) vs directory (main worktree), and emits a prominent `WARNING: WORKTREE DETECTED` `additionalContext` message with the current worktree path/branch, resolved main path, three actionable suggestions, and the active `orchestration.sub_agent_cwd` policy — logged to `worktree-nudges.jsonl`. Layer 2 (existing): `agent-working-dir-inject.sh` (PreToolUse:Agent) injects a `WORKING DIR:` directive per the `sub_agent_cwd` policy (`current`/`main_worktree`/`branch`), and `agent-bash-cwd-enforcer.sh` (PreToolUse:Bash) warns (does not block) when a sub-agent's git command would operate on a worktree branch. Layer 3 (pending, separate task): upgrade the enforcer from warn to command-rewrite mode — transparently prepending `cd <main-path> &&` or using `git -C <main-path>` — the only layer providing guaranteed (not advisory) enforcement, requiring a HALT-and-WAIT gate on first activation.

## Why
The problem is silent and surprising by construction: there is no error, commits simply accumulate on an unintended branch (often a short-lived Claude-managed branch like `claude/gracious-burnell-5a757d`). Alternatives considered and rejected: a git-level pre-commit hook (fragile — requires per-worktree setup, warns only at commit time, cannot inject the correct path, only blocks); orchestrator chdir at startup (not exposed by Claude Code, and would break the user's own relative-path workflows); disabling worktree support entirely (worktrees are used intentionally for branch isolation, a core workflow feature).

## Consequences
Positive: Layer 1 eliminates silent surprise since the warning is in the session transcript even if ignored; the 3-layer design has no single point of failure; Layers 1-2 are advisory-only with zero risk of blocking legitimate worktree work; `orchestration.sub_agent_cwd: current` provides a clean opt-out; the nudge log enables usage analytics. Negative: users who deliberately work from a worktree see the Layer 1 nudge every session (mitigated by the opt-out); ~10-20ms added to session start for the `git worktree list --porcelain` call (within the SessionStart SLO budget); Layer 3's command-rewriting is non-trivial and risks breaking legitimate git invocations, hence deferred with its own review gate.

## Status & current state
Accepted (2026-04-20). Layer 1 is deployed and registered in `default`/`full` profiles. Layer 2 was already deployed pre-ADR (no change required). Layer 3 is explicitly "Not yet implemented — planned as a follow-up task," requiring design review of the rewrite logic, a HALT gate on first activation, and test coverage for rewrite edge cases — this is the concrete PARTIAL remainder.
