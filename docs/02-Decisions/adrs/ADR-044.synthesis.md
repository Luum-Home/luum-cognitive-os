## Decision
Adopt a tiered (T1/T2/T3) context loading model for everything non-rule (a paired Agent B ADR, ADR-043, covers rule payload separately). T1 (always loaded): identity, date, cwd, git branch, ≤1-line pointers. T2 (lazy on trigger): full protocol text loaded via slash commands — `/engram-help` for the Engram protocol, `/sdd-help` for the SDD pipeline spec, `/rules-expand` for rule detail, `/skills-search` for full skill descriptions. T3 (lazy on demand): full skills catalog entries and tool schemas (already lazy via ToolSearch precedent). Concretely: compress the ~525-token Engram protocol block in global CLAUDE.md to a 3-line summary + `/engram-help` pointer (saves ~450 tokens); same treatment for the ~800-token SDD pipeline spec via `/sdd-help` (~700 tokens); add a `summary_line` (≤80 char) SKILL.md frontmatter field so the harness-injected skills catalog can shrink from ~3,500 to ~2,500 tokens; audit SessionStart hook stdout to emit only actionable one-liners. Backward-compatible and opt-in: old CLAUDE.md persists until a user runs `scripts/startup-slim.sh --apply`; slash commands are additive, and agents fall back to reading the source file directly if a slash command is missing.

## Why
Session TTFT scales with ingested tokens on every single session start, and most of that ~8,175-token payload (Engram protocol prose, SDD pipeline detail, full skill descriptions) is only actually needed by a small fraction of sessions/tasks — the tiered model lets agents pull detail on demand via the same mental model that already works successfully for deferred tool schemas (ToolSearch).

## Consequences
Positive: conservative target of ~40% non-rule payload reduction (33KB→20KB, ~3,300+ tokens), stacking multiplicatively with Agent B's separate rule-slimming work; new users no longer drown in a 200-line CLAUDE.md on first read; upstream harness skill-catalog injection becomes tractable to shrink since COS owns the frontmatter even though the harness owns the injection mechanism itself. Negative/risk: agents that relied on implicit protocol context now must remember to invoke a slash command (mitigated by clear T1 pointers); slash commands must stay synced with canonical source files or go stale (mitigated by sourcing directly, no duplication); harness-controlled surfaces (skills catalog, deferred tools, MCP instructions) can only be shrunk at the edges COS controls — if the harness adds new mandatory context, savings erode; if an agent forgets to invoke the expansion command it may guess and miscall a tool.

## Status & current state
Accepted; `implementation_status: partial-blocked`, explicitly `blocked_on: .claude/commands/ write permission for slash-command projection`. Phase 2 partially resolved 2026-04-21: the `summary_line` frontmatter convention was migrated onto 88 of 125 skills in one pass (2 skills' missing `description` fields also fixed), `scripts/generate_compact_catalog.py` updated to prefer `summary_line`, and `skills/CATALOG-COMPACT.md` shrank from 13,019 to 11,941 chars (~270-token reduction, ~8%). BLOCKED: all four planned slash commands (`/engram-help`, `/sdd-help`, `/skills-search`, `/rules-expand`) could not be created — the session's sandbox denied both `mkdir .claude/commands` and `Write` under that path; unblocking requires either an out-of-sandbox pass with elevated permissions or a settings.json allowlist entry. Global `~/.claude/CLAUDE.md` slimming itself remains explicitly deferred to an opt-in Phase 3 (`scripts/startup-slim.sh`, not yet built) since the file is user-owned. Measurement tooling (`startup-tokens-probe.sh` to empirically validate before/after token counts) is also not yet built — all savings figures in this ADR are design targets, not measured actuals.
