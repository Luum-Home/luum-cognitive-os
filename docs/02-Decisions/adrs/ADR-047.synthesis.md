## Decision

Introduce a Session Lifecycle Management (SLM) subsystem: a psutil-based watchdog daemon (`scripts/so_session_watchdog.py`) enforcing TTL + idle heuristics + TTFT (time-to-first-token) alerts, a session registry, TTFT-tracking hooks, a cross-platform shell helper library (`hooks/_lib/portable.sh`), and a semaphore limiting concurrent engram MCP children. Rollout is two-phase: Phase A logs only (never kills) for 2 weeks to calibrate a false-positive gate; Phase B enforces kills only after the gate passes.

## Why

Four root causes: (1) the existing reaper (`scripts/so-reaper.sh`) only kills PIDs it registered itself — it never tracks the main `claude` process, so a crashed/detached terminal leaves the harness process unreapable; (2) each session spawns its own `engram mcp --tools=agent` child with no shared transport, so N sessions produce N MCP children hammering one `engram serve` backend (8+ children observed, causing SQLite lock contention); (3) no hard wall-clock TTL exists per session — cleanup depends entirely on the user closing the tab cleanly, which silently fails on crash/SIGKILL/lid-close; (4) no TTFT watchdog exists, so a session stuck in a long silent reasoning loop is invisible to supervision — it looks "alive" to the OS and "silent" to every hook.

## Consequences

Positive: SLO 4 restored (the `xfail` in `tests/unit/test_session_leak_detection.py` designed to flip to pass); engram MCP contention bounded by a semaphore (max 4 concurrent children); TTFT watchdog provides the first supervision signal for silent reasoning loops; the portable.sh library eliminates GNU-vs-BSD command drift going forward.

Negative/trade-offs: the single highest-severity risk is killing an active user session and losing uncommitted work — mitigated by a layered activity probe (parent-liveness as a hard orphan signal, heartbeat freshness as primary, metric-write freshness as secondary, sustained CPU activity as tertiary — all three of heartbeat/metric/CPU must agree "stale" before a TTL-breached session is killed), a 30s SIGTERM-before-SIGKILL grace period, a 2x TTL-reset cap, an opt-out env var, and a global kill-switch. The original TTY-atime liveness design was empirically invalidated on macOS (Claude.app sessions have no controlling TTY, confirmed via `ps`/`lsof`) and replaced by the layered probe (documented as AMENDMENT §A).

## Status & current state

Proposed 2026-04-20, still gated. Phase A (log-only) is DELIVERED (`lib/session_watchdog_lib.py`, `scripts/so_session_watchdog.py`, 50 unit tests passing). Phase B (enforce/kill) is explicitly BLOCKED — the 2026-04-21 gate evaluation collected 162 total watchdog records over only 7 hours (not the required 2-week/336h observation span), of which just 42 were flagged detections spanning only 2 distinct PIDs (need ≥50 flagged detections), and those 2 flagged PIDs both resumed within 24h for a measured 100% false-positive rate, so all three gate criteria failed and enforcement hardening was shipped that refuses to activate kill-mode even if config says otherwise. Several Phase B components (`session-ttl-register.sh`, TTFT hooks, engram-MCP semaphore wrapper) remain NOT YET IMPLEMENTED as of the ADR body; only `hooks/session-heartbeat.sh` (the liveness signal) had already shipped.
