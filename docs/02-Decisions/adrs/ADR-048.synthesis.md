## Decision
A 4-layer defense: (1) `scripts/cos-config-audit.sh` gains a `meta.docker_container_freshness` contract comparing the compose file's `@sha256:` pin against each running container's `Config.Image` (not `.Image` — see meta-incident below); (2) `hooks/docker-drift-detector.sh` runs on SessionStart, fast and graceful-degrading, emitting a one-line WARNING on drift but never auto-recreating (recreation can sever live connections); (3) `templates/project-gotchas.md` documents the pin-update gotcha for sub-agents; (4) `scripts/cos-update.sh` gains `recreate_docker_if_compose_changed()`, tracking the compose file's SHA-256 and running `docker compose pull && up -d --force-recreate --no-build` when it changes, mirroring the existing settings-freshness auto-regeneration pattern. `--no-build` is deliberate: a broken local Dockerfile build (e.g. nemo-guardrails) must not abort the whole recreate of pulled-image services.

## Why
Root cause: pinning `@sha256:` in compose and restarting via `unless-stopped` are two different operations — only `--force-recreate` actually pulls and swaps the digest. The meta-incident: the first validator implementation compared `{{.Image}}` (image config ID) against the pin's manifest digest — two different hash schemes of the same image — so every running container was falsely flagged as stale until caught. This is the exact class of error `rules/decision-depth-gate.md` (written the same session) was designed to prevent ("before declaring two values inconsistent, verify they're not the same thing in different encodings"), and the author violated their own rule while building the fix.

## Consequences
Positive: drift is now detected automatically (CI weekly cron + SessionStart + on-demand audit) and fixed automatically downstream via cos-update; the settings/docker/Python-deps "track SHA + detect + auto-apply" shape is now used in three places; a regression test locks in the manifest-digest-vs-image-ID distinction. Negative: `--force-recreate` severs open connections (acceptable for dev, production users of cos-update should pause during update windows); `--no-build` means a broken local build is silently skipped rather than aborting, which could mask a service that never got its update.

## Status & current state
Accepted 2026-04-21, PARTIAL — explicitly scoped as governing freshness/recreation only for Docker containers that remain as optional, fallback, CI, or reference surfaces after ADR-018 and the local-daemon decisions in ADR-042, ADR-043 (deprecated 2026-05-05, see ADR-171), and ADR-045; does not make Docker mandatory again. All rollout items (validator, SessionStart hook, gotcha doc, validator bug fix, cos-update auto-recreate, invariant test) are marked complete in-ADR.
