## Decision
Build `lib/qwen_agent_loop.py`, a Qwen agent loop mirroring Claude Code's `Agent()` tool iteration using OpenAI-style function-calling (Qwen's native tool-call protocol). Shipped in four phases: Phase 1 MVP (`read_file`, `edit_file`, `run_bash` with blocklist, iteration/token caps), Phase 2 tool-set expansion (`web_fetch`, `grep_files`, `glob_files`, reuse of `SmartReader`/`smart_truncate`), Phase 3 context injection (`lib/qwen_context_injector.py` reusing the same governance templates as Claude sub-agents, `context_level` param defaulting to `"none"` for backward compatibility), Phase 4 parity test harness (`scripts/parity_harness.py` running tasks through both Qwen loop and Claude executor, comparing cost/latency/tool-calls).

## Why
Without tool-use parity, Qwen was "a chat endpoint, not an agent runtime" — it could not read, edit, run bash, or iterate. This blocked `scripts/orchestrator.py --providers qwen,claude` from being a viable end-to-end path for preserving Claude Max quota. The concrete motivating gap: sub-agents dispatched via the cascade needed real read→edit→test→verify loops, not single-shot completions. OpenAI function-calling was chosen over emulating Anthropic's format because Qwen's endpoint speaks it natively — no translation layer needed. Hard-coded safety caps (20 iterations, 100K tokens, bash substring blocklist) were chosen over a full sandbox because sandboxing is the caller's (orchestrator's) responsibility, and a richer policy could wait for Phase 4 data.

## Consequences
Sub-agents can now do real coding work on Qwen, preserving Claude Max quota for orchestration/critical reasoning. Cost transparency via `AgentLoopResult` token/USD counts feeds `rules/token-economy.md`. Risks accepted: tool-call schema drift if Qwen changes function-calling behavior (mitigated by Phase 4 parity tests); silent tool failures returned as strings could cause loops (capped by max_iterations/token_budget); the bash blocklist is a substring filter, not a parser (backtick/escaping bypasses possible, accepted trade-off); token-budget checks happen post-API-call so one over-budget round-trip is possible.

## Status & current state
Implemented — Phases 1-4 all delivered same session (2026-04-21), commits for each phase. 13 unit tests (Phase 1) growing to 36 total across the module, all mocked, all passing. Parity harness has 14 additional tests. Follow-up not yet done: wiring `run_agent` into `lib/dispatch.py`'s `--providers` flag, and documenting routing rules in `rules/llm-dispatch.md`.
