## Decision
Ship a three-tier progressive adaptive-dispatch system, independently togglable, with only L1 shipping now. L1 (Quota Pressure Advisory, advisory-only, always on): `hooks/agent-quota-advisor.sh` (PreToolUse:Agent) plus `lib/quota_pressure.py` compute a 0.0-1.0 pressure score (50% rate-limit signal from `llm-dispatch.jsonl` in a 30min window, 50% cost signal from `cost-events.jsonl` vs `daily_alert_usd`); bands are LOW (<0.5, silent), ADVISORY (0.5-0.8, recommends `--providers qwen,claude`), STRONG (>=0.8, mentions the L2 kill-switch). L2 (Auto-Redirect with Block, deferred, design-only): opt-in via `COS_AUTO_REDIRECT_AGENT=1`, would deny native Agent() calls and redirect to the cascade when pressure > 0.7 or a rate-limit error occurred in the last 5 minutes. L3 (Transparent Bridge, deferred, design-only, blocked on ADR-050): per-skill opt-in that rewrites the Agent tool call into an orchestrator.py Bash invocation, explicitly trading away native governance hooks (blast-radius, reinvention-check, completion-gate, trust-score-validator) for quota preservation.

## Why
Claude Code exposes no hook that rewrites a native Agent() tool call before it hits the Anthropic API, so the cascade cannot intercept it directly. The only available levers are observing quota pressure from existing JSONL logs and advising the orchestrator via `additionalContext` (the same mechanism `hooks/blast-radius.sh` already uses). Without any intervention, the user discovers quota exhaustion post-hoc when Agent() is refused mid-task, causing user-perceived latency, lost context, and cascading failures in multi-agent sprints.

## Consequences
What improves: quota pressure becomes observable and advisory before hard failure. What breaks/risks: the rate-limit signal is inherently lagging (only observable after first failure, cannot predict exhaustion); a 30-minute window causes false positives under burst load (a single failing batch triggers advisories for 30 minutes after recovery — L2 will need a decay function or shorter window); cost attribution mixes real and estimated costs identically; cross-project contamination is unaddressed (two sessions on different projects share the same Claude Max quota but only see their own project's JSONL signals).

## Status & current state
L1 accepted and implemented (advisory-only, always on) — 13 unit tests in `tests/unit/test_agent_quota_advisor.py` plus a 4-check smoke script, with a registration sanity-check in `apply-efficiency-profile.sh`. L2 and L3 are deferred, design-only: L2 needs 2 weeks of L1 telemetry confirming the 0.7 threshold before it can ship; L3 needs ADR-050 (per-skill routing policy) shipped first, with rollout initially limited to 3 low-risk skills (`document-feature`, `skill-creator`, `sdd-archive`). Escalation between phases is manual and explicit — no auto-promotion.
