## Decision
Deprecate Langfuse (frozen trace sink, containers stopped but volumes preserved) and adopt Arize Phoenix (`pip install arize-phoenix`, no Docker/ClickHouse) as the optional self-hosted LLM observability tool. MLflow stays unchanged as the cost/outcome exporter; the self-improvement loop continues to read JSONL directly (`.cognitive-os/metrics/*.jsonl`) and is unaffected by either tool.

## Why
The trigger was a concrete Docker-weight audit on 2026-04-24: six `cognitive-os-langfuse-*` containers (ClickHouse, worker, app, pg, seaweedfs, valkey) had run for 3 days steady-state, burning ~1.34 GiB RAM and ~1380% aggregate CPU just to stay idle — flagged as the #1 weight complaint in 2026-Q2 onboarding feedback. Compounding this, `cognitive-os.yaml` said `langfuse.mode: disabled` but the compose file had no profile gate, so the stack started anyway — violating the Service Catalog's operating rule that "disabled" must equal "not running." An audit of actual consumers found Langfuse was only an optional, silently-no-op trace sink in `lib/record_completion.py` and was not depended on by `skills/analyze-improvements/` or any hook/rule/skill as mandatory — so its footprint was wildly disproportionate to its role. Phoenix was chosen after a 9-way comparison (Logfire, Laminar, OpenLLMetry, Weave, Helicone, Opik, OpenLIT, incumbent Langfuse) for being pip-installable (no Docker), LLM-native (OTel GenAI spans), local-first, and actively maintained weekly by Arize's core team.

## Consequences
Positive: frees ~1.34 GiB RAM, removes ClickHouse from the default stack, restores catalog "disabled means not running" doctrine, and OTel-based spans give future backend portability. Negative: loss of Langfuse's prompt-management/eval-dataset UI (mitigated — Phoenix ships equivalent features, checked in Phase 1) and an operator learning tax for new Phoenix idioms (projects/spans/evals vs traces/generations/scores). Neutral: self-improvement loop and MLflow are untouched.

## Status & current state
Accepted, `implementation_status: partial`. Phase 0 (stop containers, catalog/config updates) is DONE. Phase 4 integration coverage (OTel sink end-to-end test against a live Phoenix collector, `tests/integration/test_record_completion_sends_trace_to_phoenix.py`) was DELIVERED 2026-04-24, including removal of the two Langfuse e2e tests. Remaining: Phase 1 (adopt Phoenix skill + smoke test), Phase 2 (migrate `_send_langfuse_trace` → `_send_phoenix_trace`), Phase 3 (remove Langfuse from Compose/scripts/hooks/tests), Phase 4 final cleanup (volume deletion, close ADR) — targeted through 2026-06-30. "Rollback remains cheap" while volumes are preserved.
