## Decision
Adopt a 3-phase validation plan with hard exit criteria, explicitly designed to demote unproven claims rather than quietly preserve them. Phase 1 (Aggressive Prune, ~2 weeks): target `dormant_aspirational_ratio < 0.25` (from 0.381) by issuing "remove or prove" 14-day-deadline tags on DORMANT-180-days-without-test items and forcing every ASPIRATIONAL item to either implement its missing dependency or be removed — no "leave as aspirational" allowed; unresolved items auto-archive to `docs/99-Archive/archive/`. Phase 2 (Install Timing Test, ~1 week): a new `scripts/install-timing-test.sh` measures elapsed time, manual steps, errors, and Docker requirement for a clean install; if `elapsed_s >= 300` OR `manual_steps > 3` OR any error, the "plug-and-play" claim is demoted in README to "scripted install" with honest numbers. Phase 3 (Core vs Extensions Split, ~3 weeks): split `hooks/` and `skills/` into `core/` (registered + tested, default install) and `extensions/` (opt-in via `/install-hook`/`/install-skill`), with explicit graduation/demotion criteria.

## Why
The operator posed three existential questions — "how much is hype?", "is it worth more than vanilla Claude Code/Codex?", "are the promises (plug-and-play install, auto-improve, great DX) fulfilled?" — and the third was found to be literally unmeasured: zero empirical install-timing test runs existed prior to this ADR.

## Consequences
Positive: moves the SO from "heavy blob" to "lean kernel + modular extensions"; reduces adoption friction (23 skills + 67 hooks visible by default instead of 137 + 155); replaces intuition with measurement for the plug-and-play claim; Phase 1's prune pressure becomes a documented recurring cycle preventing future bloat. Negative: ~20-30 hours of human+agent migration effort across 3 weeks to classify/move 114 skills + 88 hooks; risk of archiving legitimate rarely-used primitives (mitigated by 180-day window + test-coverage filter); on-demand extension install adds UX complexity since users must know which skill they need. Neutral: the 38% "hype" number is a snapshot that moves as the repo changes.
