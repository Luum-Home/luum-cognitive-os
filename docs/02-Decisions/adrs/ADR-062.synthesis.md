## Decision
Generalize `lib/qwen_agent_loop.py` (misnamed — it's a generic OpenAI-SDK-compatible loop, not Qwen-specific) into `lib/openai_compatible_agent_loop.py`, keeping `qwen_agent_loop.py` as a thin backward-compat shim. Add a `lib/providers/` directory with one wrapper per provider (qwen, openai, openrouter, gemini, deepseek, ollama), each exposing `is_configured()`, `get_client()`, `MODEL_MAP`, and `call()`. Extend `lib/dispatch.py` to accept a comma-separated provider cascade with per-provider advance rules (e.g., qwen/openrouter/gemini/deepseek advance on any failure; openai/claude advance only on rate-limit since paid-tier failures are often real; ollama advances on timeout). Default cascade per 2026-04-24 operator decision: qwen → openrouter → gemini → ollama (local) → claude (last resort, preserves Claude Max). OpenAI/DeepSeek are opt-in via env keys only, never default, per the ADR-060 local-first principle.

## Why
`lib/qwen_agent_loop.py` already works against any OpenAI-protocol-compatible endpoint (OpenAI, Gemini, OpenRouter, DeepSeek, Groq, Ollama, LMStudio, vLLM) but was hardcoded to a two-tier qwen/claude cascade, which left no fallback path during the 2026-04-23 quota-exhaustion incident.

## Consequences
Positive: independence from Claude Max quota during peak usage; a true local fallback (Ollama) when all cloud tiers fail; automatic routing toward the cheapest capable provider; groundwork for ADR-052's cross-provider benchmarking harness. Negative: config surface grows (`cognitive-os.yaml` `llm_providers` block); each new provider adds an env var and quality variance; OpenAI-compat is not 100% consistent across providers (function-calling format and response shape differ), so edge cases are expected. Neutral: Claude stays in the cascade at the last tier — unchanged behavior once all other tiers are exhausted.

## Status & current state
Proposed — 2026-04-24, not yet implemented (`implementation_status: planned`). Four-phase rollout planned: Phase 1 refactor loop + 3 providers (qwen/openrouter/gemini, ~1.5h sonnet); Phase 2 Ollama + dispatch cascade (~1h); Phase 3 opt-in providers OpenAI/DeepSeek (~1h); Phase 4 verification/smoke (~1h). Estimated total ~4.5h sonnet / ~$4 agent cost. Open questions remain unresolved: OpenRouter auto-routing vs explicit model selection, Ollama default model size (llama3.3:70b needs 40GB+ RAM vs qwen3:32b ~20GB), per-provider rate-limit error detection, and tool-call payload tolerance across providers.
