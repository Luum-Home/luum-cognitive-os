## Decision
Define four harness integration surfaces the OS must abstract, with Claude Code staying the on-by-default reference harness and other harnesses opt-in via adapter packs: (1) event capture via `lib/harness_adapter/` (ADR-033, extend not rebuild) with new adapters for Codex, Cursor, bare-cli, and CI; (2) hook registration via a canonical `cognitive-os.yaml > harness.hooks` block projected per-harness by settings drivers (e.g. `settings-driver-codex.sh`); (3) skill invocation via a `cos-skill run/list/describe` CLI entrypoint so skills aren't gated behind Claude Code's slash-command UI; (4) sub-agent spawning via `cos-agent spawn` calling the ADR-062 provider-agnostic loop, explicitly not replicating MCP, TodoWrite semantics, or Claude Code's native `Agent()`.

## Why
Shell scripts already referenced `.claude/settings.json` in 15+ places and `record_completion.py` read `.claude/projects/` for session reconstruction — the OS was "portable in principle, Claude Code in practice." As of Codex v0.124.0, `PreToolUse`/`PostToolUse` fire only for the Bash tool (tracked upstream at openai/codex#16732), so the Codex adapter had to explicitly handle this tool-coverage gap rather than silently assume parity.

## Consequences
Positive: the OS runs anywhere rules/skills/hooks can exist as files on disk; unlocks CI-driven compliance/audit runs independent of any IDE; strengthens a "portable governance layer" differentiation story. Negative: four more drivers to maintain that can drift independently; `cos-runner` duplicates skill discovery and hook chaining that Claude Code gives for free, creating implementation-risk drift; settings-driver projection can desync (canonical says X, driver projects Y, hook fires Z), requiring a `cos doctor harness` verifier. Honest estimate: 10-15 sessions of work across phases, $15-30 in agent cost before human review — negative ROI if the operator only ever uses Claude Code.

## Status & current state
Accepted 2026-04-30 (flipped from the 2026-04-27 status review once the acceptance condition — "Phase 2 ships and at least one non-CC harness produces byte-identical canonical events for a reference skill" — was met). Surface 1 (event capture) is implemented: `lib/harness_adapter/codex.py` shipped (292 LOC, full `HarnessAdapter` ABC), the capability matrix documents Codex's honest limitations, and a parity test asserts byte-identical canonical events between `ClaudeCodeAdapter` and `CodexAdapter` for session_start/user_prompt_submit/session_end (4/4 passing, non-Bash tool events excluded with documented rationale). Surfaces 2-4 (settings-driver matrix, `cos-skill` CLI, `cos-agent` spawner, Cursor/bare-cli adapters) remain outstanding P0 implementation work tracked in `.cognitive-os/plans/architecture/adr-064-implementation-plan.md`. **Correction, measured 2026-08-20 (see the verification note of that date in the source ADR):** Surface 2 was never implemented for the Claude Code harness — `scripts/_lib/settings-driver-claude-code.sh` keeps its hook registry as 186 shell literals and has never read `harness.hooks`, while the bare, codex and opencode drivers do read it. The dead `CONFIG_FILE` assignment shipped in the implementing commit `387c9fc56` was taken for the implementation for 111 days. The decision itself is not withdrawn: three sibling drivers do exactly what Surface 2 describes.
