## Decision
Ratify a mandatory three-layer, defense-in-depth policy for SKILL.md frontmatter quality — all three layers required, none optional: (A) a canonical skill template plus skill-creator enforcement that fills required placeholders at creation time; (B) a PostToolUse hook on `Write|Edit` matching `skills/*/SKILL.md` that warns (advisory by default, exit 0; strict/blocking mode opt-in via `COS_STRICT_SKILL_VALIDATION=1`) immediately after the agent writes the file; (C) an audit test (`tests/audit/test_skill_descriptions_nonempty.py`-style) that is the hard CI gate catching anything that slipped past A and B, including writes that bypass the Edit/Write tool surface entirely (raw Bash redirection, git merges). The v1 contract requires non-empty `name`, `description` (not bare `>`/`|`, ≥30 chars), a valid `audience` enum, semver-ish `version`, `YYYY-MM-DD` `last-updated`, and a valid `<!-- SCOPE: ... -->` comment.

## Why
Each layer alone has a documented failure mode that the incident actually exhibited: a template alone only helps if agents use it (new authors deviate); a hook alone can be bypassed by writes outside the Edit/Write tool surface, so drift returns silently; an audit alone catches errors only at CI time, after the agent already claimed the work "done" and the operator discovered it hours later in the catalog — which is exactly what happened with the `radar-update` skill shipping without a description mid-session, with no automated check firing at any point.

## Consequences
Positive: drift like the 18-skill incident becomes structurally impossible since three independent gates must all fail; agents get in-session feedback before claiming "done" rather than after; the audit test is a permanent ratchet against regression; the 3-layer pattern is explicitly designed to generalize to `rules/*.md`, `hooks/*.sh`, and ADRs in Phase 2. Negative: Layer B adds hook latency (budgeted <100ms) against an existing 18s Stop-hook baseline; the hook can be bypassed by writes outside Edit/Write (acknowledged, hence Layer C exists); strict mode could regress sessions if enabled prematurely, so it defaults to advisory/WARN.

## Status & current state
Proposed, design-only — the ADR itself states "no source code, hook, or test is created here... implementation is Phase 1." `implementation_status: planned`. Sequencing note in the ADR: the parser fix and the 7 description backfills were expected to land first (via a separate in-flight agent), then Layer C (audit), then Layer A (template), then Layer B (hook). Phase 2 (extending the pattern to rules/, hooks/, and ADRs) records operator-ratified decisions on WARN-by-default and grandfathering cutoffs, with further research triage captured in `docs/06-Daily/reports/adr-067-phase-2-2026-04-24.md`.
