## Decision
Ship a self-contained heuristic (`scripts/detect_runner_capacity.py`) evaluated top-to-bottom, first-match-wins: cores ≤2 -> serial (`0`); load >70% -> `2` workers; available memory <2GB -> cap at `4`; battery present, <30%, and not plugged in -> serial; `CI=true` -> `auto`; otherwise (healthy machine) -> `auto`. Precedence for overrides, highest first: explicit `-n` flag on the pytest command line, then `COS_PYTEST_WORKERS` env var, then a stateful-lane safety guard, then the heuristic table, then default `auto`. `psutil` is the cross-platform abstraction (cores/memory/load/battery/CI), with graceful "best-effort" fallback (assume 8GB, 0% load, no battery) if `psutil` is missing — this is a performance helper, not a correctness gate, and must never block tests.

## Why
Each threshold is defended with a concrete rationale rather than picked arbitrarily: cores≤2 because xdist's per-worker fixed overhead (~1-2s plus IPC) exceeds the savings on a suite of a few hundred unit tests; load>70% because OS schedulers start thrashing well before 100%, leaving headroom for whatever else is running; mem<2GB because each xdist worker realistically costs 50-100MB and capping at 4 keeps total worker memory under 400MB; battery<30% because that's the OS-level "user-visible warning" threshold and shouldn't be compounded with thermal throttling from a parallel run. A later Phase 2 amendment found the initial "every no-`-n` invocation is adaptive" policy too broad for full-suite runs: `tests/ -n auto` combined shared repo state, external process pressure, xdist worker death, and session timeouts into one noisy, untrustworthy repair-queue signal, so stateful/broad lanes (`tests/`, `tests/behavior`, `tests/integration`, `tests/e2e`, `tests/contracts`, `tests/audit`, `tests/hooks`, `tests/chaos`) were changed to default to serial unless the caller explicitly opts into workers.

## Consequences
Positive: the 21-minute incident becomes preventable for anyone invoking the wrapper without remembering a flag; battery-aware courtesy prevents laptops from being hammered on low charge; logged diagnostics (`.cognitive-os/metrics/test-runs/<timestamp>/capacity.json`) enable evidence-based threshold retuning instead of guesswork. Negative: adds `psutil` as a dependency (degrades gracefully without it); detection adds ~50ms per pytest invocation, judged worth it against a 12-minute mistake; one more script to maintain, scoped tightly to pytest only (not a generic resource-manager abstraction, per explicit non-goal). Neutral: doesn't change which tests run, only worker count — test outcomes remain deterministic regardless of detected capacity.

## Status & current state
Accepted, Phase 2 implemented 2026-04-30 (original proposal 2026-04-24). Phase 1 (`detect_runner_capacity.py` + wrapper edits + 5 heuristic unit tests) and Phase 2 (capacity logging with an 11-key schema, 3 unit tests) are both marked Done in the ADR's own phase table. Phase 3 (Windows CI runner exercising the no-`os.getloadavg` fallback path) is Queued, and Phase 4 (generalizing detection into `lib/runner_capacity.py` for reuse by other tools) is Queued pending a second real consumer — explicitly out of scope until one exists.
