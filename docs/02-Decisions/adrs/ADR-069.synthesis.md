## Decision
Route any task by four risk dimensions (acceptance-criteria clarity, blast radius, reversibility, decision count). If any dimension is "High," the task goes through a 3-phase research-first protocol instead of standard fire-and-forget: Phase 0 read-only research agent produces a report (Inventory, Decision points, Risk assessment, Open questions, Recommended path, Acceptance criteria draft) written only to `docs/06-Daily/reports/`; Phase 1 is an operator decision with no SLA, persisted to Engram (`decision/<topic>`) or a follow-up ADR; Phase 2 is a standard implementation agent with the operator's decisions baked into narrow, verifiable acceptance criteria.

## Why
Background agents work great for mechanical, low-judgment tasks (`gofmt`, `grep -c` checks, single-transitive-dep bumps) but fail for tasks with subjective acceptance criteria, wide blast radius, hard reversibility, or 3+ judgment calls. The concrete motivating incident: a 300-line `scripts/cos-init.sh` rewrite to Python is the FIRST experience every new project has with the OS — a silently broken rewrite that "passes the smoke test" but mangles the generated `cognitive-os.yaml` would ship an unusable OS to every new consumer, and reverting costs a release cycle (versus `git revert <sha>` for a botched gofmt). Two other items (extending ADR-067's template+hook+audit pattern to more directories, and major Python dependency bumps) hit the same pattern: judgment calls mid-flight that a fire-and-forget agent cannot make alone.

## Consequences
Positive: high-risk tasks get human judgment at the critical decision point rather than after the fact; research reports become durable rationale artifacts; routing is explicit and auditable. Negative: 2-3x wall-clock for high-risk tasks versus a single research+impl pass; reports are an extra artifact that can go stale (mitigated by cross-linking from the spawning ADR); solo operators may feel friction writing a report to themselves. Neutral: low-risk task throughput is unchanged; no changes to existing SDD or background-agent infrastructure (this ADR is meta-process only, until Phase 5).

## Status & current state
Proposed, not accepted — `implementation_status: planned`. Codification phase (Phase 1) is done by virtue of this ADR existing; Phase 2 (pilot with the three carved-out items) and Phase 3 (operator triage) were intended for the same session. Phase 5 (a `templates/agent-research-only.md` base prompt) is an explicitly open, not-yet-built item. The verification checklist itself shows only 1 of 5 acceptance criteria checked off in the ADR body.
