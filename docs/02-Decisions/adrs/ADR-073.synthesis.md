## Decision
Adopt a role registry where every test-related primitive gets exactly one primary role: Selection (`.cognitive-os/test-lanes.yaml`, `tests/conftest.py`, `cmd/cos-test` selectors), Execution (`cmd/cos-test` + explicit legacy runners), Reporting (`scripts/pytest-with-summary.sh`, inventory scripts, report stores), Governance (hooks/skills/scripts enforcing DoD/coverage/ratchets), and Lifecycle (baselines, historical reports, ratchet state). The inventory ledger lives at `.cognitive-os/migrations/test-architecture-inventory.md`. A canonical map designates `cos-test focused/cluster/broad` as the single default UX, with legacy shell runners marked as deprecated compatibility shims via a 3-stage deprecation policy (mark → redirect/proxy → remove after one release cycle with no external consumers).

## Why
ADR-072 made `cos-test focused/cluster/broad` the canonical execution ladder, but selection, execution, reporting, governance, and lifecycle concerns remained mixed across bash scripts, Go commands, hooks, skills, reports, and metrics with no primitive-level contract preventing governance code from silently reinventing test selection/execution policy.

## Consequences
Positive: new contributors get a single test ladder instead of five ambiguous "run everything" scripts; governance primitives are prevented from becoming hidden test runners; reporting artifacts stay consistent across focused/cluster/broad runs. Negative: existing scripts must remain for one more release cycle before removal; the role registry itself adds an audit burden — new test primitives must declare role and canonical owner.

## Status & current state
Accepted — 2026-04-30, partial. A gap audit table tracks P0-P2 follow-ups, several already resolved after acceptance: worker/resource policy is now canonical (`--workers`/`--lane` scalars, `COS_FORCE_SERIAL_LANES`); `cmd/cos-test` deprecated `run`/`dashboard` as compat shims over broad/cluster; core governance gates (`auto-verify`, `dod-gate`, `pre-commit-gate`) now consume persisted artifacts via `scripts/cos_test_artifact_status.py`. Remaining: continue reducing selector duplication by exposing a focused-plan API so future gates prefer persisted reports over direct scanner/executor fallback; legacy shell runners (`test-all.sh`, `test-cognitive-os*.sh`, `cos-smoke.sh`) are still independently executable and risk an empty-shell-pyramid false pass. Resource governance itself (CPU/Docker/model-cost budgets) is explicitly out of scope for this ADR, tracked separately in `.cognitive-os/plans/architecture/test-resource-governance-sprint.md`.
