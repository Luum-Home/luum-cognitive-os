## Decision

Consolidate all project-level ADRs into a single canonical root, `docs/02-Decisions/adrs/`, using `ADR-NNN-kebab-slug.md` naming (Option A, rejecting Option B's "keep the split, expand tooling" alternative). Concretely:

- Migrate all 26 files from `docs/04-Concepts/architecture/adrs/` into `docs/02-Decisions/adrs/`, renaming to the uppercase `ADR-` prefix.
- Migrate the 3 orphaned files from `docs/04-Concepts/architecture/harness-adoption-gap/` (no README, no isolation policy) into the canonical root at new slots.
- Resolve the ADR-027 collision: `docs/02-Decisions/adrs/ADR-027.md` (SO Slimming, chronological priority, already has ADR-027a referencing it) keeps number 027; the migrating `027-headless-clustered-runtime-direction.md` is renumbered (planned ADR-088, actually landed as ADR-091 due to slot conflicts with Session B's concurrent work).
- Keep `docs/04-Concepts/architecture/cos-dispatch/adrs/` as an exempted local subsystem namespace, but rename its files in place to add a `CD-` prefix (`CD-001` … `CD-011`) so a recursive search can't confuse them with project-level ADRs.
- Leave one-line `# Moved` redirect stubs at old paths for one release cycle; remove `docs/04-Concepts/architecture/adrs/` once empty.
- Add enforcement: `tests/audit/test_adr_locations.py` fails on any `ADR-[0-9]*.md` outside the canonical root (except the CD- exemption and stubs).

## Why

As of 2026-04-30, 97 ADR files existed across four directories with no governing rule for where a new ADR must land, and the startup hook (`hooks/session-startup-protocol.sh`) hard-coded a scan of only `docs/02-Decisions/adrs/` — 36 files were invisible to tooling. This mirrors ADR-082's plan-fragmentation problem but at higher severity: plans in the wrong directory just hurt discoverability, but ADRs in the wrong directory produce **number collisions between Accepted decisions**. The concrete triggering incidents:

1. **The ADR-027 collision** — two different Accepted decisions both claimed ADR-027 ("SO Slimming" in the canonical dir vs. "Headless and Clustered Runtime Direction" in the legacy dir), so any tool resolving `ADR-027` would silently pick one or error.
2. **The ghost-ADR incident** — the orchestrator saw no ADR-002 in the indexed directory and began drafting a new one, unaware three different ADR-002 files already existed across three namespaces.
3. **Bare citations in production files** — `ADR-002` cited 8 times in `install.sh` and 2 times in `cognitive-os.yaml`, plus bare `ADR-012` and `ADR-021` citations elsewhere, all resolving only by reader inference.

Option A (full consolidation) was chosen over Option B (expand tooling to scan both dirs) because Option B does not eliminate the ADR-027 collision — it only makes it visible and requires a second rule to arbitrate. ADR-082 already proved 26-file migrations are scriptable and low-risk as a single changeset.

## Consequences

**Positive**: single glob indexes all project ADRs; the ADR-027-style collision class is eliminated and any future collision is caught by the audit test; bare `ADR-NNN` citations become safe post-rewrite; cos-dispatch isolation becomes machine-readable via `CD-`; the 3 harness-adoption-gap decisions become discoverable.

**Negative/trade-offs**: one-time cost of moving/renaming 29 files (26 + 3) plus 11 in-place cos-dispatch renames, each requiring cross-reference updates; redirect stubs must be tracked and removed after one release cycle or they become their own fragmentation; the ADR-002 citation rewrite in `install.sh` was flagged as highest-risk because an incorrect mapping (of 3 candidate files) would silently misattribute installation rationale — required per-line verification, not bulk substitution; `docs/04-Concepts/architecture/adrs/` becomes a deprecated empty directory that must be removed as part of the changeset.

## Status & current state

**Accepted**, executed 2026-04-30 by Session A (implementation_status: partial — one follow-up item remains, per front matter `partial_remaining`: "Migration is a single follow-up task").

What actually happened, per the ADR's own "Migration log" section:
- All 26 legacy-dir files and the 2 `ADR-001`/`ADR-002` files were moved into `docs/02-Decisions/adrs/` with no number change.
- The 027-collision file landed as **ADR-091** (not the originally planned ADR-088) because Session B had concurrently claimed slots 088–090 for unrelated work.
- The 3 harness-adoption-gap files landed as **ADR-092, ADR-093, ADR-094** (not the originally planned ADR-089–091), for the same reason.
- `install.sh`, `cognitive-os.yaml`, and `tests/unit/test_efficiency_optimization.py` bare `ADR-002` citations were rewritten to `ADR-093`.
- Bare `ADR-012` and `ADR-021` citations were updated to include full paths.
- 11 cos-dispatch files renamed in place to `CD-NNN-*.md`.
- `tests/audit/test_adr_locations.py` created (4 tests, passing).
- `hooks/session-startup-protocol.sh` verified to need no change (already scanned only the canonical directory).
