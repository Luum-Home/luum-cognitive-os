## Decision
Collapse the three-tier installer (`--lean`/`--standard`/`--full`, plus an internal `--minimal` alias and an auto-detection heuristic `has_git && src_count >= 5`) to two tiers: `default` (no flag) installs 10 curated "vanilla value" skills (`compose-prompt`, `exhaustive-prompt`, `agent-dashboard`, `auto-refine`, `verification-before-completion`, `cos-status`, and others) identified by the ADR-001 ghost-skill analysis, plus 14 core rules and the previous `standard` tier's ~29 hooks (rate-limiter, agent-prelaunch, auto-verify, dod-gate, completion-gate, mlflow-sync, etc.) at ~8000 tokens/session overhead. `--full` installs everything (~142000 tokens/session), intended for mature projects and COS contributors. Auto-detection is removed entirely — the default install is always the same.

## Why
Two concrete problems: (1) zero-skill default UX — the "lean" auto-detected default installed no skills at all, the opposite of how vanilla `git`/`gh`/`claude` behave with sensible zero-flag defaults; (2) cognitive load for no payoff — the three-way choice required users to model tier semantics before their first session, and the middle "standard" tier had no independent value (either "good enough," making `lean` pointless, or "not good enough," making `full` the only real answer), while the auto-detection heuristic just shifted the naming-recall burden rather than removing it.

## Consequences
User-facing: `install.sh` with no flags now produces a working OS with 10 skills visible immediately; help text shrinks to document only `--full`/`--from`/`--force`. This is an explicit BREAKING CHANGE — `install.sh --lean`/`--standard` and `COS_PROFILE=lean`/`standard` are rejected with a migration message (the new `default` is a superset of old `lean`). Installer-side: `apply-efficiency-profile.sh`, `cos-init.sh`, and `generate-project-settings.sh` all alias legacy names (`lean`/`standard`/`minimal`) to `default` (mostly silently, with a stderr note in one case) so existing deployments keep working without rewriting `cognitive-os.yaml` immediately; `auto-update-projects.sh` auto-migrates the registry's recorded mode on the next scheduled cascade with no manual intervention required. Ecosystem: at ADR time, the `cos-status` skill directory didn't yet exist (only `scripts/cos-status.sh`), so a fresh default install silently installed 9 of the 10 named skills until the skill wrapper was authored.

## Status & current state
Accepted (2026-04-16), PARTIAL per frontmatter — the explicit remaining item is "any follow-up install step" (documentation references to `--lean`/`--standard` in tests, wizard flows, and tutorials still needed a follow-up update pass, though this ADR does not block on that work since legacy flags remain aliased).
