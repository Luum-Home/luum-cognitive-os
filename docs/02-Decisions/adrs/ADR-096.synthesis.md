## Decision
Add a Hermes-inspired review-agent pattern: after a sub-agent completes, a second agent (reviewer) is triggered post-hoc/async on a 20% sample rate by default, using a cross-review model matrix that forbids self-review (haiku→sonnet, sonnet→opus, opus→sonnet lateral). Reviews check trust-report honesty, claim accuracy (files/tests claimed vs real), AC coverage, and hallucination indicators — not style/formatting. Findings persist to both `.cognitive-os/metrics/review-findings.jsonl` and Engram (type `review-finding`, deduped by content-hash topic key). A daily budget (50 reviews/day, tracked in `review-budget.json`) hard-skips reviews when exhausted rather than queuing them. No automatic skill modification is performed in this phase — findings surface for a human/downstream consumer (`/analyze-improvements`) to act on.

## Why
Hermes's `_spawn_background_review` proved the pattern works: a forked agent with shared memory/conversation context runs silently, reviews for skill opportunities and hallucinations, and writes findings directly to shared stores. COS's existing passive classifiers (`feedback_detector.py`, `feedback_consumer.py`, `hooks/skill-feedback-tracker.sh`) could not answer "did this sub-agent's output actually hallucinate or under-deliver" because they only look at user-authored prompts, not the agent's own claims — meaning silent agent errors (ones no user ever flags) were structurally invisible to the learning loop. Cross-review (not self-review) was chosen specifically to avoid the echo-chamber risk of a model grading its own blind spots.

## Consequences
Positive: closes the previously-invisible agent-error detection gap; produces queryable Engram evidence ("what did the reviewer find about yesterday's deploy agent?"); becomes the natural detector feeding ADR-095's skill-synthesis path; cross-review matrix structurally prevents echo chambers. Negative: async review means findings can land after the parent hook has already exited (mitigated by pending markers + sweeper, but drift is real); a reviewer that habitually rubber-stamps "verified" creates false assurance — the prompt forbids this (must find ≥1 gap) but LLM compliance is stochastic, so review-quality meta-evaluation is a genuine open follow-up; cost is bounded (~$0.02-$0.05/day at 20% sample + haiku pricing).

## Status & current state
Accepted, `implementation_status: partial` — explicit remaining scope noted in frontmatter: "the parent task is never blocked waiting for review" area still has open follow-up work. Sync v1 was superseded by an async v2 (pending markers + `scripts/review_pending_sweeper.py` background sweep); the legacy synchronous path remains available via `review.async: false` / `COS_REVIEW_ASYNC=0` for diagnostics. Meta-evaluation phase 1 shipped (deterministic `review_quality` score/verdict per finding), but correlating review findings with later user corrections and acted-on improvements remains future work, as does scheduling periodic sweeps for crash-orphaned pending markers.
