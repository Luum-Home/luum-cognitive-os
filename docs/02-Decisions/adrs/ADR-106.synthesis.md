## Decision
Four independently-deployable primitives. (1) Stash Leak Alarm: at SessionStart and before every agent dispatch, scan for `auto-pre-agent-*` stashes; WARN via `.cognitive-os/runtime/stash-leak-alarm.json` past `COS_STASH_LEAK_TTL` (default 600s), and block dispatch past `COS_STASH_LEAK_BLOCK_TTL` (default 3600s) until the operator resolves via `git stash pop/drop`. (2) Plan File Advisory Lock: before writing a `[ ]→[x]` transition to any `.cognitive-os/plans/` file, the writer must `mkdir` an advisory lock dir containing session_id/agent_id/pid/acquired_at/purpose; a second session gets the holder's metadata and must not proceed; TTL 1800s with stale-PID auto-clear; gates writes only, not reads. (3) Commit Provenance Enforcement: every commit to main (or any COS-tracked branch) must carry an `X-COS-Session: <id>` trailer (ADR-088 format) when `COGNITIVE_OS_SESSION_ID` is set; pre-commit hook rejects commits missing it; kill-switch `COS_SKIP_PROVENANCE_CHECK=1` logs every bypass to `provenance-bypass.jsonl`. (4) Orchestrator Bilateral Verification Gate: before any commit that flips a plan checkbox to `[x]`, the orchestrator must run the ADR-105 bilateral verification command for every high-stakes claim and document exit codes; on any failure it must not commit, must revert the checkbox to `[ ]`, and must surface the discrepancy — this is a behavioral rule for the orchestrator, not a hook, since hooks cannot run arbitrary verification on the orchestrator's behalf.

## Why
ADR-089 (multi-session git coordination) covers git-index-level coordination; ADR-098 (multi-agent file coordination) covers file-level edit locking within a session. Neither covered stash lifecycle alarms, plan-file advisory locking across sessions, commit provenance cross-referencing, or orchestrator-level bilateral verification — the four gaps this ADR closes, all surfaced by the single 2026-05-02 incident.

## Consequences
Positive: stash leaks surface immediately instead of silently persisting; concurrent plan-file writes produce an explicit error instead of silent last-write-wins; parallel session activity becomes visible in `git log` via X-COS-Session trailers; the bilateral gate provides a formal check before false-done reaches main. Negative: a crashed session holds the plan lock until TTL expiry (30 min max, mitigated by stale-PID detection matching the ADR-098 pattern); the provenance trailer adds 1 line to every commit message and requires operator manual commits to either set the env var or use the skip flag; the 1-hour stash block threshold may fire legitimately on long sessions with intentionally deferred stashes (operator can inspect and clear). All four primitives are additive — they layer on top of ADR-089/098 without changing existing hook/lock/commit logic.

## Status & current state
Accepted, `implementation_status: implemented` — status line notes primitives are "implemented or superseded by newer safety boundaries." One explicit correction: commit provenance trailers are no longer mandatory for public history; provenance is now handled by explicit opt-in controls rather than mandatory X-COS trailers. Primitive 4 (bilateral gate) has no automated test — its correctness depends on orchestrator behavioral compliance, verified manually. A "Cross-Session Reconciler" (periodic comparison of plan-file state across worktrees/sessions) is explicitly deferred pending session-to-session IPC that doesn't yet exist (tracked in FROZEN-BACKLOG.md).
