## Decision
Establish a named "Concurrent Agent Safety Layer" as an umbrella contract composing existing/adjacent primitives rather than replacing them: ADR-089 (git-index coordination), ADR-098 (file-edit locks), ADR-099 (pre-agent snapshot safety), ADR-105 (bilateral claim verification), ADR-106 (stash alarm, plan lock, provenance, bilateral gate), ADR-110 (preserve-branch governance), ADR-111 (core/consumer projection boundary). If ADR-108 and a lower-level ADR disagree, the lower-level ADR controls its own primitive mechanics; ADR-108 controls cross-primitive invariants and the scenario-test requirement. Required primitives: an append-only Agent Work Ledger (`.cognitive-os/runtime/agent-work-ledger.jsonl`), logical Resource Leases for domains spanning multiple files, adopted file/git/plan locks exposing holder metadata and stale detection, a Stash Leak Alarm (warn after short TTL, block strict dispatch after longer TTL), a Claim Verification Registry mapping high-stakes claim verbs to executable bilateral proof commands, Commit Provenance (`X-COS-Session` metadata), an Approval and Override Ledger, and a read-only Cross-Session Reconciler (future `cos doctor concurrency`, shell fallback `scripts/cos-doctor-concurrency.sh`).

## Why
Concurrency is valuable but creates specific observed risks: two agents silently overwriting the same file, two sessions creating false shared plan state, an auto-pre-agent stash hiding uncommitted work from a later session, untraceable commits, high-stakes claims accepted after only optimistic (not bilateral) verification, and agents mutating different files that represent the same logical primitive. Prompt-level scope guards had already been observed to fail in this repo ("the repo has already seen prompt-level scope guards fail"), which is why the decision explicitly rejects trusting agents to coordinate via prompts alone. The composed ADRs supply the concrete trigger for that judgment: on 2026-05-02, a parallel session's rebase orphaned two of another session's commits (`173bcae1`, `3f5932d6`), and a compounding false-done incident let a `git stash` operation silently withhold 59 modified files from working-tree visibility until an adversarial review was manually triggered (per ADR-116 and ADR-117).

## Consequences
Positive: concurrent agent workflows remain possible while state corruption becomes visible or blocked; false-done propagation is harder to commit silently; safety claims become testable via reproducible scenarios instead of asserted; future "doctor" tooling can report real concurrency posture instead of isolated per-hook status. Negative: more runtime state accumulates under `.cognitive-os/runtime/`; some workflows will block or park instead of racing ahead; tests require scratch repos, subprocess simulation, and careful isolation to write. Neutral: CRDT/OT was explicitly not required — locking plus worktrees is judged sufficient for the current 2-4 concurrent agent scale, revisitable only if same-file contention becomes frequent.

## Status & current state
Accepted; implemented through safety mesh tests, worktree isolation, branch ownership, release freeze, claim gates, and control-plane audits — this ADR decides the layer and invariants, and future additions extend it rather than reopening it as proposed. The first mandatory scenario slice (two agents editing the same file, false-done-in-plan, stash leak) is fixed and verified via `tests/integration/test_concurrent_agent_same_file.py`, `tests/behavior/test_plan_false_done_gate.py`, `tests/behavior/test_stash_leak_alarm.py`. A later slice (`cos-doctor-concurrency.sh --strict` plus its behavior test) is noted as still to be added — this is the concrete PARTIAL remainder.
