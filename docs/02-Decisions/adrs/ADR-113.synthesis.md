## Decision
Extend the validation capsule lock (`hooks/_lib/validation-lock.sh`, `scripts/cos-validation-capsule.sh`) with 5 liveness primitives: P1 heartbeat (writer updates `last_heartbeat_epoch` every 30s; stale after 3 missed beats, and after a 60s startup race window a lock cannot be "active" without a positive live owner PID and an existing `capsule_dir`), P2 activity log (`.cognitive-os/runtime/validation-activity.jsonl`, semantic staleness is secondary and only reaps locks whose PID is already dead), P3 diagnostic command `cos validation status` (HEALTHY/STALE verdict with wait estimate), P4 targeted recovery `cos validation break --capsule ID --reason TEXT` (SIGTERM→SIGKILL, removes lock+worktree, audited to `validation-breaks.jsonl`, replacing the global bypass), and P5 SessionStart auto-recovery hook (`hooks/validation-lock-cleanup.sh`) that sweeps stale `*.lock` files (only ones ≥60s old) and logs to `validation-auto-recovery.jsonl`.

## Why
Existing liveness logic only checked TTL expiry and `os.kill(pid, 0)` — correct for crashed processes but blind to hangs, deadlocks, busy loops, and OOM-killed-but-PID-reused processes. During the 2026-05-02 incident the operator had no way to distinguish a genuinely working validation from a hung-but-alive one, and the only available remedy (`COS_VALIDATION_ALLOW_CONCURRENT_AGENTS=1`) was a global bypass that reintroduced concurrent-mutation risk rather than a targeted fix.

A 2026-05-02 correction (from `make test-laptop`) further found that a quiet-but-live pytest process inside a capsule could be wrongly flagged semantically stale and have its worktree removed mid-run. The corrected rule: live PID + fresh heartbeat is authoritative liveness; activity staleness may only reap ownerless/dead locks, and cleanup must check the source repo's validation lock before `git worktree remove --force`.

## Consequences
Positive: hang detection (P1+P2) closes the previous blind spot; P5 self-heals stale locks from closed terminals without operator action; P4 replaces the global bypass with an audited, targeted operation; P3 turns lock-status archaeology into one command; existing TTL+PID logic is preserved (additive only). Negative/cost: +1 file write per 30s during validation (negligible); activity-log growth bounded by capsule lifecycle; ~5h implementation cost (inflated by invariant tests); audit-trail files need future rotation. Risks: heartbeat thread leaks if the cleanup trap misses the subprocess (mitigated by PGID-kill + eventual P5 reap), activity-log false negatives on long quiet validation steps (mitigated by tunable threshold + status command showing elapsed time), and a narrow P5-vs-concurrent-start race (mitigated by only deleting locks ≥60s old).

## Status & current state
Accepted, `implementation_status: implemented`. All 5 primitives (heartbeat writer, activity log, `cos validation status`, `cos validation break`, SessionStart cleanup hook) are specified with concrete file targets and an acceptance-criteria checklist; a 2026-05-02 correction was folded in after `make test-laptop` exposed the quiet-live-process false-positive.
