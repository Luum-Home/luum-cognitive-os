## Decision

Twelve coordination primitives organized into six layers (L1 Detection through L6 Shared evidence): task-claim ledger, work-identity fingerprinting, inter-session pub/sub bus, stale-task watermark, per-session branches by default, merge queue/landing pipeline, validation-capsule full mode default-on, orphan-commit notifier, `git reset --hard` protection layer, coordination-status CLI, pre-commit content-hash dedupe, push-time collision detection, stash provenance auto-reapply, atomic plan-checkbox transitions, and engram as cross-session claims/lock source-of-truth. Each primitive is independently deployable behind a feature flag, all defaulting to `false` except the read-only coordination-status CLI.

## Why

Concrete incident on 2026-05-02: commits `173bcae1`/`3f5932d6` existed as git objects but were unreachable from any branch after a parallel session's rebase; equivalent content was accidentally re-applied as `52380c52`/`781e2c79` — recovery happened by luck, not design. A sub-agent's fix to `orchestrator_verify.py` was wiped from the working tree by a parallel `git pull --rebase origin main` before landing, later recovered as `f4e4ddd1` only because the operator noticed the diff vanish. `.git/index.lock` blocked all commits for ~2 hours. None of the existing primitives (ADR-098 file edit-locks, ADR-099 untracked snapshots, ADR-105 bilateral claim verification, ADR-106 stash/plan locks, ADR-108/109/110/113 validation capsule) composed into a complete contract — there was no task-claim ledger, no duplicate-work fingerprinting, no inter-session signaling, no merge serialization, and no orphan-commit alarm.

## Consequences

Positive: closes the orphaned-commit class entirely (fingerprinting + patch-id dedupe + push-collision detection + orphan notifier), closes the duplicate-claim class (task-claim ledger + engram-as-SoT), addresses the wiped-fix class (destructive-git guard + stash auto-reapply), and provides a single diagnostic surface (coordination-status CLI) for any future incident of this kind.

Negative: ~12 new feature flags added to `cognitive-os.yaml`, growing configuration surface; engram becomes a hot-path dependency for two primitives (P5.1/P5.2) with graceful filesystem-JSON fallback on daemon outage; per-session branches (P2.1) change operator muscle memory. Engram write throughput for the combined P1.3+P5.1+P5.2 load (~50 writes/min at peak) is explicitly unmeasured and flagged as needing a benchmark before those flags go default-on.

## Status & current state

Accepted 2026-05-02, transactional rollout in progress (implementation_status: partial). A first "transactional gate rollout" slice already landed default-on structural pieces: `scripts/derived_artifact_gate.py` (registry drift gate), projection-parity blocking for supported harness events, `lib/task_claim_ledger.py` + `scripts/claim_task.py` (atomic local claim cache for P1.1), `lib/session_bus.py` + `scripts/session_event_bus.py` (P1.3 bus), and `scripts/merge-to-main.sh` (single-writer landing via `.cognitive-os/runtime/main-merge.lock`). This slice does not finish P1.2/P4.1/P4.2/P5.1/P5.2 — engram-as-claims-SoT remains a stepping stone, not yet flipped on. Frontmatter flags the plan-checkbox false-done class (P4.4) as remaining in scope, gated behind ADR-105 parser hardening.
