## Decision
Every `git stash` operation executed by an OS hook (in `hooks/`, `packages/*/hooks/`, or any hook-invoked script) MUST satisfy five invariants simultaneously: (1) Named — stash messages carry a UUID or `{session-id}:{hook-name}:{epoch}` identifier, plain `git stash`/`git stash push -m "WIP"` are forbidden; (2) Apply-by-name — never `git stash pop` (forbidden because it atomically drops the entry before signalling apply failure); always `git stash apply <ref>` then explicit `git stash drop <ref>` only after successful apply; (3) Auditable — every push/apply/drop appends a JSONL line to `.cognitive-os/metrics/stash-ops.jsonl` with ts/hook/name/action/status (log-write failure is non-fatal but must warn on stderr); (4) Budget — max 5 unrestored stashes per session before a new push is blocked with a warning; (5) Coordinated — stash-mutating hooks must acquire `.cognitive-os/runtime/stash.lock` via flock, with read-only hooks exempted only via an explicit `# STASH-LOCK-EXEMPT:` comment.

## Why
The stash leak was the worst class of silent-mutation bug: anonymous stash messages made forensic identification unreliable, `git stash pop` on partial-apply-failure silently lost work, no structured log existed to trace which hook pushed/applied/dropped what and when, and uncoordinated concurrent hooks/sessions could push/apply/drop without awareness of each other — producing 59 modified files silently withheld from working-tree state, invalidating agent observations and cascading into false-done reports across the session.

## Consequences
- Positive: structural prevention of the silent-revert pattern — a partial apply failure now always leaves a recoverable named stash entry; `stash-ops.jsonl` gives a queryable chronological audit trail replacing manual `git reflog` grepping; session-tagged names plus budget enforcement prevent cross-session stash leakage.
- Negative: flock-based lock acquisition adds roughly 5ms per stash operation (acceptable at per-agent-invocation cadence, potentially noticeable in a tight loop); new hook authors face a learning curve for the five-invariant contract, currently enforced only via code review rather than a single automated gate; sandboxed environments with read-only `.cognitive-os/metrics/` will produce an incomplete audit trail (non-fatal fallback).

## Status & current state
Proposed (2026-05-02), implementation_status: planned. R1 (`post-agent-snapshot-restore` hook) has landed. R2 (auto-checkpoint named-stash library `lib/stash_ops.py`), R3 (`flock`-based `lib/stash_lock.sh`), and R4 (session budget warning) are "in flight" per the ADR's own implementation-status table. Compliance is currently distributed across six test files (`test_auto_checkpoint_named_stash.py`, `test_stash_lock.py`, `test_stash_lock_hook_wiring.py`, `test_stash_reapply.py`, `test_stash_budget_warn.py`, `test_stash_leak_alarm.py`) rather than a single consolidated contract wrapper; code review must verify these stay green for any hook PR touching stash.
