## Decision
Introduce a governed lifecycle state machine for any primitive (hook, skill, rule, script, doctor) created/modified/promoted/demoted/archived/deleted by an agent or self-improvement workflow: `candidate → sandbox → advisory → blocking → default-on`, with parallel `demoted → archived → deleted` exit states. Each primitive must eventually carry canonical machine-checkable metadata (id, kind, owner_adr, lifecycle_state, maturity, distribution tier, governance_class, risk_class, supported_harnesses, exit_behavior, metrics_file, docs_claim_level capped at actual maturity, latency_budget_ms, rollback/repair command, sunset_criteria). Promotion requires proof at each gate (e.g., sandbox→advisory needs passing tests + docs; advisory→blocking needs false-positive border tests + repair-first messaging + documented bypass; blocking→default-on needs a positive-ROI dashboard + chaos/multi-session test coverage). Demotion/removal triggers on negative ROI, duplication, excessive noise/false-positives, staleness, or unsafe behavior (mutate/stash/delete without symmetric cleanup+tests) — removal is archive-first unless the file is generated/disposable, and high-stakes verbs (archived/deleted/wired/default-on) require ADR-105 claim verification. Self-adjusting workflows must classify changes, run minimal evidence commands, publish a session/event-bus notification, update derived artifacts or fail before commit, avoid touching active projection over unrelated WIP, and require human approval before default-on or destructive changes.

## Why
ADR-120 (harvester that proposes new primitives from repeated patterns), ADR-124 (distribution boundaries: core/team/maintainer/lab), and ADR-125 (governance value boundary requiring demotion of low-ROI primitives) are each necessary but not individually sufficient for self-adjusting behavior — without an explicit lifecycle governor tying them together, the system risks repeating ADR-017's failure mode of unchecked primitive sprawl. Runtime hardening (2026-05-03) then made the contract concrete: `manifests/primitive-lifecycle.yaml` was populated with lifecycle metadata for all 116 hooks actually projected by `.claude/settings.json`, with hard invariants — every projected hook needs a manifest entry pointing at a real file, `maturity: blocking` must correspond to an actual `exit_behavior: exit_2` with pytest evidence, and `docs_claim_level` cannot overstate runtime maturity (docs cannot sell an observe/advisory hook as blocking).

## Consequences
Positive: primitive creation becomes slower but safer; auto-generated primitives stay in candidate/sandbox until evidence exists; demotion/archival become normal hardening actions rather than admissions of failure; distribution/profile projection becomes deterministic since every primitive carries explicit metadata; the primitive harvester (ADR-120) stays useful without becoming an uncontrolled source of runtime drift. Negative/open: the repo still needs a manifest+tests enforcing metadata completeness, promotion gates, and bilateral archive/delete claims across the board (not yet universal).

## Status & current state
Status: Proposed, `implementation_status: planned`. Concrete progress since proposal: two semantic demotions have landed — `hooks/task-completed.sh` (2026-05-03, first demotion, signed as "semantic-portability," not ROI, because TaskCompleted is a COS-extension event that shouldn't be a default-projected portable baseline) and `hooks/context-watchdog.sh` (2026-05-03, second demotion, signed by `scripts/cos-manifest-tier-claim-audit` because the hook was an advisory-only wildcard adding default surface without blocking unsafe state). The lifecycle governor is explicitly NOT yet considered a proven repeated control loop: the ADR states it needs a second demotion (now satisfied, `demotion_count >= 2`) AND at least one ROI-signed demotion (`roi_signed_demotion_count == 0` — still unmet). `scripts/cos-demotion-loop-audit` currently WARNs on this gap; if it remains open 30 days after the second demotion, the check escalates from warn to fail (treated as governance rot if left permanently open).
