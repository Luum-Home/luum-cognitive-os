## Decision
Replace GitHub Actions with a three-layer local architecture. Layer 1 (pre-push hook): `git-hooks/pre-push` invokes `scripts/cos-ci-local.sh`, consolidating the seven ubuntu-only workflows (pytest, test-lane orchestration, test-quality audit, `gofmt -l` + `go vet`, config-drift audit, aspirational-classification audit, on-demand metrics) — aborts the push on any failure, with `--no-verify` as the explicit escape. Layer 2 (launchd schedules): the three weekly workflows become `launchd` plists generated by `scripts/install-launchd-jobs.sh` (Mondays 09:00/12:00/12:30 local time), rescheduling automatically if the Mac was asleep. Layer 3 (CLI on demand): `scripts/cos-pr-review.sh <PR>` replaces the three Claude API workflows — captures the diff via `gh pr diff`, runs local analysis, posts back via `gh pr comment`. Cross-platform matrix coverage becomes native macOS plus `docker run ubuntu:latest` for Linux.

## Why
The honest follow-up question to ADR-130's suspension was "can we replace all of this locally?" — the answer was yes for all eleven workflows across six categories, using infrastructure that already existed (no new services required). This ADR captures that target architecture so the design isn't re-litigated when the maintainer has cycles to implement it.

## Consequences
Positive: zero per-PR GitHub Actions cost; 10-30 second feedback vs 2-5 minute hosted-runner cold start; no "works on my machine, fails in CI" divergence since the local script *is* the CI; works fully offline (except push itself); the project's own hook-enforced governance philosophy now applies to its own CI. Negative/trade-offs: single-maintainer SPOF (if the Mac breaks, no CI runs — acceptable for solo dev, unacceptable for a team); no third-party verification of the local hook; Docker cross-platform coverage is ~95% fidelity (glibc/kernel differences unexercised); loss of GitHub PR status badges (replaced by `gh pr comment` audit trail); issue triage and `@claude` mentions become manual-only.

## Status & current state
Accepted and implemented in the same PR that landed this ADR — all listed implementation files (`scripts/cos-ci-local.sh`, `git-hooks/pre-push`, `scripts/install-git-hooks.sh`, three weekly wrapper scripts, `scripts/install-launchd-jobs.sh`, `scripts/cos-pr-review.sh`) are present in the working tree. The eleven `.disabled` GitHub Actions workflow files are intentionally retained as documentation/recovery artifacts, not deleted. When the local script and a `.disabled` workflow disagree, the local script is authoritative.
