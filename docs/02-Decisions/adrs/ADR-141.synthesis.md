The upstream Engram project shipped a native `engram cloud` feature in April 2026 (config/enroll/upgrade, `sync --cloud`, `cloud serve` self-hosted server), and the DX-first cloud flow bootstrap plan named cross-machine Engram daemon discovery as a required prerequisite for promoting any flow beyond `lab`.

## Decision
Wire the upstream `engram cloud` feature into COS without replacing any existing path — this is explicitly not an adoption decision for Engram itself (already integrated), only a transport wiring decision. Three sync modes coexist permanently, none deprecating another: `local-only` (default, no sync), `git-jsonl` (existing, unmodified, always-available fallback), `engram-cloud` (new, HTTP bearer-JWT to a self-hosted `:8080` server, worker↔central live replication). Local SQLite (`~/.engram/engram.db`) remains the single source of truth in all modes; cloud sync is append-only replication, never overwriting local state. Adds client-side tenant isolation enforcement in `lib/engram_http_client.py` (drops mismatched-project observations with a warning) and disables the upstream `--all` flag in COS usage (always passes explicit project scope). Workers use project-scoped bearer tokens (never the maintainer's personal token), provisioned via a new thin wrapper `scripts/cos-engram-cloud-enroll`. Extends the ADR-138 flow contract schema with `engram_project_scope` and `air_gapped_compatible` fields, and every cloud sync operation appends a row to the canonical `agent-audit-trail.jsonl` (bridging to ADR-142's compliance surface).

## Why
Bundle/import (ADR-136) is async, manual evidence exchange — insufficient for the near-real-time worker↔central replication the bootstrap plan's flow-promotion path requires. Rather than building new sync machinery, this ADR adopts the upstream Engram project's already-shipped cloud feature as a strict additive layer, preserving the git-jsonl air-gap fallback so no deployment is ever forced to depend on a cloud server.

## Consequences
Positive: workers get near-real-time observation sharing without polling git or manual bundle exchange; git-jsonl survives as an unconditional air-gap fallback; conflict surfacing (`mem_save` returning `judgment_required: true`) reuses the already-understood propose-only contract from ADR-134/135/138 rather than inventing a new mechanic; the audit bridge makes cloud memory state inspectable via plain JSONL grep, no dashboard required. Negative/risk: `engram cloud serve` becomes a new operational dependency whose availability COS does not manage; project-scoped token rotation is manual (mitigated by the enrollment wrapper, but rotation cadence is not enforced); the upstream `engram cloud` feature is April-2026 vintage and breaking upstream API changes would require updates to the wrapper and `lib/engram_http_client.py`.

## Status & current state
Accepted, implemented. Implementation evidence: `scripts/cos-engram-cloud-enroll` (project-scoped wrapper with dry-run/JSON modes and audit rows); `scripts/engram-sync.sh` (explicit `--cloud` mode, never calls `--cloud --all`); `packages/engram-sync/hooks/engram-auto-sync.sh` (conditional `--cloud` append when `ENGRAM_CLOUD_AUTOSYNC=1`); `docker/cos-worker/docker-compose.yml` (local `engram-cloud` profile with Postgres/pgvector); `scripts/cos-engram-cloud-docker-smoke` (repeatable local proof enrolling two projects and verifying project-scoped rows in `cloud_chunks`). Validated by `tests/audit/test_adr_139_141_142_cloud_surfaces.py`, `tests/unit/test_cos_engram_cloud_enroll_and_audit_archive.py`, and an optional testcontainers lane. Manual proof documented at `docs/09-Quality/manual-tests/engram-cloud-docker-sync.md`.
