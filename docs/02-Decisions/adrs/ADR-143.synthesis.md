## Decision
Add `scripts/cos-closure-discipline-audit` as a blocking maintainer primitive wired into `scripts/cos-ci-local.sh quick`. It is intentionally narrow, checking exactly the 5 drift classes that escaped targeted validation in the incident: (1) tests/scripts must not reference active `.github/workflows/*.yml` when only the ADR-130 `.yml.disabled` artifact exists, unless using an active-or-disabled compatibility helper; (2) runtime-hook-count tests must assert report-derived parity, not magic integers; (3) the validation capsule may use the ADR-129 safe-worktree helper in COS checkouts but must retain a non-`rm -rf` fallback for minimal repos; (4) `primitive_lifecycle.py --json` findings count as closure failures for maintainer quick CI; (5) quick local CI must actually run the closure-discipline audit itself (self-wiring), or the audit is decorative. This gate does not replace `make test-laptop` — for pre-commit WIP validation use `make test-laptop-direct`; the capsule used by `make test-laptop` validates committed HEAD in an isolated worktree, so it's the post-commit/release-safety proof path, not proof of uncommitted edits.

## Why
The SO already had partial closure mechanisms (DoD/dod-check, verification-before-completion skill, completion-gate.sh/dod-gate.sh, validation capsule, derived-artifact gate, local-CI migration, primitive lifecycle governor, work-inventory doctor) but each covered a different slice and none was wired as a named, self-checking closure-discipline gate — so the validation nervous system itself could silently drift from repository reality while feature-local tests still passed. This is not a failure of the new ADRs' direction; it is a failure to close the system that validates the direction.

## Consequences
Positive: fast agent batches can still move quickly, but stale validation infrastructure becomes visible before a completion claim forms; the SO now distinguishes feature validation from validator closure; ADR-130/131 workflow suspension is mechanically understood by tests instead of relying on maintainer memory; hook demotions/promotions no longer require updating a magic test integer; validation-capsule portability is tested against minimal repos, not just the COS checkout. Negative: quick CI gains another maintainer-only blocking check; the audit must stay narrow or it will duplicate `make test-laptop` and increase DX tax; some findings are conservative and a legitimate exception must be encoded in the audit with an ADR-backed reason, never bypassed by deleting tests.
