## Decision
A rule may only be listed in `EXCLUDED_RULES` with a `# → hook.sh` enforcement claim if: (1) the referenced hook file exists; (2) it is registered in `cognitive-os.yaml > harness.hooks`; (3) it is projected by the active profile into the relevant harness settings; (4) rules not hook-enforced must say `agent-instruction-only` instead of making a false `# → hook.sh` claim. Also adds a new PreToolUse Bash gate, `hooks/skill-router-bash-gate.sh`, blocking direct dependency/toolchain upgrade commands (`brew upgrade`, `pip install --upgrade`, `uv sync --upgrade`) unless routed through `/deps-update` or explicitly overridden with `COS_ALLOW_SKILL_BYPASS=1`.

## Why
The project has multiple projection layers (`cognitive-os.yaml > harness.hooks` canonical registry, `scripts/_lib/settings-driver-claude-code.sh`, `scripts/_lib/settings-driver-codex.sh`, `scripts/apply-efficiency-profile.sh`), so hand-editing generated settings would only fix the self-hosted checkout and leave consumer projects vulnerable to the same drift. The concrete incident was the discovery of a "dangerous fourth state": rules claiming hook enforcement with the hook present on disk but absent from `.claude/settings.json`, across at least seven named rules.

## Consequences
Startup stays lean (rules can still be excluded from context when hooks are real); missing hook projection now fails an audit test instead of relying on manual review; settings fixes land at the canonical projection layer so consumer projects self-heal via `scripts/apply-efficiency-profile.sh`; some additional maintainer hooks now run in the hot path (accepted since they're tied to rules already advertised as enforced); Codex receives only the supported Bash-hook subset until it supports non-Bash events.

## Status & current state
Accepted and implemented.
