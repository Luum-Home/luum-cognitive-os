## Decision
Add a primitive readiness ledger for scripts (`python3 scripts/primitive_readiness_ledger.py --project-dir .`), generating `docs/06-Daily/reports/primitive-readiness-ledger-scripts-latest.{json,md}`. Each script row declares `path`, `role` (`agentic-primitive | maintainer-tool | migration-only | driver-specific | lab | archive`), `role_source`, `confidence`, lifecycle fields, supported harnesses, consumer accessibility, consumers, evidence signals, and next action. Classification is advisory by default; optional `--fail-low-confidence` / `--fail-agentic-without-lifecycle` flags allow future ratcheting.

## Why
The repo already had lifecycle metadata, coverage reports, usage maps, docs execution audits, and gap snapshots, but none gave a single per-script row answering what role a script plays, which evidence caused that classification, and what promotion/demotion action comes next — forcing every session to rediscover `scripts/` from scratch.

## Consequences
- Future agents can review `scripts/` without re-reading every file.
- Product claims can be checked against role and lifecycle evidence.
- Creates a ratchet path: start advisory, fail only on touched rows or chosen role classes later.
- Classification is revisable, not a permanent decision.

## Status & current state
Accepted, implemented, and extended through several follow-on updates on 2026-05-04: (1) the first low-confidence pass was closed via `manifests/primitive-readiness-script-overrides.yaml` (ledger now reports zero low-confidence rows); (2) protected install/profile/projection surfaces got `priority: protected` lifecycle treatment via `manifests/primitive-readiness-protected-install-surfaces.yaml`; (3) candidate lifecycle rows were added to `manifests/primitive-lifecycle.yaml` with `lifecycle_state: candidate`, treated as inactive by `scripts/active_primitive_index.py` and `scripts/cos_adoption_profile.py`; (4) a `consumer_accessibility` field (`install-profile-managed`, `lifecycle-declared-consumer-candidate`, `lifecycle-declared-maintainer`, `skill-referenced-not-projectable`, `so-local-only`) separates local evidence from downstream project availability; (5) the ledger was generalized to hooks/skills/rules via `scripts/primitive_family_readiness_ledger.py`.
