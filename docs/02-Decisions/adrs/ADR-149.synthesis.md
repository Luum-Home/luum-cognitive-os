## Decision
Add `scripts/primitive_duplication_audit.py` as the first unified, dependency-free duplication audit across agentic-primitive and configuration surfaces, writing `docs/06-Daily/reports/primitive-duplication-latest.json` and `.md`. Findings are classified by kind: `exact-copy` and `near-copy` (normalized content identical or token-shingle similar → common home `templates/` or `lib/`), `yaml-structural-repeat` (shared config schema → `manifests/`), `bash-function-repeat` (identical normalized shell function bodies → `hooks/_lib/` or `scripts/_lib/`), `python-function-repeat` (identical AST bodies → `lib/`), `primitive-overlap` (highly similar rule/skill procedure text → `skills/` or `rules/`). Every finding includes a recommendation, proposed common home, and consumer relevance. Intentionally advisory in reconstruction — exposes extraction opportunities without auto-refactoring or blocking CI. The ACC pipeline runs it as an adapter during refresh so duplication debt sits alongside readiness/projection debt.

## Why
No single command could answer "where is behavior repeated, and where should it live if extracted" across all of Bash/Python/YAML/rules/skills/hooks/docs at once — each existing tool only saw one narrow slice of the problem.

## Consequences
Positive: maintainers get one report for repeated patterns across all surface types; findings are actionable (each names a proposed common home); consumer-project relevance is explicit so projected primitives aren't refactored from an SO-local-only viewpoint; ACC surfaces duplication debt without making it a hard gate too early. Negative: the first implementation is heuristic and can false-positive; near-copy detection can get expensive if thresholds/include-paths widen too far; some duplication is intentional for harness isolation and needs human triage before extraction.

## Status & current state
Accepted and implemented (2026-05-04). Verification: `tests/unit/test_primitive_duplication_audit.py`, a live `python3 scripts/primitive_duplication_audit.py --project-root . --json` run, and `python3 -m py_compile` on the audit script plus `scripts/acc_pipeline.py`. Rejected alternatives: using only `jscpd`/PMD CPD (don't understand COS common-homes or primitive boundaries), extending `docs_duplicate_audit.py` only (too narrow for non-doc surfaces), blocking CI on any duplicate immediately (rejected during reconstruction — first scan should build a baseline), auto-extracting repeated code (can change portability/harness behavior).
