## Decision
Promote six harnesses to implemented structural projection: `gemini-cli`, `warp`, `amp-code`, `jetbrains-junie`, `qoder`, `factory-droid`. Each gets specific generated project-local files only (no user-global config, no credentials): Gemini CLI → `GEMINI.md` + `.gemini/settings.json`; Warp → `AGENTS.md` + `.warp/README.md` (deliberately NOT `WARP.md`, despite its documented precedence, to avoid overriding the shared AGENTS.md path); Amp → `AGENTS.md` + `.amp/settings.json`; JetBrains Junie → `.junie/AGENTS.md` + `.junie/README.md`; Qoder CLI → `AGENTS.md` + `.mcp.json` + `.qoder/settings.json`; Factory Droid → `AGENTS.md` + `.factory/mcp.json` + `.factory/settings.json` + `.factory/skills/cognitive-os/SKILL.md`. All generated MCP settings are empty placeholders. Kiro stays `planned`/`none` in the landscape manifest with `lifecycle-investigation` status — it may become a native-lifecycle candidate only after an explicit event-mapping adapter and runtime smoke exist.

## Why
The vendor documentation provided enough concrete, verifiable, account-free project-local surfaces to justify promoting these six to "structural" proof level without needing runtime/account smoke tests, while Kiro's stronger hook system deliberately was not promoted because COS has no adapter mapping or runtime smoke for it yet — keeping native-lifecycle promotion evidence-gated rather than documentation-gated.

## Consequences
Positive: the ACC consumer-projection adapter now proves six additional structural harnesses through temp-project installs; AGENTS.md-native surfaces share one consistent bounded COS block instead of duplicating full docs; Factory Droid gets a project skill shim without prematurely wiring COS hooks into the Factory runtime; Kiro's hook surface is tracked separately so native-lifecycle promotion stays evidence-gated. Negative: no account-backed runtime smoke was performed for any of the six; structural files may need adjustment if vendors change project config paths; both Factory and Kiro expose hook systems but COS native-lifecycle parity remains unimplemented pending event-payload mapping and runtime smoke.

## Status & current state
Accepted and implemented (2026-05-05). Verification: `tests/behavior/test_consumer_project_projection.py`, `tests/contracts/test_acc_pipeline_contract.py`, `tests/contracts/test_harness_implementation_phases.py`, `tests/contracts/test_ai_agent_harness_landscape.py`, plus `python3 -m py_compile scripts/cos_init.py scripts/acc_pipeline.py` and a live `scripts/acc_pipeline.py --project-dir . --refresh --fail-new` run. Rejected alternatives: promoting Kiro directly to native-lifecycle (no adapter mapping or runtime smoke yet), generating user-global configs (violates project-local-only projection, risks touching credentials/personal IDE state), copying all COS skills into `.factory/skills/` (too much duplication vs. referencing the projected `.cognitive-os/skills/cos/` path), using `WARP.md` for Warp (its documented precedence over AGENTS.md would unnecessarily override the shared path).
