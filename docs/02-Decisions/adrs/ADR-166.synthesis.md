## Decision
Introduce an expected-skip registry (`manifests/test-skip-registry.yaml`) enforced from the pytest summary wrapper used by `cos-test`. Each expected-skip entry declares category, matching lanes, reason pattern, activation condition, and opt-in-lane or repair path. Five allowed categories: `external-dependency`, `opt-in-lane`, `runtime-sample-precondition`, `optional-runtime-state`, `policy-exemption`. `scripts/test_skip_registry.py` parses JUnit XML, classifies each skip against the registry, writes `skip-summary.json`/`.md`, and returns non-zero when an unclassified skip appears. `scripts/pytest-with-summary.sh` runs the registry after pytest, adds category counts to `summary.txt`, and fails the run if pytest passed but unclassified skips exist. Bare `skip` is now valid only for conditional applicability — reproducible known debt must become `xfail(strict=True)` or a real failing test; tests whose product claim no longer exists should be deleted or rewritten.

## Why
Legitimate environment gates (Docker, network, credentials, HOME mutation, runtime sample windows, opt-in proof drills) look identical to accidental or lazy skips in raw pytest output. Without classification, maintainers cannot tell whether validation quality is improving or silently decaying as new skip classes accumulate unnoticed inside an otherwise-green laptop lane.

## Consequences
Positive: `make test-laptop` keeps legitimate skips without hiding new skip classes; operators see skip counts by category in the normal run summary; Docker/provider/Engram/p95 checks remain explicit opt-in lanes; creates a migration path from bad skips to `xfail(strict=True)` or real failures. Negative: reason-pattern matching can become too permissive if entries are written broadly, requiring ongoing registry review; some existing skips will need later narrowing from coarse patterns; more test metadata exists overall, accepted as the cost of preventing silent validation-coverage decay.

## Status & current state
Implemented for the first enforcement slice (2026-05-05) — reason-pattern classification, not exact per-test node-ID matching (that is an explicit follow-up). Does not require eliminating every skip; it makes skips classified, summarized, and enforceable so new unclassified skips fail the wrapper. Follow-ups tracked but not required for this slice: periodic audit of over-broad rules, additional explicit opt-in proof lanes (Docker, provider smoke, Engram Cloud, p95 runtime, full integration), and migration of old skips to `xfail(strict=True)`.
