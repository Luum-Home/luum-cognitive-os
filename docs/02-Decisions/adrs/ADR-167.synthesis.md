## Decision
Add `scripts/proof-drill-select` as the selector/doctor primitive for the proof-drill registry, selecting by id, scope, class, projection profile, and text tokens (`provider`, `docker`, `headless`, `codex`). Add `scripts/proof-drill-evidence-record` so proof runs can update the machine-readable evidence report ACC consumes. Extend `manifests/proof-drill-registry.yaml` with `consumer_projection` classification and three projection profiles: `consumer-default`, `consumer-opt-in`, `maintainer-only`. Extend `cos-instance-init` so instance plans expose registered proof drills and default-safe doctor commands without executing opt-in drills. Teach `scripts/acc_pipeline.py` to load `docs/06-Daily/reports/proof-drill-evidence-latest.json` as aligned/stale/unverified ACC capabilities. Register `COS_CODEX_EXEC_MODEL` in `manifests/runtime-env-flags.yaml` as a documented test-opt-in/provider-smoke model pin. Consumer projection rule: consumer projects get `/run-tests` by default; proof drills only travel via explicit projection profile, and provider/Docker proof drills are `maintainer-only` unless a later ADR proves a safe project-local adapter.

## Why
Agents needed to ask a registry for the correct proof-drill command instead of reading long reports and guessing, and the newly-introduced `COS_CODEX_EXEC_MODEL` flag needed a governed home rather than becoming ad hoc shell-environment folklore.

## Consequences
Positive: agents can query the registry instead of reading long reports; COS instance plans know which proof drills are available per profile; ACC shows proof-drill evidence without manual classification; provider model pins are governed as runtime flags rather than ad hoc shell environment. Negative/trade-offs not separately enumerated beyond the consumer-projection constraint: provider and Docker proof drills stay `maintainer-only` by design, so consumer-project operators do not get those drills unless a future ADR promotes them.

## Status & current state
Implemented (2026-05-05) — "for the proof-drill selector, evidence recorder, ACC adapter, instance-profile projection, and runtime-flag registry scope." Live proof execution remains opt-in per the registry; this ADR closes the selector/evidence/control-plane integration boundary, not live execution guarantees. Verification: `tests/contracts/test_proof_drill_registry.py`, `tests/contracts/test_proof_drill_select.py`, `tests/contracts/test_cos_instance_profiles.py`, `tests/unit/test_acc_proof_drill_evidence.py`, `tests/contracts/test_runtime_env_flags.py`. Rejected alternatives: keeping proof selection in prose only (agents could pick provider/Docker drills by mistake), executing all profile smokes from `cos-instance-init` (would turn opt-in provider/Docker proof into default installer side effects), letting ACC infer proof from Markdown only (needs stable machine-readable rows), projecting all proof drills to consumer projects (provider/Docker drills are SO-maintainer surfaces unless proven safe and packaged).
