## Decision
Evolve `manifests/dependencies.yaml` into the single source of truth for cross-device dependency installation. Each entry must declare: name, category (runtime/package-manager/cli/ai-cli/desktop-app/container/security/mcp/service), profiles (core/standard/full/maintainer-only), criticality (required/recommended/optional), scope (project/user/system), syncable (yes/no/state-only/config-only), auth_bound boolean, check command, per-platform install commands (macos/linux/windows_wsl), manual_url for script-unsafe installs, and never_copy paths for credential material. New operator-facing installer: `scripts/cos-deps-install.sh --profile core|standard|full --platform auto [--dry-run|--apply]` — dry-run by default, auto-detects platform, installs only non-auth-bound dependencies with a platform command, reports manual/auth-bound dependencies with doc links, and never copies/reads/infers credentials from another device. New doc `docs/05-Methodology/setup/cross-device-dependencies.md` maps what travels via git/Docker/Engram/manifests vs what must be installed per-machine.

## Why
COS should not pick one package manager as the universal answer — external precedent (Homebrew Bundle's declarative Brewfile, Windows Package Manager's JSON export/import, Nix flakes' pinned reproducibility, asdf's `.tool-versions`) confirmed the right shape is a vendor-neutral dependency contract, not a single tool. The installation surface was genuinely mixed (Python via pyproject.toml+uv, Docker services, host CLIs via a mix of Homebrew/apt/curl/pip/npm/Go/vendor installers, auth state that must never cross machines, and an intentionally macOS-only Obsidian helper) — a unified manifest was needed to keep doctors and installers from disagreeing while keeping credential boundaries explicit.

## Consequences
Positive: dependency installation becomes auditable instead of scattered across prose and ad hoc scripts; new machines reproduce the portable part of setup from one command; doctors and installers share one manifest so they stop disagreeing; auth-bound tools stay visible without unsafe credential migration. Negative: the manifest schema grows and needs its own validation tests; existing one-off scripts must be migrated/wrapped rather than duplicated; "one command installs everything" remains an invalid claim by design since some dependencies stay manual; Windows/WSL support needs explicit proof rather than inference from Linux commands.

## Status & current state
Partial — implemented for the manifest-driven dry-run installer and credential-safe reporting scope (2026-05-05). Delivered: `manifests/dependencies.yaml` v2 fields (category/profiles/scope/syncable/auth_bound/platform commands/never_copy), `lib/manifest_loader.py` validation (still accepting legacy string entries during migration), `scripts/cos_deps_install.py` emitting JSON buckets (already_present/installable/manual/auth_bound/unsupported_platform/installed/failed), and `tests/contracts/test_cross_device_dependencies.py` enforcing the no-credential-copy invariant. Remaining follow-up (explicit, not hidden): doctor convergence (`scripts/manifest-check.sh`, `scripts/cos-doctor-tools.sh` consuming v2 fields) and `scripts/setup.sh` delegation to the new installer.
