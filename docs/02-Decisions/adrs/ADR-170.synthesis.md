## Decision
The primary UI surface for Cognitive OS is the operator CLI plus the markdown report library, period — no web dashboard until a real driver exists. `scripts/cos-boring-reliability` is the operator dashboard (structured JSON or human-readable text, no web rendering); `docs/06-Daily/reports/` is the durable artefact surface. Phoenix (already in the `observability` dependency lane) is accepted as a complementary, opt-in LLM-trace UI reachable via `uv run phoenix serve` — it renders traces/latency/cost/evals but explicitly does not model COS lifecycle, doctrine, demotion, or governance concepts, keeping trace and governance surfaces separate.

## Why
A prior custom dashboard had already been demoted (ADR-169); this ADR closes off building a replacement without a proven driver. The evidence was direct: a live-smoke check of the API surface showed almost every endpoint 404ing except health — a half-functional dashboard would not have served buyers or operators better than terminal output backed by durable markdown evidence.

## Consequences
- Positive: zero new web surface to maintain, consistent with the "subtraction + maturity-driven" doctrine; buyers are evaluated on operator usability rather than a half-functional dashboard; every audit/demotion/proposal flows through `docs/06-Daily/reports/` as durable, git-tracked evidence.
- Negative: no graphical demo for sales contexts depending on screen-share appeal (mitigated by strength of markdown artefacts); higher onboarding bar for users expecting a Notion/Linear/Jira-style UI (mitigated by the Docker runbook and CLI surface itself).

## Status & current state
Superseded by ADR-172 (published the same day, 2026-05-05) — but explicitly as an extension, not a reversal. The CLI-as-primary clause survives unchanged as Surface 1 of ADR-172's four-surface architecture (CLI, Phoenix, Engram Cloud, Obsidian/markdown reader). ADR-172 generalizes the framing (each artefact kind has its own ideal surface) and elevates Phoenix and Engram Cloud to first-class named surfaces, but does not change the "no web dashboard for governance/lifecycle/doctrine" boundary. Falsifiable claim carried forward: if 3+ independent external evaluators cite "no UI" as a blocker within 6 months, this is a Shape-B trigger requiring revisit (per ADR-132).
