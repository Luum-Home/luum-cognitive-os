## Decision
Adopt OpenSpace's 6-table SQLite schema verbatim into `lib/skill_store.py` (COS-namespace column adjustments only: `creator_id`→session IDs not user IDs, `analyzed_by`→model-name not user-id; standard-library only, no new pip deps), stored at `.cognitive-os/skill_store.db`. Separately adopt only the *signal-collection* half of OpenSpace's post-execution analysis trigger: new hook `hooks/skill-post-execution-analysis.sh` (PostToolUse Agent, async, <200ms budget) extracts skill_name/tool_count/duration_ms/status, writes to SkillStore, and — only when a "candidate for evolution" heuristic fires (3+ tool issues, or status=error AND duration>30s) — writes a **propose-only** Markdown artifact to `docs/06-Daily/reports/skill-analysis-proposals/<date>/<skill>.md`. The hook has zero write path to any live `SKILL.md` or `.claude/skills/` — the propose-only discipline is enforced structurally, by absence of a write path, not by a runtime check. Explicitly reject OpenSpace's auto-apply evolver/analyzer logic in its entirety.

## Why
ADR-133 (expansion-without-monsterization) and ADR-134 (headless self-improvement, propose-only doctrine: audit → propose → human review → apply) forbid any analysis trigger that automatically rewrites a SKILL.md. OpenSpace's schema was independently validated at production scale and directly solves COS's real gap (JOIN-able lineage/execution/judgment queries vs O(n) JSONL grep) — reinventing it would violate ADR-208's Imported Pattern Closure Contract against reinventing well-maintained patterns. ADR-171 had already codified the applicable discipline: adopt schema, not behavior. This ADR follows that exact playbook — port the DDL verbatim (lines 80-166 of the source file, blob SHA `b3e27516c9b5582d4b7377bab0e126ac405ae0a9`), reject the evolver/analyzer behavior wholesale.

## Consequences
Positive: SQLite JOIN queries replace O(n) JSONL grep for skill-quality analysis; content-addressable lineage via SHA-256 output hashing enables reproducibility checks; the propose-only gate is structurally enforced (no write path exists), stronger than a runtime check that could be bypassed. Negative: a new binary `.db` file must be gitignored; the migration script must handle malformed legacy JSONL gracefully; the hook adds ~20ms startup overhead per Agent-tool completion.

## Status & current state
Accepted and implemented. `lib/skill_store.py` creates the 6-table DB at init; `scripts/migrate_skill_archive_to_store.py` migrates the old JSONL idempotently (dry-run default, `--apply` to write); `hooks/skill-post-execution-analysis.sh` is registered across `templates/security-profiles/{minimal,standard,paranoid}.json` and `hooks/_lib/registration-allowlist.txt`. Killswitch `DISABLE_HOOK_SKILL_POST_EXECUTION_ANALYSIS=1`. Falsifiable claims backed by named tests: `test_skill_store.py::test_query_lineage_depth`, `test_skill_post_execution_hook.py::test_hook_latency` (200ms), and `test_skill_post_execution_hook.py::test_discipline_gate_blocks_live_write` (100% block rate on live SKILL.md writes). Old `skill-archive.jsonl` retained read-only for 30 days post-migration, then archived.
