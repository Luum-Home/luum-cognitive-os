## Decision
Cherry-pick exactly 3 primitives from OpenHarness (commit `7873f0d109174a57b3b1af7aa5397a6b3b0bd551`, fields read verbatim via `gh api`) — explicitly NOT a substrate migration; the 227 unique shell hooks, settings driver, skill router, and dispatch layer are untouched. (1) `HttpHookDefinition` ported to `lib/hook_types.py` with COS adaptations: `timeout_ms` (5000ms default) replaces `timeout_seconds` as primary field, adds `method`/`body_template`/`expected_status`, inherits from `HookDefinition(ABC)` instead of Pydantic to avoid a new dependency. (2) `PromptHookDefinition`, also in `lib/hook_types.py`: `prompt_template` (str.Template substitution) replaces `prompt`, `model_hint` (haiku/sonnet/opus tier names) replaces `model`, adds `inline_agent_subagent_type`/`max_tokens`, preserves `block_on_failure=True` default. (3) `ProviderProfile` credential-slot pattern ported to `lib/provider_profile.py`: `auth_slots: dict[str,str]` replaces the single `credential_slot` (format `"ENV:<VAR_NAME>"` for auditable env-var indirection), `model_aliases` replaces `default_model`/`allowed_models` with the existing opus/sonnet/haiku tier mapping, loaded from `manifests/provider-profiles.yaml` (absent file = no-op, backward compatible with existing `lib/providers/REGISTRY`).

## Why
ADR-171 (the "removed-integration lesson") requires verifying upstream source before adopting any external pattern — all field definitions here were read directly from the exact upstream commit rather than from documentation or memory, per that precedent. The adoption targets a concrete structural gap (operators cannot wire an HTTP callback or inline prompt as a hook without a shell wrapper) and a concrete maintainability gap (credential config scattered across provider modules instead of centralized).

## Consequences
- Positive: once wired, operators can declare HTTP-callback and inline-prompt-validation hooks in `cognitive-os.yaml` without shell scripts; provider credentials centralize into one YAML file; `lib/providers/__init__.py` gains a `get_provider_profiles()` shim with zero changes to existing `REGISTRY`/`is_configured()`/`get_client()` symbols.
- Negative: execution is NOT wired — `HttpHookDefinition`/`PromptHookDefinition` are declared types only; the hook dispatcher does not yet dispatch them natively, so operators must use disabled shell shims (`hooks/example-http-callback.sh.disabled`, `hooks/example-prompt-hook.sh.disabled`) in the interim. `ProviderProfile` schema may need extension if upstream adds fields COS missed (mitigated: `from_dict` ignores unknown keys). Cherry-pick risk of hidden cross-primitive dependencies was checked via import analysis (COS ports are standalone dataclasses, no transitive OpenHarness import) but OpenHarness itself was only 35 days old with no observed canonical test-suite run, so the upstream executor's semantic behavior was not verified end-to-end.

## Status & current state
Accepted, implementation_status: partial. Implemented: `lib/hook_types.py`, `lib/provider_profile.py`, `manifests/provider-profiles.yaml` (5 seeded profiles), `lib/providers/__init__.py` extension, two disabled shell-shim examples, and 43 passing unit tests (26 + 17). Explicitly deferred: wiring `HttpHookDefinition`/`PromptHookDefinition` into the actual hook dispatcher, and `AgentHookDefinition` (out of scope for this ADR, would need full subagent lifecycle management). Trust Report confidence: 0.87.
