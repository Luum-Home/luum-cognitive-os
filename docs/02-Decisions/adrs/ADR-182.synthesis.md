## Decision
Introduce a branch ownership lock primitive. A session intending to mutate a branch acquires a lease recorded at `.cognitive-os/runtime/branch-locks/<branch-slug>.lock` (JSON with branch, session_id, pid, worktree, acquired_at, ttl_seconds=14400 default, expires_at, renewed_at). New `PreToolUse Bash` hook `hooks/branch-ownership-lock.sh` matches destructive git verbs (commit, push, reset --hard, rebase, merge, cherry-pick, stash apply/pop, worktree add/remove, branch -D): acquires the lock if none exists; proceeds if the lock belongs to the current session or a dead-PID session past TTL; hard-blocks with a named-holder error if a different live session holds it. Lock releases explicitly (`cos-branch-release`), on session-end (Stop hook), or when TTL expires with a dead holder PID. The holder's UserPromptSubmit hook auto-renews TTL. Lock key is the branch name, not the worktree. An explicit auditor read-only carve-out lets an agent inspect a sibling worktree/branch without acquiring the writer lock, routing findings through the directed agent message bus instead of mutating.

## Why
Existing partial concurrency primitives were insufficient: `task-claims.json` is advisory and per-task, not per-branch; `active-sessions.json` is a PID registry, not exclusion; `destructive-git-blocker.sh` is per-session and blind to peers; ADR-111's concurrency_safety primitives are passive, not an arbiter. What was missing was a hard exclusion lock at the branch level. The postmortem's concrete incident: two orchestrator sessions writing contradictory disposition policies (annotate-and-keep vs delete-and-tombstone) to the same subject with zero mutual awareness, destructively overwriting each other's ADR-171/ADR-179 work.

## Consequences
Positive: tonight's incident class becomes structurally impossible — a second session would hit a hard block on its first commit attempt; operator can run multiple Claude Code tabs on different branches without cross-talk fear; postmortem action item P1 closed. Negative: ~10ms latency added to every destructive git op; new hook increases standard security-profile surface area; a misbehaving zombie reaper could leave a session falsely blocked (mitigated by TTL auto-release + explicit `COS_ALLOW_BRANCH_OWNERSHIP_OVERRIDE=1` operator override). Neutral: this is a per-machine local lock — no cross-machine coordination (that's ADR-184's territory).

## Status & current state
Accepted and implemented: `hooks/branch-ownership-lock.sh`, `lib/branch_lock.py` (acquire/release/holder/is_held_by_other/renew API), `tests/contracts/test_branch_ownership_lock.py`, plus `lib/session_coordination.py` and `lib/agent_message_bus.py` for the auditor carve-out. Falsifiable claim: two simultaneously-started sessions targeting the same branch must show (a) first acquires, (b) second's git commit hook fails with the documented error, (c) after release/TTL-expiry the second can proceed — if the lock ever fails open under plausible workload, the implementation is broken and must be revisited. Known limitation: direct terminal git commands outside any Claude Code session bypass the hook entirely (advisory only in that case).
