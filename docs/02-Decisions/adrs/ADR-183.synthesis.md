## Decision
Extend the existing minimal `lib/session_bus.py` append-only bus with a fixed event schema and two hooks. Event log: `.cognitive-os/sessions/events.jsonl`, append-only, standardized payload shape (schema_version, timestamp_epoch, event_type, session_id, pid, project_dir, payload). Pinned v1 event taxonomy (open but with a floor that must not regress): session-start, branch-acquire/release, coordination-claim, worktree-intake, agent-message-sent/ack, agent-spawn, file-write-intent, commit-intent/landed, session-end. `hooks/cross-session-event-emit.sh` emits most of these; `lib/branch_lock.py` emits branch-acquire/release; `lib/agent_message_bus.py` emits message events. `hooks/cross-session-peer-context.sh` runs at UserPromptSubmit, reads the last 200 events, filters to live peer sessions active in the last 30 minutes, and injects an `additionalContext` summary (peer's branch, recent file writes, inferred topic) so the orchestrator can coordinate or back off before issuing conflicting changes. Log rotates at 50MB or weekly to `.cognitive-os/sessions/events-archive/<YYYY-MM>.jsonl.gz`.

## Why
COS already had a minimal shared bus (`session_bus.py`, `session_event_bus.py`, `events.jsonl`) — the gap was not absence of any bus, but that the existing bus was too generic and too lightly wired: it didn't emit the full cross-session taxonomy, didn't summarize peer activity at prompt-submit time, and didn't connect to the claim ledger or directed message bus. ADR-182 (branch ownership lock) *prevents* conflicts by enforcement; this ADR provides *awareness* even when sessions don't contend on the same branch — the missing piece that would have surfaced the second session's conflicting `ADR-171-tombstone.md` write in the first session's context, prompting coordination instead of silent overwrite.

## Consequences
Positive: orchestrator gains peer awareness without manual operator inspection; the incident pattern (two sessions silently writing contradictory content) becomes detectable via file-write-intent surfacing at UserPromptSubmit; provides a debuggable audit trail of inter-session activity. Negative: adds disk I/O on every relevant tool call; privacy — file paths and topic keywords leak between sessions on the same machine (mitigated by opt-out env var, data stays local); requires tail-style JSONL reads with PID liveness checks. Neutral: this is advisory only, not enforcing — ADR-182 enforces, ADR-183 informs.

## Status & current state
Accepted and implemented, extending `lib/session_bus.py` plus emit/context hooks. Acceptance criteria specify latency budget <100ms for the peer-context hook, non-empty `additionalContext` only when peers exist, git-ignored log, and killswitches `DISABLE_HOOK_CROSS_SESSION_EVENT_EMIT=1` / `DISABLE_HOOK_CROSS_SESSION_PEER_CONTEXT=1`. Falsifiable claim: correct if, over a 90-day audit window, peer-context injection detects peer activity in >=95% of multi-session events with <60s worst-case detection lag and measurably reduces duplicate/conflicting commits — if the conflict rate hasn't decreased or lag exceeds 60s at p99 after 90 days, the design is broken and must be revisited.
