## Decision
Adopt a typed, severity-graded, append-only directed message queue (`lib/agent_message_bus.py`, implemented as `agent_message_bus` because it also carries implementation requests, questions, replies, and status messages, not just audit findings) living at `.cognitive-os/coordination/agent-messages.jsonl`. Findings carry `severity` (block/warn/info), a `target`, a `body`, and structured metadata. A PreToolUse Bash hook (`agent-message-inbox-guard.sh`) surfaces unacknowledged `severity=block` messages targeting the current session — warning by default, blocking under `COS_AGENT_MESSAGE_GUARD_MODE=block`. Acknowledgement is explicit and append-only (`ack_message`), stitched by `message_id`, so consumed-but-unresolved findings can be detected and re-escalated by a follow-up auditor run.

## Why
The gap was specifically about directive semantics — ADR-183's generic cross-session event log informs peers of activity but has no severity gating, target filtering, or consumed/resolved state, so a finding sat alongside routine `commit-intent` events without distinction. The JSONL queue is deliberately the runtime source of truth and does not depend on Engram availability, because Engram writes are best-effort and Codex/Claude environments don't always expose the same `mem_*` tools — "the JSONL is the runtime queue; Engram is an optional archive."

## Consequences
Positive: the auditor-finds-bug/implementer-never-sees-it failure mode becomes structurally addressable — a finding gets injected into the next matching orchestrator's context and must be consumed before commit if blocking; operators gain a first-class backlog of unresolved findings. Negative: a new JSONL file to manage and rotate (50MB rotation, 30-day TTL auto-archive); adds latency to every UserPromptSubmit (~50ms) and commit (~10ms); risk of finding-spam from overused low-severity emission, mitigated by severity filtering at the hook level and content-hash dedup at emission; the queue is per-machine only in v1, cross-machine delivery requires Engram Cloud federation (ADR-136).

## Status & current state
Accepted and implemented: the message bus, CLI (`scripts/cos-agent-message`), inbox guard hook, inbox-context hook, and unit tests for send/inbox round-trip, severity filtering, ack-state stitching, and blocking-before/after-ack all exist per the frontmatter's `implementation_files` list. A 2026-05-06 follow-up added a companion (not a replacement) inbound-signal protocol at the harness-adapter layer (`event_type: "inbound_signal"`, carrying control/answer/interrupt signals for stop/pause/resume) enforced via `agent-control-inbound-guard.sh` for hook-capable runtimes without a process handle, or `lib.agent_control_policy.evaluate_control()` for runtimes without hooks. The ADR sets a falsifiable 90-day claim: ≥95% detection rate for unresolved findings within one prompt cycle, zero commits landing with an unresolved blocking finding, <5% false-positive rate, and p99 hook latency <200ms even at 100+ pending findings — if detection rate, severity-gate efficacy, or latency fail, the ADR must be revisited.
