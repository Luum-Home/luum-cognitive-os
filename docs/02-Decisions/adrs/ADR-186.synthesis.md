## Decision
Activate ADR-038 Wave 3 enforcement via `lib/context_budget.py` (pure stdlib, `len(text)//4` heuristic token counting with optional `tiktoken` via `COS_USE_REAL_TOKENIZER=1`), a `hooks/context-budget-meter.sh` registered last in the UserPromptSubmit chain to see all prior injections and log a full JSONL breakdown, and a shared per-hook accountant (`hooks/_lib/context_budget_lib.sh:context_budget_emit_or_skip`) that every additionalContext-emitting hook must call before emitting — skipping injection with a stderr warning if the remaining budget is exhausted. Verdicts are PASS (≤1.0x budget), WARN (1.0-1.5x, non-blocking), BLOCK (>1.5x, non-zero exit unless `COS_ALLOW_CONTEXT_BUDGET_OVERRUN=1`).

## Why
ADR-038 Wave 2 had declared numeric budgets in `cognitive-os.yaml` (`static_max_tokens: 4000`, `turn_max_tokens: 8000`, `user_max_tokens: 12000`, `cache_max_tokens: 32000`) but Wave 3 enforcement "never landed." In the 8 hours preceding this ADR, five separate hooks were added that each inject 100-500 characters of additionalContext at 15-30% hit rates — a worst-case all-fire overhead of 800-2000 extra characters before the operator's actual question is even consumed, compounding across a session's turns. Without enforcement, the orchestrator's prompt grows silently and unmeasured; this ADR converts a declarative-only budget into one with real runtime teeth.

## Consequences
Positive: the runaway-context risk becomes observable and bounded; the operator gains a quantitative per-prompt metric of exactly how many tokens hooks added; future ADRs that add another additionalContext source can be tested against the existing budget instead of judged by intuition. Negative: adds ~5-15ms latency per UserPromptSubmit; the v1 heuristic tokenizer is approximate and may WARN when a real tokenizer wouldn't; hook ordering now matters more — a low-priority suggester late in the chain can be starved by an earlier high-priority one consuming the budget first (mitigated by documented priority ordering in `cognitive-os.yaml`).

## Status & current state
Accepted, `implementation_status: implemented`. All acceptance criteria shipped: `lib/context_budget.py` API, the meter hook registered last in chain, the shared accountant wired into the skill-router/rule-router/ADR-relevance suggester hooks (with cross-session-peer-context and agent-message-inbox wired "when implemented" per their own ADRs), sub-agent preamble counting via `subagent-context-injector.sh`, and `tests/contracts/test_context_budget_enforcement.py` covering emit/skip and threshold transitions. Falsifiable claim for a 30-day window: 100% of prompts produce a metrics entry, ≥90% PASS rate (WARN ≤8%, BLOCK ≤2%), override usage <5%, meter p99 latency <30ms.
