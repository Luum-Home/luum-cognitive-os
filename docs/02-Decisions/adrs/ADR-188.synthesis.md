## Decision
When the skill router emits a match at `confidence >= 0.90` for the current user prompt, the orchestrator must do one of three things: invoke the suggested skill, invoke a strictly more powerful skill that subsumes it (with a 1-line justification), or emit an explicit `SKILL_BYPASS:` annotation with a concrete reason, persisted to `.cognitive-os/metrics/skill-bypass.jsonl` for retro-audit. A new hard-gate hook (`hooks/orchestrator-skill-invocation-gate.sh`) runs on PreToolUse:Agent/Bash and WARNs when a high-confidence suggestion was ignored without annotation; three WARNs in one session escalate to a BLOCK with a one-time env-var override.

## Why
The existing `skill-router-prompt-suggest.sh` hook was suggestion-only — advisory `additionalContext` the orchestrator could freely ignore. This produced two recurring failure modes already documented before this ADR: bespoke prompt drift (ad-hoc prompts that look like research but silently skip a skill's output schema, depth gates, and persistence guarantees) and orchestrator bandwidth burn (the operator babysitting decisions the skill had already pre-resolved). The 2026-05-06 repo-scout incident is the concrete, named case, and an earlier instance of the identical anti-pattern is documented in `docs/06-Daily/reports/audit-corpus-revalidation-2026-05-05.md` — proving this was a repeat pattern, not a one-off.

## Consequences
Positive: the repo-scout failure mode becomes structurally detectable and auditable — operators can answer "did you use the skill?" by reading a JSONL file instead of trusting the orchestrator's word; skills become first-class contracts reliably applied at high confidence; creates back-pressure on skill quality (frequent bypasses signal a broken or over-fit routing pattern). Negative: adds ~10-30ms latency per Agent/Bash launch; operators must learn the `SKILL_BYPASS:` annotation syntax; risk of false-positive blocks if routing patterns rate too many prompts above 0.90 (mitigated by tuning routing patterns, not by lowering the global threshold).

## Status & current state
Accepted and implemented 2026-05-06 — hook registered across all three harness drivers (claude-code, codex, bare-cli) with contract tests covering all five acceptance scenarios passing. Falsifiable claim set for a 60-day audit window: bypass rate should stay under 10% of high-confidence suggestions, repeat-bypass-same-skill under 3/week without a routing-pattern fix, skill-invocation frequency should rise ≥30% versus the prior 60 days, and gate latency p99 should stay under 50ms. The 0.90 threshold is explicitly noted as "a guess" pending recalibration once bypass audit data accumulates.
