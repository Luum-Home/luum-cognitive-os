## Decision
Adopt a manifest-backed cross-stack secret audit policy: primary toolchain is `gitleaks` + `trufflehog` (both run by default, either finding a real secret fails the audit); secondary scanner `detect-secrets` for Python/pre-commit; forensic escalation to ScanCode Toolkit when primary tools disagree; commercial/SaaS tools (GitGuardian, Snyk) remain optional, never required. New artifacts: `manifests/cross-stack-secret-audit.yaml`, `lib/cross_stack_secret_audit.py`, `scripts/cos-cross-stack-secret-audit`, `cos secret audit [--json] [--strict] [--verify-live]`, installer scripts, and a pre-commit hook.

## Why
No release-readiness audit CLI existed — an operator had no single command to ask "is this safe to publish, no secrets/env files/keys/PII?" The 2026-05-06 audit (gitleaks + trufflehog + custom regex, assembled ad-hoc) had to invent this each time. Also no canonical toolchain policy existed — the choice of scanners was orchestrator instinct, not a manifest-backed reproducible decision. This mirrors the licence-audit gap ADR-212 already closed; this ADR closes the symmetric gap for secrets, per the dogfood-evidence pattern of the orchestrator repeatedly bypassing canonical primitives because none existed.

## Consequences
Positive: one multi-stack audit path covers Python/Go/Node/shell/docs/fixtures; closes the orchestrator-bypass pattern (dogfood evidence #7, #15, #16); symmetric CLI shape with ADR-212's licence audit; schema-versioned output (`cross-stack-secret-audit-report/v1`) feeds ADR-201 and ADR-211. Negative: two binaries (gitleaks + trufflehog) instead of one; trufflehog is AGPL-3.0 so it must be invoked via subprocess only, never imported (per ADR-006's AGPL ban); operator must install scanners; placeholder allowlist requires ongoing curation as fixtures land.

## Status & current state
Partial. Active first slice (2026-05-06): manifest declares policy/placeholders/allowlists/report paths; `lib/cross_stack_secret_audit.py` audits scanner availability, mutable GitHub Actions tags, sensitive local surfaces, and summarizes existing redacted reports; CLI entrypoint and `cos secret audit` wired; unit + behavior tests cover the active substrate. Not yet active: scanner run wrappers, pre-commit integration, curated baseline, and ADR-211 hard-gate consumption — so the repo has a whole-repo audit command but not yet automatic release blocking. Remaining in scope per frontmatter: known-bad scanner version blocking (blocklist currently empty, populated as incidents emerge).
