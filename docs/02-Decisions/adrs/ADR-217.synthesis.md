## Decision
Adopt a manifest-backed cross-stack adoption-truth audit mirroring ADR-212's shape: canonical CLI `cos adoption audit [--json] [--strict]`, manifest `manifests/cross-stack-adoption-truth.yaml`, schema-versioned report (`cross-stack-adoption-truth-report/v1`), implementation in `lib/cross_stack_adoption_truth.py` + `scripts/cos-cross-stack-adoption-truth`. The audit inventories dependencies across Python/Go/Node/submodules, parses NOTICE and `component-sources.md`, and classifies each dependency's `adoption_verdict` as one of: `INTEGRATED`, `INTEGRATED_UNTRACKED`, `DEAD_IN_NOTICE`, `ASPIRATIONAL_PLANNED`, `OVERCLAIMED`, `ACTIVELY_TRACKED`, or `NOT_APPLICABLE`. `--strict` exits non-zero on any `DEAD_IN_NOTICE`, `ASPIRATIONAL_PLANNED`, or `OVERCLAIMED` finding.

## Why
ADR-212 (license audit) and ADR-215 (secret audit) both audit what is in the codebase, not whether it is adopted as documented. Four sources of truth — lockfiles, NOTICE, component-sources.md, and external-tools-inventory reports — routinely disagree, creating four dangerous combinations: dead deps accredited in NOTICE, PLANNED status leaking as a marketing feature claim, untracked adoption drift, and overclaimed integration for WATCH/EVALUATED status items.

## Consequences
Positive: one audit replaces four manual cross-references nobody actually runs; marketing copy cannot ship WATCH/PLANNED features as shipped (ADR-206 enforces, ADR-217 detects); NOTICE can never accredit a nonexistent dep; schema-versioned output lets the Maintainer agent (ADR-201) consume verdicts deterministically. Negative: requires ongoing manifest curation for new dep types; may false-positive `INTEGRATED_UNTRACKED` for transitive deps if the allowlist is incomplete; initial baseline run is expected to surface a backlog of `OVERCLAIMED` entries from legacy marketing copy.
