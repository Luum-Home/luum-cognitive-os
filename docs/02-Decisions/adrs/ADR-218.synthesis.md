## Decision
Adopt a manifest-backed history-sanitization primitive: canonical CLI `cos history sanitize [--dry-run|--execute] [--json]`, default mode `--dry-run` (in-memory plan + diff report, no ref mutation); `--execute` requires `COS_ALLOW_DESTRUCTIVE_GIT=1` (per ADR-055b) AND an explicit interactive y/n confirmation even when the env var is set. Backed by `git-filter-repo` (not the deprecated `git filter-branch`). Manifest `manifests/history-sanitization.yaml` declares text replacements (operator email, home/repo path prefixes), preserve patterns (license-transition text, test-fixture placeholders like `[REDACTED]`/`deadbeef` that must never be scrubbed), and a backup-or-refuse invariant (`git clone --mirror` to `.cognitive-os/recovery/` before any execute). Blob content is rewritten by default; author/committer metadata and commit messages are preserved unless the operator explicitly sets `COS_HISTORY_SANITIZE_METADATA=1` / `COS_HISTORY_SANITIZE_COMMIT_MESSAGES=1`.

## Why
ADR-055b already gates raw destructive git ops behind explicit operator authorization; this ADR layers a manifest-backed primitive on top so history sanitization becomes auditable, repeatable, and bounded — rather than an ad-hoc `git filter-branch` invocation that's easy to misuse. The operator's Path 4 decision (preserve history, recorded in `.cognitive-os/strategy/04-license-repo-and-corrections-log.md`) created the tension this ADR resolves: scrub genuinely sensitive content from old blobs without a fresh repo, without losing the license-transition narrative, and without ad-hoc destructive commands.

## Consequences
Positive: history-rewrite becomes manifest-driven and auditable; the preserve-list explicitly protects honest history (license transition, test fixtures) from accidental scrubbing; backup-first removes the "lost my git history" failure mode; ADR-055b gating prevents accidental invocation; schema-versioned report enables post-publish forensics. Negative/trade-offs: all SHAs change on execute, invalidating refs/tags/signed commits (mitigated by running only pre-first-public-push); operator must force-push manually after sanitization; future leaks cannot reuse the same manifest a second time without escalating process (intentional friction — repeated rewrites cause permanent drift for any existing clones); `git-filter-repo` requires installation.

## Status & current state
Partial — slices 1-6 active as of 2026-05-06/07: manifest declares env-backed replacements and preserve patterns; `lib/history_sanitization.py` emits `history-sanitization-report/v1`, counts candidate hits without materializing full blobs, detects replacement-vs-preserve conflicts, and blocks execute without `COS_ALLOW_DESTRUCTIVE_GIT=1`; CLI dry-run path and unit/behavior tests (manifest loading, unresolved-env warnings, non-mutating dry-run, destructive-env refusal, preserve-conflict blocking) pass. Not yet active: the live `git-filter-repo` rewrite itself, mirror-backup creation, the interactive confirmation prompt, installer wiring, and the operator runbook — the automated part can detect and plan the scrub, but mutating public history remains fully operator-approved and not yet executable end-to-end. Expected single execution: shortly before the first public push, never repeated after.
