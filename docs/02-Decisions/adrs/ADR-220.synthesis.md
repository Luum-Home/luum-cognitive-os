## Decision
Adopt a manifest-backed worktree-divergence audit primitive: `cos worktree audit [--json] [--strict] [--against <ref>]`, defaulting to comparing against `origin/main` (falling back to `main`, then `@{upstream}`). It detects four categories — `silent_divergence` (worktree behind main with unchanged-looking-but-actually-stale files), `path_conflict_pending` (main touched paths the worktree also has dirty), `cross_worktree_overlap` (another linked worktree holds a stash on overlapping paths), and `reapply_risk` (worktree's pending diff is a strict superset of a commit already on main) — and is strictly read-only, never mutating refs/index/working-tree/stash.

## Why
Existing primitives don't cover this failure mode: ADR-129 gates worktree *removal* safety, ADR-182 locks *branch ownership* across sessions, and ADR-219 enforces *claim liveness* — none of them detect the case where everything looks healthy by their own criteria but the operator's mental model of "did my fix land?" is simply wrong because their worktree silently fell behind main. `cos_work_inventory.py` already reports stash counts and claim queues but not branch-vs-main divergence or which files main touched since the divergence point. The 2026-05-06 session hit this exact mechanism twice in a row (the license-switch commit `598b95bd` and the email-redaction commit `02e97bcd`, both on main), risking the operator re-applying or discarding already-completed work.

## Consequences
Positive: closes a class of bug that bit the same session twice; gives operators one authoritative answer to "is my worktree out of sync with main in a way that affects my pending work?"; reuses ~80% of plumbing from the existing ADR-212/215/217 manifest+CLI+schema-versioned-report pattern rather than inventing a new shape. Negative/trade-offs: one more tool to maintain; `silent_divergence` will legitimately fire when an operator deliberately wants a stale branch (mitigated via an allowlist keyed on branch pattern, e.g. `release/.*`); `cross_worktree_overlap` requires reading other worktrees' stash lists, which can be slow with many worktrees (mitigated by per-audit-run TTL caching); adds a non-zero-cost step to every governed preflight call (budgeted at <200ms on a clean repo).

## Status & current state
Accepted, `implementation_status: partial` — "preflight/readiness gate active." The manifest declaration itself (`manifests/worktree-audit.yaml`) is deliberately deferred: Slice A embeds the ruleset directly in `lib/worktree_audit.py` rather than shipping the YAML, per the project rule "no metadata without consuming code" — the target manifest shape is fully documented in the ADR but not loaded at runtime, and will only be promoted to a real file once a second out-of-process consumer needs to read the same rules. ADR-116 governed preflight consumes the CLI's `--strict` exit code as an additional check. Open question left unresolved: whether `reapply_risk` should default to BLOCK or WARN (currently WARN, pending 30 days of telemetry).
