## Decision
All persistence of stash identity in Cognitive OS MUST use the immutable 40-char stash commit SHA (resolved via `git rev-parse stash@{0}` at the moment of push success), never the position-based `stash@{N}` reflog ref. Marker files, JSONL events, and manifests get a new `stash_sha` field (v2 schema); `stash_ref_at_capture` is retained only for human forensic readability, never for decision-making. Consumers must enumerate `git stash list --format='%H %gd %gs'` and match on SHA to find the current position — never apply/drop/inspect by historical `stash@{N}`. If a recorded SHA is absent from the current stash list, consumers must emit a `stash_lost` event rather than silently misapplying.

## Why
`stash@{0}` always means "most recent" — every new `git stash push` silently shifts every prior entry's index. Under multi-agent/parallel sessions, pushes interleave, so a marker recorded at time A may resolve to a completely different stash by the time its restore logic runs at time B. The 2026-05-06 session reproduced exactly this: three identical `auto-pre-agent-*` stashes accumulated with identical `stash@{0}` markers, and resolving any one of them would have applied the wrong stash — a bug class independently documented in Claude Code itself (GitHub issue #11005), the official `git-stash(1)` manpage's own warning about unrecoverable mistaken drops, and long-standing HN consensus that stash accidents are git's most common footgun. The deeper fix — not using `git stash` at all for pre-agent state capture, replaced by worktree-per-write-agent — is tracked separately as a larger architectural move; this ADR is the tactical SHA-based fix for as long as `git stash` remains in the pre-agent path.

## Consequences
Positive: eliminates the entire "applied the wrong/already-applied stash" bug class under concurrency structurally, not by convention; makes stash identity portable and comparable across processes/sessions/time; aligns with how Anthropic's eventual upstream fix to #11005 will likely have to be shaped. Negative/trade-offs: one release cycle of dual v1/v2 marker format support adds complexity (mitigated by conservative, fail-safe v1 fallback that refuses ambiguous subject matches rather than guessing); operator-facing logs lose the convenient `stash@{0}` shorthand (mitigated by keeping `stash_ref_at_capture` for display); existing in-flight v1 markers trigger a warning path on restore.

## Status & current state
Accepted, `implementation_status: partial`. Slice 1 is active: `lib/stash_sha.py` provides SHA-first helpers, `lib/snapshot_manager.py` writes `tracked_stash_sha` and applies by SHA, `hooks/pre-agent-snapshot.sh` writes the v2 marker schema, and `hooks/post-agent-snapshot-restore.sh` resolves by SHA with position-drift tolerance — all covered by regression tests. Remaining follow-up (explicitly still open): update `stash_provenance` / SessionStart reapply logic to persist and consume `stash_sha`, and add grep-based CI audit tests (`tests/audit/test_no_position_stash_refs.py`, `test_no_position_apply_in_os_code.py`) forbidding position refs in apply/drop/show code paths.
