## Decision
Ship `lib/shadow_git.py` as the canonical checkpoint substrate: one bare git repo per session at `~/.cognitive-os/snapshots/{project_id}/{session_id}/.git`, outside the user's project tree, with three operations. `snapshot(workspace_path) -> tree_sha` stages the workspace via an isolated `GIT_INDEX_FILE` (never touching the user's real index) and runs `git write-tree`, idempotently returning the same SHA for an unchanged workspace. `restore(tree_sha, workspace_path, mode)` supports three modes mirroring Cline's UX — `files_only`, `conversation_only` (truncates ADR-226 events past the originating `seq`), and `files_and_conversation` (atomic combination) — always preceded by a mandatory `git diff-tree` preview written to disk before any destructive operation, with the CLI (`cos rollback`) refusing to proceed without operator confirmation or `--yes`.

## Why
The dominant checkpoint failure mode documented in the prior-art research is the "context-mismatch bug": restoring files without truncating the corresponding conversation events leaves the agent in an inconsistent state (Hermes solves this; the Claude Code SDK's `rewindFiles()` explicitly does not, per its own docs). ADR-227 makes atomicity a hard rule via a session-scoped `flock` restore lock so file-restore and conversation-truncation happen as one operation or roll back entirely. Shadow-git was chosen over VM snapshots (no hypervisor allowed per constraint C2), block-level CoW (requires storage-backend control the local-first OS doesn't have), `git stash` (doesn't capture untracked files and pollutes semantics the research explicitly argued against), and per-event commits to the user's own repo (pollutes `git log`, breaks bisect).

## Consequences
Positive: Devin-parity replay-and-restore at zero infrastructure cost; the unique combination of ADR-227 (file state) plus ADR-226 (event sequence) means every governance event (blast-radius assessment, policy check, audit finding) can carry a `file_tree_sha`, enabling "governance-as-restore-point" that no competitor was found to offer; untracked-file capture closes a gap `git stash` doesn't solve. Negative: storage growth (one bare repo per session, mitigated by ADR-200 retention GC on session close); snapshot latency can spike on large workspaces (budgeted p95 <200ms, hard block above 500MB, warning above 50MB); restore-mode confusion risk, mitigated by mandatory diff preview and explicit CLI help.

## Status & current state
Accepted, Slices A-F implemented 2026-05-07. Actually shipped: `lib/shadow_git.py` creating off-repo bare repos, isolated-index snapshotting, restore previews, and preview-gated `files_only` restore, plus `scripts/cos-rollback` exposing `--snapshot`/`--preview`/`--restore --yes`. Explicitly deferred per the ADR's own "Implementation status" section: conversation truncation, the combined atomic `files_and_conversation` restore mode, PostToolUse event-envelope wiring (so governance events don't yet carry `file_tree_sha` automatically), and retention/reaper integration. The test-tier matrix marks T6 (performance) and T8 (cross-harness, N/A) and T9 (adoption-truth, pattern-only) as not fully checked.
