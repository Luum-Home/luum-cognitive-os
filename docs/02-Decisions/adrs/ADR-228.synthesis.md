## Decision
Ship `lib/dispatch_gate.py` as a unified pre-call gate consolidating both fixes into one chokepoint (both live in `dispatch()`, both need a sync gate, both need post-call accounting, both are file-backed): (1) `classify_failure()` — single authoritative classifier mapping exceptions/responses to one of `connection_layer`, `rate_limit`, `provider_5xx`, `validation_error`, `auth_error`, `quota_exceeded`, `unknown`, replacing all six scattered rules; (2) deterministic per-class retry policy (e.g., connection_layer: 4 attempts exponential backoff; validation_error: 2 attempts with mandatory prompt-diversity; auth_error/quota_exceeded: 0 retries, escalate immediately); (3) `SessionBudget` — file-backed at `.cognitive-os/metrics/session-budgets/{session_id}.json`, with `pre_call_check` raising `SessionBudgetExceeded` synchronously before the HTTP request fires; (4) graduated backpressure at 70%/90%/100% of budget (caution signal → switch to cheaper model tier → refuse) instead of a binary hard-stop; (5) `IdempotencyKeyMixin` required on any tool with `mutates_external_state: true`, keyed by `sha256(session_id + event_seq + tool_name)`; (6) a per-provider circuit breaker (error rate + p95 latency + quota % + validation failure rate) with open/half-open/closed states, file-backed to survive process restarts. ADR-229 (originally the cost-budget ADR) is now a tombstone pointing here.

## Why
Retry-without-cost-awareness produces the $47K-incident class of failure; cost-without-retry-classification produces silent connection-error drops and wrong retries for validation errors (a `quota_exceeded` error retried for free still costs operator time). The two gaps are architecturally coupled because they share the exact same fix surface (`dispatch()`), so consolidating into one ADR/one gate avoids two parallel modifications to the same hot path.

## Consequences
Positive: the $47K-incident class becomes structurally impossible for sessions running through the gate; six contradictory retry rules collapse into one canonical classifier+policy; validation errors get correct re-prompt-with-schema retry (closing the LangGraph+Pydantic trap) instead of blind retry; idempotency keys eliminate silent duplicate side effects (Slack messages sent twice, DB rows written twice) estimated at 15-30% of LLM tool-call retries; circuit breaker prevents cascading failure on provider degradation. Negative: one more layer in the dispatch hot path (mitigated — p95 <2ms, in-process file read only); manifest-driven retry is less flexible than per-call overrides (mitigated by an explicit override parameter); per-session ledger avoids contention but requires `cost-events.jsonl` as the canonical rebuild source; operator confusion at budget hits is mitigated by explicit tier/threshold messaging. Rejected alternatives: adopting LiteLLM or Temporal as runtime dependencies (violates the no-external-runtime-dependency constraint C2); building the cost gate without the classifier or vice versa (each alone reproduces one of the two original failure modes); opt-in idempotency ("opt-in idempotency is opt-in side-effect-duplication").

Accepted; Slices A-E implemented 2026-05-07 (`lib/retry_classifier.py`, `lib/session_budget.py`, `lib/dispatch_gate.py`; manifests `retry-contract.yaml`/`session-budget.yaml`; `rules/retry-contract.md`).
