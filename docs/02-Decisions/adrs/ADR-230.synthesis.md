## Decision
Ship `lib/handoff_envelope.py` + `lib/handoff_dispatcher.py` as the canonical handoff protocol, with three primitives: (1) a frozen `HandoffEnvelope` dataclass that every cross-agent call MUST construct — no raw `dispatch_to_agent(prompt)` calls, CI-enforced — carrying identity, `intent` (delegate/handoff/query), `context_mode` (full/summary/reference/none), granted tools, depth, and the full call chain; (2) call-chain deduplication — before dispatch, checks if `to_agent` is already in `call_chain` and raises `HandoffCycleDetected` if so (described as "<1 day of code, highest-ROI safety primitive in the orchestration space"), plus a `MAX_HANDOFF_DEPTH = 7` defense-in-depth cap; (3) permission intersection — granted tools are the intersection of what the caller can grant and what the receiver's manifest declares it accepts, enforced server-side in the dispatcher, emitting a `handoff.permission.scoped_down` event rather than erroring. Handoffs above a blast-radius threshold require explicit operator approval via an exit-code-2 hook.

## Why
Three unsolved failure modes: infinite handoff loops (no cycle tracking anywhere in COS); context-passing without consensus (three competing patterns — full history, summarization, reference-only — each with documented failure modes, so the ADR makes the choice explicit per-handoff via `context_mode` rather than baking in one strategy); and permission inheritance silently expanding blast radius (OpenAI Swarm and Anthropic Agent Teams both default to flat inheritance, meaning a compromised or misconfigured sub-agent can do everything the caller could — the correct model, per ElevenLabs and prior-art research, is intersection not inheritance). The design borrows the envelope shape from Google A2A's `referenceTaskIds` (Apache-2.0, pattern-only) and LangGraph's `Command` (MIT, shape adopted, library not linked) — pattern adoption under C1, not runtime dependency adoption.

## Consequences
Closes the #1 production multi-agent failure mode (cycles) at under a day of code — described as the single highest-ROI item in the orchestration research. Typed envelope replaces ad-hoc string passing across both in-session subagents and cross-session calls, consumed identically by ADR-211 (service mode) and ADR-233 (agent teams). Trade-offs: one more typed struct in the hot dispatch path (mitigated — frozen dataclass, sub-millisecond construction); four context modes may confuse operators (mitigated by automatic depth-based defaults); permission intersection can silently narrow a delegation the caller intended (mitigated by the scoped-down event the caller can inspect). Explicitly rejected: hub-and-spoke status quo (doesn't scale to ADR-233), direct LangGraph/A2A library adoption (pattern-only sufficient), loose JSON typing (typing is the entire point), depth cap without cycle cap (acyclic but unbounded chains are still pathological), and opt-in permission intersection ("opt-in is opt-in-blast-radius-expansion").

## Status & current state
Accepted; Slices A-E implemented 2026-05-07: `packages/agent-lifecycle/lib/handoff_envelope.py` and `lib/handoff_dispatcher.py` (with symlinks) implement the frozen schema, cycle/depth detection, query read-only semantics, tool intersection, blast-radius blocking, ADR-226 event emission, and idempotent replay; `manifests/handoff-protocol.yaml` declares policy. Slice F (file-IPC transport, `cos team handoff send`) and Slice G (operator-controlled receiver execution, `cos team handoff receive --exec-command-template`) and Slice H (external receiver hooks via `--hook-command`) are also implemented, plus chaos coverage for kill-mid-dispatch (`tests/chaos/test_handoff_receiver_kill_mid_dispatch.py`). Current slices intentionally do not spawn agents or mutate worktrees — this is transport/dispatch machinery, not full agent execution.
