## Decision
Change the default `cognitive-os.yaml` setting from `sub_agent_cwd: main_worktree` to `sub_agent_cwd: isolated_worktree`. Write-capable agents now get a dedicated ADR-223 worktree via `hooks/agent-prelaunch.sh` / `scripts/cos-agent-worktree-prepare`; `hooks/agent-working-dir-inject.sh` no longer injects a shared cwd in isolated mode (defers to agent-prelaunch); `hooks/agent-bash-cwd-enforcer.sh` only rewrites git commands back to main when the policy is explicitly `main_worktree` (legacy); raw branch context changes (`git switch`, `git checkout <branch>`) are now blocked by `hooks/destructive-git-blocker.sh` as governed mutations unless explicitly audited via `--allow-branch-switch` or `COS_ALLOW_BRANCH_SWITCH=1`. Four policy modes remain available: `isolated_worktree` (new default, safest for 2+ agents), `current` (opt-in, safe only if caller controls branch), `main_worktree` (legacy, single-agent only), `branch` (opt-in, safer than shared main only with one branch owner).

## Why
A causal review found the anti-pattern was mixing path consistency (agents seeing the canonical repo path) with branch ownership (each writer needing an isolated HEAD/index) — `main_worktree` gave the former by sacrificing the latter. Agents had multiple legitimate-looking signals that made branch creation seem like the responsible choice (protected-branch guards discourage direct-to-main commits, ADR-116/ADR-225 describe branch-per-task isolation, `cos-session-branch.sh` exists to create branches, merge-queue docs normalize temporary branches) — but the system bug was allowing that branch creation to happen inside the *shared* operator worktree. Existing primitives (ADR-035's working-dir-inject, ADR-182's branch locks, ADR-223's prelaunch worktrees) were each individually reasonable but composed into an unstable mode: branch locks protect writes on the *current* branch but can't stop a prior command from having already moved the shared worktree to a different branch.

## Consequences
Positive: parallel write agents no longer mutate the operator worktree HEAD; `.git/index.lock` contention is reduced since each agent has its own index; commits get an auditable per-agent branch/worktree boundary before explicit merge to main; the C4 portability lane is safer since readiness agents can't silently shift each other's branch context. Negative: dedicated worktrees consume disk (observed roughly tens of MB per agent for this repo); agent cleanup/reaper paths remain important since abandoned worktrees must be reaped (tracked as follow-up, not yet automated); legacy tests/docs that intentionally exercise `main_worktree` must be relabeled as legacy single-agent mode.

## Status & current state
Accepted and implemented. `cognitive-os.yaml` sets the new default; `hooks/agent-working-dir-inject.sh`, `hooks/agent-bash-cwd-enforcer.sh`, `hooks/agent-prelaunch.sh`, `hooks/destructive-git-blocker.sh` all updated per the decision; covered by `tests/integration/test_agent_working_dir_inject.py`, `tests/integration/test_cwd_enforcer_rewrite.py`, `tests/unit/test_destructive_git_block.py`. Explicitly does NOT guarantee automatic worktree cleanup — abandoned-worktree reaping is a tracked follow-up, not yet built.
