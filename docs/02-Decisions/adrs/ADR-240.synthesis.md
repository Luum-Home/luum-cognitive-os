## Decision
Adopt a machine-readable primitive coherence manifest (`manifests/primitive-coherence.yaml`) declaring surfaces, owners, writers, write-protocols, and ordering constraints, plus a non-mutating audit script (`scripts/primitive-coherence-audit.py`). Slice A is intentionally read-only and checks: (1) ordering inversion in the hook chain, (2) registration-checker vs. classification-manifest disagreement, (3) undeclared multi-writer surfaces without an owner/protocol. Slice B extends this to recursive control-plane loops and third-party tool boundaries — every external tool adapter (git, git-filter-repo, trivy, syft, gitleaks) needs an owner, SPDX license, adapter name, allowed callers, failure policy, and explicit recursion boundary. Going forward, every new or promoted agentic primitive needs a machine-readable registration contract (kind, owner, lifecycle, mutates, reads/writes, surfaces, bypasses, ordering, external_tools, tests) before being treated as governed.

## Why
Cognitive OS has many agentic primitive classes (hooks, scripts, rules, skills, profiles, manifests, ledgers, gates, cleanup tools) that could each be locally correct yet globally incoherent. The named incidents above are the concrete motivating failures — none is hypothetical; each was found during release-prep review. The ADR explicitly enforces a "detection-before-repair" rule: contradictions must be observed by the audit before being manually fixed, otherwise a green audit result would just reflect hand-corrected primitives rather than genuine detector coverage.

## Consequences
Positive: gives operators one place to see cross-primitive contradictions; prevents profile regeneration from silently reordering mutating hooks before blockers; distinguishes intentional opt-in hooks from accidental orphans; foundation for release-readiness/service-mode gates. Negative: introduces another manifest to maintain; Slice A only covers a narrow set of contradictions; some initially noisy findings expected until legacy checkers consume the same manifest. Explicit non-goals: no auto-editing of `.claude/settings.json`, no auto-registering hooks, no deleting/rewriting state or git history, no inferring ownership from prose alone.

## Status & current state
Accepted — Slice A implemented (2026-05-08). Slice B (recursion + external-tool boundaries) is part of the decision text but implementation_files is empty in frontmatter, so treat Slice B as decided-but-verify-on-disk. Acceptance criteria: bad hook-ordering fixture blocks; classified opt-in hook reported by legacy checker produces a disagreement finding; multi-writer surface without protocol blocks; current repo audit emits JSON without mutating files. Future slices explicitly deferred: bypass-env conflict detection, producer-without-consumer detection, ADR status vs. implementation/test consistency, static write-surface discovery, integration into `cos-pre-public-risk-audit`.
