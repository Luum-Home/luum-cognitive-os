## Decision
Replace seven separately-named bypass env vars (`COS_ALLOW_DESTRUCTIVE_GIT`, `COS_BYPASS_COMMIT_GUARD`, `COS_ALLOW_MAIN_BRANCH_WRITE`, `COS_ALLOW_UNPROVEN_SCOPE_BOTH`, `COS_ORCHESTRATOR_CLAIM_GATE_MODE`, `DISABLE_HOOK_PUSH_COLLISION_CHECK`, `COS_ALLOW_DIRECT_PUSH`) with one allowlist variable, `COS_BYPASS=key1,key2,...`, resolved by a shared `hooks/_lib/bypass-resolver.sh` function `cos_bypass_allows <key>`. The resolver checks `COS_BYPASS`, then back-compat legacy envs (kept as aliases for one release), then `.cognitive-os/runtime/bypass.env` — the last of which is what makes `PreToolUse` hooks see the same bypass scope a shell-set inline var could not reach. Every listed gate hook switches to calling the resolver. A canonical cheatsheet at `docs/09-Quality/security/bypass-cheatsheet.md` lists every stable key (e.g. `destructive_git`, `commit_guard`, `main_branch_write`, `claim_gate`, `push_collision`, `direct_push`), what it disables, its audit-trail entry, and an example invocation.

## Why
Each of the seven bypass envs had a different naming convention and scope with no central document, so during the 2026-05-08 incident the operator resorted to `--no-verify`, discarding commit-signing checks, branch-ownership lock, and merge-queue gates all at once just to bypass one gate. Two hooks even named the same concept differently (`COS_ALLOW_DESTRUCTIVE_GIT` vs `COS_BYPASS_COMMIT_GUARD`), so honoring one didn't honor the other. The anti-pattern identified: per-hook bypass naming with no shared resolver undermines the governance value of fine-grained gates through cumulative friction.

## Consequences
Positive: one name and one document to learn; `PreToolUse` hooks see the same bypass scope as bash hooks via the runtime file; audit entries cite a stable key enabling namespace-level analysis in `agent-heartbeat.jsonl`. Negative: back-compat aliases mean two code paths for one release; the runtime file is one more piece of session-end cleanup state; operators must relearn muscle memory for new key names.

## Status & current state
Accepted, but explicitly PARTIAL: Slice A (shared resolver, cheatsheet, target hook integration, behavior tests) is active; broad ecosystem bypass consolidation beyond the listed hooks remains future expansion.
