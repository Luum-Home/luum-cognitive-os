## Decision
Introduce a "post-rewrite mode": `lib/history_sanitization.py` (and the ADR-242 wrapper) writes `.cognitive-os/runtime/last-rewrite.json` (`pre_head`, `post_head`, `rewritten_at`, `ttl_seconds`=86400, `rules_hash`). `hooks/_lib/push-collision-check.sh` and `scripts/push_collision_detect.py` consult this marker and admit subject collisions only when the marker is unexpired, local HEAD equals `post_head`, upstream HEAD equals `pre_head`, and the collisions fall within the rewrite's commit range. When admitted, every collision is still logged to `agent-heartbeat.jsonl` with the rewrite hash for audit — the check is bypassed, not silenced. The marker clears on first successful push or TTL expiry.

## Why
Post-rewrite, every commit keeps its old subject line but gets a new SHA, which push-collision-check normally (and correctly) treats as a sign of accidental duplicate commits. Without an exception, the only escape hatch was `--no-verify`, which killed commit-signing checks, branch-ownership lock, and merge-queue gates simultaneously — a much bigger blast radius than intended, and the bypass envs at the time didn't even reliably reach `PreToolUse` hooks when set inline (same root cause as ADR-241).

## Consequences
Positive: force-push after a deliberate rewrite no longer needs `--no-verify`; other push-time protections stay active; the audit trail retains the colliding commit set correlated to the rewrite hash. Negative: the 24-hour TTL is a narrow window where a coincidental non-rewrite force-push could match marker conditions; one more runtime file to manage at session end; the bash and python bypass paths must be kept in sync.

## Status & current state
Accepted, Slice A implemented: history sanitization writes the marker; push-collision detection consumes it. `tests/behavior/test_push_collision_post_rewrite.py` covers marker-match success, marker-expired fallback, marker-mismatch fallback, and audit-entry presence.
