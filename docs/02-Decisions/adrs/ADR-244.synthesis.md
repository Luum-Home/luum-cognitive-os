## Decision
Promote the claim-validator from advisory to blocking for high-stakes claims. Renamed `claim-enforcer` (`hooks/claim-validator.sh` retained as a one-release back-compat shim). When a `TRUST_REPORT` matches a trigger pattern (`\d+\s*(passed|tests pass...)`, `(fix|fixed|closes|resolves)\s+#?\d+`, `\b(green|all green|all passing)\b`), the validator must re-run the cited verification command in a **fresh context** and require exit-0 before the orchestrator accepts `completed`. If the command exits non-zero, status is downgraded to `partial` with the failing output attached as evidence — no automatic retry; the orchestrator decides per ADR-238 escalation rules. Agents may declare `verification: manual` for non-shell-runnable claims (UI smoke, design review); this bypasses execution but is logged, and repeated manual opt-outs from the same agent identity are a quality-signal flag.

## Why
The advisory model's worst outcome was a lower trust score, which "does not prevent regressions; it merely documents them" — the anti-pattern identified was scoring without enforcing, proven by the 2026-05-08 incident where a scored-and-accepted "completed" claim was immediately contradicted by re-running the same cited command.

## Consequences
Positive: a regression detected by the agent's own cited evidence cannot reach `completed` status; agents are incentivized to cite commands they actually ran since the enforcer re-runs them; the audit trail gains a strong claim-vs-reality record useful for agent-KPI rules. Negative: every high-stakes claim incurs an extra command execution (sub-second for focused tests, more for slow suites); agents with legitimately agent-internal-state-dependent verification must mark `manual` and accept the audit flag; the `claim-validator.sh` shim is one more deprecation surface to remove later.

## Status & current state
Accepted — Slice A implemented. `scripts/claim_enforcer.py` enforces structured `verification:` evidence for high-stakes claims; `hooks/claim-validator.sh` blocks on failed verification; behavior tests cover pass/fail/manual/no-op paths. Files: `hooks/claim-validator.sh`, `scripts/orchestrator_claim_gate.py`, `rules/trust-score.md`, `tests/behavior/test_claim_enforcer.py`.

## Key links
Extends ADR-105 (bilateral claim verification) and ADR-238 (escalation rules). Rejected alternatives: keeping the validator advisory, running the cited command inside the same agent (rejected — self-verification doesn't catch sycophantic completion), blocking all completions on a global suite run (too costly), and requiring human review for every claim (doesn't scale to 10-15 agent/sprint cadence).
