## Decision
Introduce `cos release freeze` as a transaction primitive for high-risk public/destructive operations. It creates a `release_transaction_id` and writes an immutable receipt (`.cognitive-os/runtime/release-freeze/<id>.json` plus a human-readable Markdown copy) across three phases: Prepare (verify repo stable enough to enter freeze), Freeze (block/pause non-allowlisted mutations), Release operation window (allow specific operations — content-only history sanitize, post-rewrite force-push, tag update, public publish — only when they reference the active transaction id). Ten required checks span working-tree cleanliness, expected branch, no active writers, no post-freeze branch switch, `cos-pre-public-risk-audit --strict` passing, primitive-coherence audit capture, metadata-rewrite flag absence unless explicitly declared, force-push referencing a recent rewrite marker, output sanitization on generated reports, and any "closed" completion claim attaching the transaction id + gate receipt.

## Why
A table of nine concrete incidents from the same session shows the pattern: agents changed branches without notice; sensitive data (operator email) was reintroduced after sanitization; content-rewrite paths were initially conflated with metadata-rewrite paths (risking erasure of human authorship); concurrent agents kept writing during force-push/rewrite prep, invalidating gates as soon as they passed; a security report itself leaked a local path regex; a script was renamed outside ownership during concurrent work; a pre-public audit false-positived on a markdown table; scorecards drifted from actual repo state (216 vs 218 hooks); and agents announced "closed" while the audit was still blocked. The common failure: the OS had many of the right individual primitives but no release transaction — a short-lived, audited mode where writes freeze, state is checked, and destructive ops require a receipt.

## Consequences
Positive: gives destructive/public operations a stable audited snapshot instead of a moving target; prevents sanitize/force-push/publish from racing background agents; makes "release ready" a receipt-backed state instead of an agent claim; provides one transaction id that ADR-218, ADR-239, ADR-240, ADR-242, ADR-243 and pre-public risk gates can all reference. Negative: adds ceremony before high-risk operations; can block legitimate emergency fixes unless an explicit override path exists (bypass is logged to `agent-audit-trail.jsonl`); requires future agent/daemon integration before it can fully pause all writers; Slice A may report active-agent false positives until liveness sources are normalized.

## Status & current state
Partial — Slice A implemented: `scripts/cos-release-freeze` provides `--prepare`, `--begin`, `--status`, `--end`; receipts under `.cognitive-os/runtime/release-freeze/`; history sanitization refuses during an active freeze unless `COS_RELEASE_TRANSACTION_ID` matches. Explicit non-goals for Slice A: no blind process killing, no auto-rewrite of history, no auto-force-push, no branch/worktree deletion, no author-email placeholder conversion, no treating hooks as active merely because files exist. Future slices (not yet built): hook integration so commit/push/rewrite hooks refuse without a transaction id; agent/daemon pause integration; report-sanitization-by-construction mode; merge-queue consumption of the freeze receipt instead of broad `--no-verify` bypasses.
