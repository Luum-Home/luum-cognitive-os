## Decision
Postmortem regression audits must be manifest-driven: `manifests/postmortem-regression-audit.yaml` declares checks (`forbidden_pattern`, `required_paths` types) mapped to owning ADRs, with a generic check engine (`scripts/cos-postmortem-regression-audit`) reading the manifest — no new Python code required per new ADR class. Sensitive values are never embedded in the manifest; they are referenced via `sensitive_value_sources.env` variable names. Every external tool used by a governance primitive must be declared with `tool`, `owner`, `license_spdx`, `adapter`, `allowed_callers`, `failure_policy`, `recursion_boundary`, `input_sensitivity`, and `output_sanitization`.

## Why
ADR-239 through ADR-246 addressed multi-agent/release-readiness failures (worktree isolation, history rewrite safety, post-rewrite push collisions, claim enforcement, chaos test source mutation, release freeze transactions), and the resulting first-pass audit script hardcoded operator emails, local home paths, and project-specific values. External research on 2026-05-08 confirmed industry precedent exists for every domain COS was at risk of reinventing (secret detection, history cleanup, hook orchestration, policy-as-code), establishing the stance: "COS is not a replacement for these tools. COS is the agentic control plane that declares when and how those tools are consumed."

## Consequences
Positive: new postmortem classes become manifest entries instead of bespoke scripts; sensitive values stay out of code/docs; mature external tools can be adopted without losing COS governance; primitive coherence improves via declared adapters with owners/callers/recursion boundaries. Negative: the manifest schema must be maintained; generic check engines need good tests to avoid false positives; external tool version drift remains a supply-chain concern requiring ADR-212/ADR-215 audits.

## Status & current state
Accepted and implemented. `manifests/postmortem-regression-audit.yaml`, `scripts/cos-postmortem-regression-audit`, and `docs/05-Methodology/runbooks/postmortem-regression-audit.md` implement the policy correction. Non-hardcoding rules cover operator emails, local home paths, project codenames, private URLs/tokens/org-internal names — using repo-relative paths and env vars/gitignored local manifests instead.
