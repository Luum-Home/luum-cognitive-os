## Decision
Define an explicit boundary: COS owns policy/safety gates, work ownership/liveness/branch-worktree boundaries, release-freeze preconditions, evidence receipts and event-log state, budget/retry/circuit-breaker/idempotency contracts, telemetry/remediation/postmortem regression findings, and cross-harness normalization. External orchestration engines (OpenAI Agents SDK, LangGraph, AutoGen, CrewAI) are adapter candidates only — they may schedule/graph/coordinate agents but cannot bypass COS governance. Introduces `manifests/agent-orchestration-adapters.yaml`, `scripts/agent-orchestration-boundary-audit.py`, and `scripts/agent-orchestration-benchmark.py`. Hard rules: core COS hot-path files must not import optional orchestration frameworks directly; any new lifecycle/handoff/queue/daemon/dispatch/worker primitive must be declared in the manifest; agent launches must pass through ADR-223 lifecycle + ADR-246 release-freeze; handoffs must use ADR-230 envelopes/receipts; provider calls must pass ADR-228's dispatch gate; and adapters must prove via benchmark that they preserve incident-shaped behavior before becoming default.

## Why
Repo-local governance primitives already existed but were scattered across ADR-057/081 (cross-harness projection), ADR-190 (harness action receipts), ADR-223 (worktree-per-write-agent lifecycle), ADR-226 (event-sourced session state), ADR-228 (retry/budget/circuit-breaker/dispatch gates), ADR-230 (handoff envelopes/cycle dedup), ADR-233 (file-IPC), ADR-235 (detached daemon), ADR-246 (release freeze), ADR-248 (control-plane audit loop) — with no single boundary statement tying them together against the mature external ecosystem. The posture mirrors ADR-250 exactly: COS owns governance and control-plane semantics; external frameworks are adapter candidates, not the source of truth for safety, ownership, release freeze, receipts, or budgets.

## Consequences
Positive: prevents COS from silently becoming a bespoke competitor to LangGraph/AutoGen/CrewAI/provider-native agent frameworks; keeps governance semantics stable while still allowing orchestration engines to be evaluated/adopted as adapters; extends the ADR-250 pattern from router retrieval into multi-agent runtime orchestration; adds a concrete audit+benchmark gate before further orchestration substrate is added. Negative: adds another manifest/audit/benchmark surface to maintain; static audits cannot prove all runtime launch paths are perfectly wired (chaos/cross-harness tests remain necessary); optional framework adapters stay future work until they clear license, footprint, benchmark, and governance-boundary review.

## Status & current state
Accepted — Slice A implemented. `implementation_status: implemented`. Active default adapter: `cos_file_ipc_minimal`. Active non-default: `cos_handoff_envelope`, `cos_dispatch_gate`. Opt-in: `cos_detached_daemon`. Candidate-only (not adopted): `openai_agents_sdk`, `langgraph`. Lab-only (heavy optional): `autogen`, `crewai`. Verification commands (boundary audit, benchmark, unit tests, control-plane audit lane) are expected to pass with zero required benchmark failures.
