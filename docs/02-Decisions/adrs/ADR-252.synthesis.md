## Decision
Introduce a manifest-backed Capability Coverage Matrix and Feature Reality Ledger: `manifests/capability-coverage.yaml` (declares every capability's stable id, owner ADR, reality level, public-claim flag, implementation/consumer/test/receipt paths, and known_gaps), generated via `scripts/cos-capability-matrix` into a human-readable `docs/07-Capabilities/capabilities/MATRIX.md` and a machine-readable `docs/06-Daily/reports/capability-coverage-latest.json`. Hard rule: if a capability is not in the matrix, it cannot be treated as a public COS capability claim. Seven reality levels defined: REAL, PARTIAL, ROADMAP, LAB, DORMANT, DEPRECATED, RESOLVED. The read-only audit (`--json`) blocks on: an accepted ADR in the configured coverage range missing from the matrix; a declared path that doesn't exist; `public_claim: true` paired with a non-REAL level; a REAL capability lacking full implementation/consumer/test/receipt evidence; a non-REAL capability lacking `known_gaps`; or a stale generated artifact.

## Why
Existing ADRs each covered a slice of the fragmentation problem (ADR-031 audits aspirational/dormant claims, ADR-147 tracks agent capability coverage, ADR-217 checks adoption truth, ADR-248 runs control-plane audits by lane, ADR-249 distinguishes behavioral proof from overfit tests, ADR-250/251 add adapter-boundary benchmarks) but none joined claim → ADR → implementation → wiring → tests → receipts → audit → reality level into a single generated view. Without that join, a capability could look done (present script) while being unwired, unregistered, or unproven — exactly the class of gap that motivated this ADR.

## Consequences
- Positive: makes capability reality visible in one place instead of requiring ad-hoc memory across ADRs/tests/scripts/docs; converts "I wonder what else has this gap" into a stable, repeatable audit finding; prevents public claims from drifting ahead of implementation evidence; gives future ADRs a predictable registration point.
- Negative: adds another manifest that must be maintained as capabilities are added; the matrix is only as trustworthy as its declared evidence (ADR-249's behavioral-proof-quality audit remains a necessary complement); Slice A does not classify every historical COS feature.

## Status & current state
Accepted, implementation_status: implemented — Slice A. Covers the ADR-230+ maintainer/control-plane line specifically, because that is where recent gaps (ADR-250/251) appeared; the manifest also declares an ADR coverage range so accepted ADRs in it cannot silently disappear from the matrix. Historical COS feature classification outside that range is intentionally deferred, tracked via `partial_remaining`. Verification: `python3 scripts/cos-capability-matrix --json`, `--check-generated --json`, `tests/unit/test_capability_matrix.py`, and `scripts/cos-control-plane-audit --lane hook-fast --json`.
