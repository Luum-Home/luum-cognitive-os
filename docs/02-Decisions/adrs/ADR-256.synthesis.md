## Decision
Introduce a Primitive Contract Registry (`manifests/primitive-contracts.yaml`) and a Runtime Evidence Ledger. A primitive is not fully governed until it has: a canonical contract row, required capability declaration, projection fidelity by harness/runtime shape, consumer-fleet impact classification, service/headless impact classification, runtime evidence mapping (block/warn/advise/suggest/observe/allow), and trace compatibility via `session_id`/`tool_use_id`. New surfaces include `.cognitive-os/metrics/primitive-interventions.jsonl` (action stream) and `.cognitive-os/metrics/codebase-itinerary.jsonl` (content-free inspection record).

## Why
Cognitive OS had lifecycle metadata, harness projection manifests, dogfood scoring, primitive coverage, hook timing, action receipts, consumer-fleet audit, service readiness gates, and run traces — but no root contract joining them. OpenSage ADK served as an external pressure test: it combines dynamic agent topology, dynamic tool/skill synthesis, sandboxed execution, and graph/hierarchical memory, so COS may extract patterns from it only through a manifest, and must not adopt a self-programming runtime until this ADR can prove primitive authorization and runtime evidence for each dynamic action.

## Consequences
- Primitive portability becomes contract-driven instead of inferred from scattered metadata.
- Cross-IDE claims can distinguish enforced, wrapper-enforced, plugin-capable, structural-advisory, CI-enforced, documented-only, and unsupported projections.
- Runtime evidence becomes comparable across harnesses once intervention/itinerary ledgers exist.
- First implementation slices intentionally duplicate some lifecycle/readiness data while the registry proves its join value; projection/trace tooling must eventually consume the registry or it becomes another passive manifest.

## Status & current state
Accepted — implemented through Phases 1-6. All primitive-lifecycle rows are registry-backed. Phases: (0) docs/contract freeze, (1) minimal registry via ADR-257, (2) intervention ledger for destructive git/rm, (3) codebase itinerary capture, (4) projection/impact reports, (5) trace joiner + observable self-use, (6) consumer UX (`cos adapters`, `cos observe primitives`). OpenCode is split by proof level: signed runtime slice covers the first 20 primitives via `packages/opencode-adapter/plugins/cos-primitive-guard.js`; remaining contracts stay `structural-advisory` until signed smoke promotes them.
