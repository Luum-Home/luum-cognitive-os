## Decision
Adopt `.ai/` as a **generated portable overlay/export surface**, not as the internal canonical source of truth. Canonical sources remain `manifests/primitive-contracts.yaml`, `manifests/primitive-lifecycle.yaml`, `hooks/`, `skills/`, `rules/`, `scripts/`. The overlay (`.ai/context.json`, `primitives/`, `profiles/`, `adapters/`, `logs/schema/`, `state/`) is generated from those sources via `scripts/portable_ai_overlay.py`; adapters translate contract-declared primitives into host-specific surfaces and must declare fidelity honestly rather than inventing behavior. Implementation proceeds in 5 phases; Phase 5 (canonical migration) is explicitly deferred pending a future ADR.

## Why
The due-diligence review found AGENTS.md, SKILL.md, and MCP are more mature and broadly adopted than VERSA itself, so replacing them with `.ai` would be a step backward. But treating `.ai` as pure documentation was also rejected — it needs to be generated, linted, tested, and joined to adapter fidelity to be useful as a consumer packaging pattern. The core invariant driving the decision: "COS canonical internal registry != consumer `.ai` overlay" — the overlay is allowed to mirror and package primitives but not to invent behavior or replace the manifests as source of truth.

## Consequences
- Positive: aligns with an emerging portable-overlay spec without breaking current runtime hooks/tests; keeps AGENTS.md/SKILL.md/MCP/host adapters as first-class surfaces; gives consumer projects packaging clarity; preserves ADR-256 runtime evidence work as another projection layer.
- Negative: adds another generated surface requiring drift tests; delays mass-porting all primitives until the overlay generator is proven; duplicates metadata until a later canonical-migration decision is made.

## Status & current state
Accepted, implementation_status: partial. Phases 0-4 implemented: overlay generator, adapter projection proof (per-host README + adapter.json under declared fidelity), enriched portable-contract views for all lifecycle primitives, and consumer-fleet impact tooling (`scripts/portable_ai_consumer_impact.py`, `scripts/portable_ai_real_consumer_smoke.py`) that never mutates downstream repos. A 2026-05-12 clarification distinguishes the maintainer's machine-readable overlay from a consumer repo's human-readable `.ai/` package — same invariant, different shape. Phase 5 (canonical migration) remains explicitly deferred; `.ai/` stays generated/non-canonical until a future ADR promotes it.
