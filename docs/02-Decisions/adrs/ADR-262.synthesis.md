## Decision
Time-boxed 3-4 day Spike (not an Accepted ADR) to design and prototype an LLM-driven evolve loop: `lib/evolve_skill_review.py` (LLM extraction job via `lib.dispatch`, Qwen primary/Claude fallback per ADR-049, filters candidates below `confidence < 0.72`), `lib/evolve_task_queue.py` (SQLite-backed proposal queue at `.cognitive-os/state/evolve-proposals.db` with `enqueue/list_pending/approve/reject/mark_promoted` ops, hard cap of 50 pending), and `scripts/cos-evolve-tick.py` (CLI: `run`, `list`, `approve`, `reject`). Hook integration adds a turn-counter gate to `hooks/auto-skill-generator.sh` (fires every N=3 turns, background, non-blocking) with kill switches (`evolve.enabled: false`, `COS_DISABLE_EVOLVE_TICK=1`). The existing regex-based `auto-skill-generator.sh` continues running unchanged in parallel — no replacement during the spike. Explicitly rejects auto-coupling to `/sdd-new` and unconditional human-in-loop is non-negotiable: no candidate is promoted without explicit operator approval.

## Why
luum's promotion-stage tooling (`lib/skill_archive.py`, `lib/skill_efficacy.py`, comparative baseline-vs-candidate gate) is already more rigorous than most OSS alternatives, but the *detection* stage is weak: the regex shell hook (`grep -cEi "(created|wrote|generated|...)"`) cannot detect novel orchestration patterns, generates redundant drafts on every agent turn, and gives no confidence signal, so all drafts land in `auto-generated/` indistinguishably and the human review gate (`self-improvement-protocol.md` §6) is effectively unreachable without manual discovery. Three uncertainties justified a Spike rather than an Accepted ADR: unknown proposal volume over a 7-day run (5 vs 500), uncharacterized LLM extraction cost, and an unvalidated 0.72 confidence threshold calibration.

## Consequences
Validates evolve-loop assumptions in a bounded window with a clear exit decision (proceed/shelve/pivot). Key risks: LLM hallucination in drafts (mitigated by human-in-loop + fingerprint dedup + reject_reason feedback), queue saturation (hard cap of 50 pending), cost overrun (kill switch + $0.05/day monitoring), and duplicate proposals from both regex and LLM hooks firing (mitigated by fingerprint dedup — treated as a feature for comparison, not a bug).

## Status & current state
Status is **Spike**, explicitly not Accepted. `implementation_status: not-applicable`. Converts to a follow-up Accepted ADR only if all 5 exit criteria are met after a 7-day observation window: (1) queue accumulates ≥10 proposals with confidence ≥0.72, (2) human approval rate ≥30%, (3) LLM cost ≤$0.05/day, (4) zero high-confidence (≥0.85) false positives that regress skill quality, (5) LLM-unique proposals ≥50% of total. If any criterion fails, the spike closes without promotion and findings are archived to engram under `topic_key: adr/262`.
