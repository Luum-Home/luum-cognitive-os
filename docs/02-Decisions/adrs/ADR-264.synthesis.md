## Decision
New dependency-free module `lib/tool_result_envelope.py` exposing `wrap_if_large(raw_result, tool_name, target_hint, threshold=28*1024, preview_size=7*1024, persist_full=True, spillover_dir=None) -> str`: passes results through unchanged under 28KB; above threshold, replaces the result with a structured Markdown envelope (`[TOOL RESULT ENVELOPE]` marker, tool name, target hint, full size, a 7KB preview, and a `full_pointer` to a spillover file) rather than a bare truncation. Full payloads persist to `.cognitive-os/sessions/<session-id>/envelopes/<sha256-of-content>.txt`, cleaned up at session end. Integrated into both `lib/agent_runner.py` (primary) and `lib/dispatch_helper.py` (secondary, with an idempotency guard against double-wrapping detected via the marker string). Designed to compose with ADR-263's tool-replay ledger: when the ledger marks a result `REFERENCE_ONLY`, the envelope collapses to pointer-only with an empty preview instead of a full preview.

## Why
Adopts a pattern identified in a private clean-room research dossier (§Capability HTTP result envelope) but deliberately diverges from the reference implementation to satisfy clean-room constraints: Markdown format instead of JSON (the model parses Markdown more naturally in Claude Code context), 28KB threshold instead of the reference's literal 32KB (independently re-derived from luum's 200K-token context window math — 28KB ≈ 7,000 tokens ≈ 3.5% of context, and sessions with 15-20 active tool calls could otherwise spend ~14% of context on 3-4 large results alone), 7KB preview instead of 8KB, and renamed identifiers throughout (`wrap_if_large` vs `formatCapabilityToolResultForModel`, `EnvelopePreview` vs `FormattedCapabilityToolResult`).

## Consequences
Positive: the model retains awareness of what was truncated and how much (via `full_size`), enabling it to decide whether to request the full payload; reviewers get explicit tool_name/target_hint/full_pointer metadata in logs instead of an opaque cut blob; large results no longer disproportionately consume context in long sessions; fully reversible via `threshold=math.inf` (zero blast radius rollback); complements rather than replaces `smart_truncator.py` (which keeps its head/tail strategy as a fallback). Negative: ~200 bytes of markup overhead per enveloped result (negligible against savings); the spillover directory can grow several MB per session without a cap (mitigated by session-end cleanup, with a future 50MB cap flagged as an open question); double-wrap risk across the two integration points, mitigated by marker-string idempotency detection.

## Status & current state
Accepted, implemented. `implementation_status: implemented` per frontmatter, verification level "strong". Acceptance criteria include unit test coverage in `tests/unit/test_tool_result_envelope.py` for passthrough, envelope triggering, persist_full on/off, SHA-256 spillover naming, preview truncation exactness, and idempotency; integration tests confirm `agent_runner.py` and `dispatch_helper.py` both apply the wrap without double-wrapping. Open/unresolved: optimal threshold calibration (28KB vs 24KB vs 32KB) needs 2 weeks of production p50/p95 measurement and should become configurable via `cognitive-os.yaml`; whether 7KB preview is sufficient for non-JSON results (large diffs, build logs) is unresolved; exposing an `expand_envelope(pointer)` model tool and a spillover-dir size cap are both explicitly parked for a follow-up ADR.
