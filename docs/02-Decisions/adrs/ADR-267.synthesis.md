## Decision
A layered defense: six new pre-commit hooks, two new governance manifests/scripts, and this ADR plus a deferred future "legal review gate" ADR — while explicitly acknowledging hooks reduce probability of error but do not establish legal compliance. The six hooks: (1) `dependency-license-classifier.sh` blocks new dependencies whose SPDX is on the BLOCKER list; (2) `external-cache-content-leak.sh` generalizes the old hardcoded clean-room gate to scan staged content against the whole `.cognitive-os/external-source-cache/` tree; (3) `adoption-freeze-gate.sh` reads `manifests/external-tool-adoption-freeze.yaml` as a mechanical kill-switch — when `frozen: true`, blocks any commit touching research annexes or the adoption manifest, intended for pre-commercial/pre-SaaS phase; (4) `spdx-header-required.sh` requires new source files to declare an SPDX identifier; (5) `attribution-completeness-validator.sh` requires per-block source-path attribution on research annex code fences; (6) `research-to-runtime-firewall.sh` blocks runtime code from importing or copying content out of the external-source cache. Also adds `scripts/cos-adoption-debt-audit`, which counts tools with an Annex F but no `reviewed-by-legal: yes` marker as "adoption debt."

## Why
Two compounding gaps needed closing for two future scenarios the operator wants ready: Scenario A (luum goes OSS public — needs SBOM, SPDX headers, NOTICE/THIRD-PARTY-LICENSES discipline) and Scenario B (luum goes commercial/SaaS — the license-policy BLOCKER table must become commit-time enforcement, plus a mechanical "STOP new adoptions until legal review" switch). Individually, each external-tool adoption is defensible under fair-use/clean-room doctrine today via `/repo-scout` + `/deep-tool-research` producing an Annex F, but there was no mechanical limit on *accumulation* — no signal that "N tools are now pending legal validation, further adoption raises aggregate risk."

## Consequences
Positive: mechanical defense against AGPL/SSPL/BSL/ELv2 strings reaching commits; a kill-switch for new adoptions that doesn't depend on orchestrator discipline; adoption debt becomes visible and tracked rather than hidden; the research-to-runtime leak path is explicitly firewalled; both target scenarios become defendible at commit time, not only at scout time. Negative: six new hooks add an estimated 30-80ms cumulative to each commit; the content-leak hook (#2) risks false positives on common-token matches requiring threshold tuning (initial guess: ≥40 chars); the attribution validator (#5) only covers the specific `docs/03-PoCs/research/*-annex-*` glob, so a differently-structured future doc type would silently reopen the gap; the dependency classifier (#1) depends on external tools like `pip-licenses` being installed locally, with the block-vs-skip tradeoff explicitly deferred to implementation; the freeze mechanism, if flipped on without operator awareness, would silently fail commits (mitigated by a proposed startup banner).

## Status & current state
Accepted; implementation_status: partial. Phase 1 (kill-switch + dependency scanner + runtime firewall) and Phase 2 (content-leak + SPDX + attribution gates) both landed 2026-05-11 — all six hooks confirmed "landed" with bypass env vars documented (e.g. `COS_ALLOW_LICENSE_CLASSIFIER_BYPASS=1`). Layer 2 (governance manifests/adoption-debt audit reporting cadence) and Layer 3 (the separate future legal-review-gate ADR defining `reviewed-by-legal: yes|no|pending`) remain on the roadmap as Phase 3/Phase 4 follow-ups — explicitly not yet built. A sibling ADR-268 documents a same-day defensive history sanitization that cross-references this ADR as the forward enforcement replacement for ad-hoc attribution discipline.
