## Decision
Two `git filter-repo` passes plus an Engram SQL maintenance pass, scoped strictly to surface text and never touching ADRs, recovery bundles, or audit artifacts: Pass 1 rewrites every commit-message occurrence of the original tool name (including "holaOS") to the neutral phrase "external pattern" across the working branch family's full history; Pass 2 renames the handful of `lib/*.py` files whose basenames embedded the tool name and rewrites their import-time strings to neutral identifiers, updating `lib/`-to-`packages/` symlinks atomically; the Engram pass deletes/updates observation rows referencing the verbatim name while keeping `topic_key` stable for searchability, preceded by a full `~/.engram/engram.db.backup-2026-05-11`. ADRs 259-264 (the canonical clean-room paper trail), the recovery bundle, the audit report itself, and Annex-F attribution documents are explicitly preserved untouched.

## Why
This is framed explicitly as NOT concealment, for five stated reasons: the full paper trail survives verbatim in ADRs 259-264; the pre-sanitization commit graph is recoverable bit-for-bit via `.cognitive-os/recovery/pre-history-sanitization-2026-05-11.bundle`; the pre-sanitization Engram observation set is preserved in the timestamped backup; this ADR itself documents the action as part of the public record from 2026-05-11 onward; and ADR-267's Layer 1 hooks (`attribution-completeness-validator.sh`, `external-cache-content-leak.sh`, `spdx-header-required.sh`, `research-to-runtime-firewall.sh`) now enforce going forward what had previously been only an orchestrator-discipline expectation, replacing ad hoc discipline with forward enforcement.

## Consequences
Positive: commit logs and Engram no longer carry casual external-tool attribution, reducing discovery surface for future audits, partners, or public release; one canonical paper trail (ADRs 259-264 + Annex-F + this ADR) replaces a duplicated, less-structured one (commit subjects + Engram observations); ADR-267 hooks now enforce on every future commit. Negative: the commit log is no longer self-explanatory for clean-room derivation — investigators must follow the ADR chain rather than `git log --grep`, and that chain must stay readable if ADRs are ever moved/renumbered; Engram search by old verbatim terms returns no hits, so any downstream automation indexing those terms needs the documented topic_key remapping. Neutral: this is a one-time operational action with no runtime-behavior change; the recovery bundle and Engram backup are untracked artifacts requiring preservation across host migrations.

## Status & current state
Accepted and implemented 2026-05-11, reinforced by ADR-267 forward enforcement. Reversal procedure is fully documented (unbundle recovery bundle to a side worktree, reset branches to recorded pre-sanitization tips, restore the Engram backup, and drop or supersede this ADR) and is stated to preserve the ADR paper trail because ADRs 259-264 were never touched by the rewrite.
