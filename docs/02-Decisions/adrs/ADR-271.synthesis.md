## Decision
Build `hooks/clean-room-ast-similarity-gate.sh` plus `scripts/cos_clean_room_ast_similarity.py` as ADR-267 Hook #8 (Tier 2 of the clean-room detection matrix). It parses staged Python files into ASTs, normalizes identifiers to positional placeholders, strips docstrings/comments/type annotations, hashes each top-level function/class (SHA-256 of `ast.dump`), and compares against pre-computed hashes of every `.py` file in `.cognitive-os/external-source-cache/`. Supports `--baseline`, `--quick`, `--format`, `--allowlist`, `--ci` modes and two bypass env vars (`COS_ALLOW_AST_SIMILARITY=1`, `COS_ALLOW_CLEAN_ROOM_BYPASS=1`). Python-only in v1; other languages deferred to Tier 5 (process/legal).

## Why
The clean-room defense had a documented tier matrix (`rules/clean-room-detection-limits.md`) with a real gap at Tier 2: the first two undetectable copy classes (symbol-renamed clones, structural ports) are mechanically detectable but nothing implemented the detector. ADR-029b already shipped Jaccard-based tokenization for the orthogonal anti-reinvention use case (same shape of problem, different corpus), and this ADR reuses that infrastructure rather than reinventing it.

## Consequences
Positive: closes the most common defendibility gap (symbol-renamed copies); reuses ADR-029b Jaccard tokenization/baseline schema; every T2 hit becomes an accepted-baseline entry or an audited rejected commit. Negative: false positives expected on common Python idioms (singletons, dataclass scaffolds, argparse boilerplate) until the baseline soaks; performance ceiling of ~20s cold-index build for 4k cached files (mitigated by JSON caching to keep warm runs <1s); Python-only in v1 (TypeScript/Rust/Go ports undetected, remains Tier 5); AST instability risk across Python 3.11 vs 3.12 `ast.dump` output requires pinned canonicalization logic.

## Status & current state
Status: proposed (2026-05-11). Implementation status: planned — no implementation files listed yet. Three-phase plan defined: Phase 1 (~1 person-week) builds the normalization/similarity engine and baseline seed; Phase 2 (~0.5 PW) adds the pre-commit hook and a 10-case test suite; Phase 3 (~1 week wall-clock) runs a warn-only soak to measure false-positive rate before promoting to an active gate. Open questions remain on TypeScript/Rust support, hash granularity (per-function vs per-file), baseline review cadence, and error-message consolidation with the Tier 1 hook.
