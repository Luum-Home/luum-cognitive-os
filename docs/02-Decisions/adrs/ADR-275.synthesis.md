## Decision
Ship two Slice-A primitives with a shared schema and trust contract: (1) `scripts/cos-session-start-projector`, which reads pending-truth, operational-guide-audit, control-plane remediation, staged-deployment directories, and git state in a single 60s-cached pass and emits a bounded top-N summary plus a machine-readable `session-start-projection/v1` JSON with ranked `suggested_next_actions`; (2) `scripts/cos-pending-truth-close`, which accepts `--id` and `--proof`, re-runs the verifier on that single item as a gate, and only on `verified-done` applies the canonical closure edit for the item's source type (plan checkbox -> `[x] (verified: ...)`, ADR frontmatter status flip, audit-finding status close, or follow-up/user-request closure fields), appending every closure to an audited `closure-trail.jsonl`.

## Why
Both gaps share one root cause named explicitly in the ADR: "COS produces capabilities faster than projection-and-closure discipline keeps up." Aggregators and audits (recolectores) exist, but projectors (surfacing data at the point of use) and closers (atomic closure with proof) lag behind. Concretely: `rules/startup-protocol.md` displayed only 4 lines with no queue visibility, so an agent or operator joining cold had to manually re-run the aggregator to discover 279 pending items; and because writing "done" was always cheap and verification always optional, a quarter of historical done-claims were unverified.

## Consequences
Symmetry is restored — read side (aggregator) and write side (closer) now share trust contracts and schemas, closing the asymmetry that produced the 25% mismarked-done rate by design. The session-start view becomes IDE-agnostic so future harnesses only need to register a hook and invoke the projector. Closure latency increases by roughly 1s because the close primitive runs the verifier before writing (acceptable; manual closure still works but yields a LOW trust signal). The 60s projector cache means rapid commits may not show immediately (`COS_PROJECTOR_NOCACHE=1` forces refresh).

## Status & current state
Accepted, Slice A implemented (projector, close primitive, and their portability tests all exist and pass). Slice B — hook wiring across the three harnesses (Claude Code `SessionStart`, Codex, cos-runner) — is designed and staged under `docs/05-Methodology/runbooks/adr-275-session-start-hook-staging/` but not deployed; `settings.json` is protected by `protected-config-write-guard`, so the operator must apply the patch after review. No backfill was needed for either side: the projector reads existing reports and the close primitive is opt-in, with manual closures still valid going forward.
