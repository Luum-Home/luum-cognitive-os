Root cause: 174 subprocess.run() calls in those two test dirs, 169 of them (97%) omitting timeout=; two specific tests (`test_repository_family_ledgers_cover_hooks_skills_and_rules` and `test_cos_primitive_surface_coverage_alias_json_exit_code_contract`) hung indefinitely because pytest's thread-based timeout can kill the test thread but not the underlying OS subprocess, which keeps file descriptors open and blocks suite teardown. Widening the scan to all of scripts/hooks/lib/tests/packages found 1824 total subprocess.run calls, 984 (54%) missing timeout=, across 97 unique files.

## Decision
Three-layer enforcement mirroring the ADR-274 audit pattern. (1) Convention: every `subprocess.run(...)` in scripts/, hooks/, lib/, tests/, or packages/ MUST include explicit `timeout=` or be listed in `manifests/subprocess-timeout-allowlist.yaml` with rationale (exemptions: interactive stdout streaming, long-running watchers/servers/REPLs, commands with their own bounded deadline) — bias is "add timeout=, justify omission." (2) Audit: `scripts/cos-subprocess-timeout-audit.py` scans the repo and emits one `warn` finding per untimed non-allowlisted call with stable_id `adr-278/subprocess-timeout/<rel>:<line>`, wired into `manifests/control-plane-audits.yaml` hourly + pre-public lanes. (3) Test-tier safety net: `tests/conftest.py` monkey-patches `subprocess.run` at module load to inject `timeout=45` when the caller omits it (configurable via `COS_TEST_SUBPROCESS_DEFAULT_TIMEOUT`, explicit per-call timeouts still override) — this unblocks the suite immediately without backfilling all 169 test calls.

## Why
This is the same anti-pattern class that motivated ADR-273 (silent state proliferation): a convention that "everyone should remember" but nothing actually enforces, and it had just caused a real hang that blocked verification work.

## Consequences
Hangs become bounded — a buggy subprocess raises `TimeoutExpired` after the configured timeout instead of blocking the caller indefinitely; the convention becomes reviewable (grep + allowlist, intent declared not implicit); the 984-call backfill debt is quantified and visible rather than hidden; marginal cost of an explicit timeout is one keyword argument, backfill cost is bounded and phased. Rejected alternatives: monkey-patching subprocess.run in production too (would hide bugs behind an implicit default instead of surfacing the omission), a single global default timeout for all callers (different operations legitimately need different deadlines), relying only on the test-tier conftest (production scripts/hooks would still hang), a ruff/flake8 lint rule (no built-in keyword-presence rule exists; custom AST check is what the audit script already does).

## Status & current state
Accepted — audit + allowlist + test-default shipped 2026-05-12; implementation_status: partial. Explicitly deferred to Phase 2: a pre-commit gate blocking new untimed `subprocess.run` calls in staged files, and backfill of the 984-item backlog (prioritized P0 = `scripts/cos-*` operator CLI, P1 = `hooks/`, P2 = `lib/`+`tests/`). Phase 3 (future): extend the audit to Go (`exec.Command`) and shell (`bash -c` without a timeout flag) for language-agnostic coverage. Verification today: `python3 scripts/cos-subprocess-timeout-audit.py --strict` currently exits 2 (984 untimed calls) — expected to reach exit 0 only after backfill.
