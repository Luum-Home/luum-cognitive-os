## Decision
Add a permanent audit (`scripts/cos-adr-implementation-audit.py`) that cross-validates every ADR declaring `implementation_status: implemented` against on-disk reality: each path in its `implementation_files:` must either exist on disk or be explicitly listed in `manifests/adr-implementation-runtime-allowlist.yaml` (with pattern/rationale/owner) as a legitimate runtime/gitignored artifact. Findings emit in the ADR-248 control-plane shape (severity `warn`, code `adr-implementation-file-missing`, stable_id `adr-281/missing/<ADR-NNN>/<rel-path>`). The audit is registered in `manifests/control-plane-audits.yaml` under `adr-implementation-coverage` in the hourly and pre-public lanes. Resolution options for any finding: create the missing file (real implementation), downgrade `implementation_status` to `partial` with a documented `partial_remaining`, or add the path to the allowlist with rationale.

## Why
This is explicitly the fourth iteration of the same root anti-pattern (state proliferates faster than verification discipline) previously closed by ADR-273 (operational model living only in chat), ADR-274 (single-instance §OG fix not generalizing), and ADR-275 (audit visible but not projected/closure asymmetric). None of the 8 existing audit mechanisms (section validator, operational-guide audit, pending-truth aggregator, closure-trust-signal, documentation-truth audit, primitive-authority audit, adr-partial-audit, doc-cross-reference audit) checked implementation_files against disk — each targets a structurally different concern (section presence, task checkboxes, closure trails, phrase claims, write-effects boundaries, partial-lifecycle metadata, primitive-token cross-reference), leaving "claim says implemented, disk says otherwise" completely uncovered.

## Consequences
Positive: overclaim is no longer invisible — the system now flags `implemented` ADRs with partial-or-aspirational reality; the allowlist is the declared safety valve for legitimate runtime/gitignored files; backfill was small (0 real overclaims found at creation, after fixing the seed allowlist) so it closed in one sweep; future overclaims cannot regress silently since the hourly control-plane lane catches new ones within an hour. No explicit negative consequences beyond the audit-maintenance surface itself.

## Status & current state
Accepted, `implementation_status: implemented` — Phase 1 shipped 2026-05-12 (audit script, allowlist, tests, control-plane wiring), confirmed by `classification_basis` in frontmatter. Follow-ups explicitly deferred: Phase 2 (extend to `partial` ADRs whose `partial_remaining` lists files that actually DO exist — the under-claim direction) and Phase 3 (cross-validate `implementation_files` against `manifests/primitive-lifecycle.yaml` so registered primitives must appear in at least one ADR's implementation_files).
