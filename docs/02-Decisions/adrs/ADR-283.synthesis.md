## Decision
Add `scripts/cos-script-exposure-audit` (with `--json` and `--fail-p0` modes), reading `docs/06-Daily/reports/primitive-readiness-ledger-scripts-latest.json` by default, classifying every script into P0 (agentic-primitive, no skill consumer — must add a consumer, document an equivalent route, or demote), P1 (maintainer-tool with zero consumers — archive/register/wire), P2 (maintainer-tool with docs/tests/scripts consumers but no skill — classify internal or promote), P3 (lab/migration-only/driver-specific without a skill consumer — allowed exception). P0 is further split into `P0-unrouted`, `P0-route-undocumented`, and `P0-promotion-candidate` exposure classes so triage doesn't confuse "missing skill" with "genuinely unreachable." Command-router exposure is deliberately conservative — only central dispatchers like `scripts/cos` count, not sibling `scripts/cos-*` scripts. Manual dispositions in `manifests/script-exposure-dispositions.yaml` (`documented_route`, `internal_backend`, `operator_workflow`, `documented_maintainer_tool`, `test_fixture`) resolve P0/P2 findings without forcing every maintainer helper into a new skill.

## Why
This is the same scalability problem ADR-282 solved for product answers, applied to script discoverability: agents were repeatedly rediscovering a large `scripts/` surface, spending tokens inspecting docs and ledgers, and still sometimes missing the right operational primitive. There was no dedicated P0/P1/P2/P3 audit turning the existing ledger facts into an actionable exposure backlog.

## Consequences
Positive: agents can run one cheap audit instead of rereading the whole scripts surface; agentic primitives unreachable through skills become visible as P0; zero-consumer maintainer tools become visible as P1 instead of silently accumulating; lab/migration-only/driver-specific scripts remain legitimate exceptions rather than creating "everything must be a skill" pressure; `--fail-p0` gives a future CI ratchet without blocking the first inventory pass. Negative/trade-offs: the audit's quality depends on the freshness of the primitive-readiness scripts ledger; some P0 rows may already have hook/router exposure but still need explicit documentation or demotion to remove ambiguity; command-router exposure classification is currently heuristic pending richer router manifests.

## Status & current state
Accepted and implemented (2026-05-12). Verification: `python3 -m py_compile lib/script_exposure_audit.py scripts/cos-script-exposure-audit`, `tests/unit/test_script_exposure_audit.py`, `tests/behavior/test_script_exposure_audit_cli.py`, plus a live `scripts/cos-script-exposure-audit --json` run. Rejected alternatives: manual `scripts/` inspection (token-heavy, inconsistent), requiring every script to have a skill (too blunt — legitimate lab/migration/private-maintainer exceptions exist), relying only on primitive-readiness ledgers (facts without P0-P3 backlog semantics), immediately deleting zero-consumer scripts (unsafe during reconstruction — visibility must precede deletion).
