## Decision
Adopt `browser-use>=0.12.6` (MIT, 93.7k stars) as an optional runtime dependency under a new `web-automation` extra in `pyproject.toml` (not in default install). Introduce `lib/browser_use_adapter.py` (the only module allowed to import `browser_use`, wraps `browser_use.Agent`, returns a typed `WebAutomationResult`, emits events to `AgentPublisher`) and `lib/web_automation_router.py` (intent classifier + kill-switch check, the integration seam `dispatch.py` will call in a future ADR). Add kill switch `COS_DISABLE_WEB_AUTOMATION=1`. Expose a `/browser-task` skill for direct invocation. Wire cost tracking through `cos_lib.dispatch_cost_predictor` so browser-use steps debit the same session budget gate as any other LLM dispatch.

## Why
`dispatch.py` enforces a strict four-phase ordering contract (ADR-236→232→228→226) validated by an architecture test; shoehorning a new modality directly into `dispatch()` without a phase amendment would be a contract violation, so this ADR deliberately adopts a sidecar integration instead. Among alternatives, Playwright/Selenium/CDP-rolled-own were rejected as low-level reinvention with no LLM loop or accessibility-tree extraction; browser-use was chosen for its MIT license, LLM-native step loop, and provider-agnostic chat-model support matching the existing Python >=3.11 floor.

## Consequences
- Positive: first-class web automation without reinventing a browser loop; MIT keeps the project inside the ADR-267 license allow-list; optional dependency means zero install cost for operators who don't need it; cost is honest — token usage flows through the same predictor as any LLM dispatch; kill switch matches existing `COS_DISABLE_*`/`COS_FORCE_*` vocabulary.
- Negative: inherits a transitive dependency surface (anthropic, openai, google-genai, browser-use-sdk), mitigated by making it opt-in via the extra; `browser_use.Agent` is still a moving target at v0.12.x, pinned `>=0.12.6,<0.13` with the adapter as the single import site; headful browser runs are expensive (mitigated: `headless=True` default, `max_steps=50` cap); a hostile page could attempt sandbox escape — until the future sandboxed dispatch integration lands, `/browser-task` requires `COS_BROWSER_USE_TRUSTED_ONLY=1` for any hostile-URL workflow.

## Status & current state
Accepted, implementation_status: implemented (as Slice A). Shipped: the adapter, router, skill, pyproject extra, and both unit/integration test suites (no real browser launched in CI — `browser_use.Agent.run` is mocked). Explicitly deferred as follow-up: direct `lib/dispatch.py` integration (proposed as a future ADR-289 reserving a "modality routing" phase and updating the ordering test) — until then `/browser-task` and direct adapter calls are the only supported entry points.
