## Decision
Adopt a three-layer knowledge architecture as the canonical model: Layer 1 (raw sources) — immutable original inputs, SHA-256 identified, canonical location proposed at `docs/08-References/raw/<type>/<source-id>.<ext>` (not yet created); Layer 2 (compiled vault) — mutable curated markdown at `docs/{00-MOCs...99-Archive}`, the human-browsing surface; Layer 3 (operational engram) — append-mostly, lifecycle-aware SQLite claims at `~/.engram/engram.db` plus portable bundles, the machine-queried layer agents use during a task. Six named unidirectional pipelines move information between layers (`ingest` L1→L2 planned, `crystallize` L1→L3 active, `export` L3→L2 active, `reinforce` L3→L3 active, `bundle` L3↔L3 active, `retrieve` L2→L3 future), plus `mem_save` as the primary (non-pipeline) write path into Layer 3.

## Why
Each layer already worked in isolation — the vault migration and Engram v3 (ADR-287) both landed cleanly — but the fragmentation risk was conceptual, not technical: without a named model, contributors couldn't tell where a fact belonged, raw inputs referenced as evidence (`evidence_sources` in engram, vault footnotes) had no canonical home or integrity guarantee, and existing pipelines (`engram_crystallizer`, `engram_obsidian_exporter`) worked but weren't described as a coherent system. Future automation (a planned `/wiki-ingest` skill) had no architectural slot to plug into without this naming.

## Consequences
Positive: gives future surface decisions (raw-sources location, ingest skill, retrieve pipeline, schema invariants) one shared model to reference instead of re-deriving it each time; operators can answer "where does this fact live?" with one word (raw/vault/engram) and follow a named pipeline from there; gives ADR-287's evidence-grounded claims a documented end-to-end story back to something concrete. Negative/accepted: adds vocabulary contributors must learn (L1/L2/L3, six pipeline names); explicitly formalizes a gap that already existed — there is still no canonical raw-sources directory — which the ADR treats as a feature (visibility) not a bug, but the gap itself remains until follow-up work lands. Risks: layers can drift if pipelines run out of band (e.g. engram citing a renamed vault page); contributors might misuse layers (long prose into engram, ephemeral notes into the vault).

## Status & current state
Accepted, `implementation_status: partial` — Layer 2 (vault) and Layer 3 (engram) are implemented; Layer 1 (raw sources) has no canonical on-disk location or ingest pipeline, and the vault→engram `retrieve` pipeline is not implemented. Three known gaps are explicitly tracked (not resolved) in this ADR against capability `knowledge-architecture-3-layer` in `manifests/capability-coverage.yaml`: the raw-sources directory doesn't exist yet, the `ingest` pipeline (planned `/wiki-ingest` skill) is absent, and the `retrieve` pipeline (vault→engram indexing) is undecided between periodic-indexer and on-demand-resolver, deferred to a future ADR.
