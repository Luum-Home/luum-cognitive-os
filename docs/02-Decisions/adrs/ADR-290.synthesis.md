## Decision
This is a tombstone ADR: superseded and split into four standalone successor ADRs — ADR-292 (Pattern 1 lazy imports + Pattern 3 MCP thread bridge), ADR-293 (Pattern 2 typed hook events, with an inline staged migration plan A through D for the 237 hooks), ADR-294 (Pattern 4 memory quality scoring, now carrying an explicit `extends: [ADR-287]` backref), and ADR-295 (Pattern 5 reflection loop, with wiring explicitly scoped out and reserved for a future ADR-296). Per ADR-281, the tombstone records the split honestly rather than retroactively editing history, and preserves the original §Context as the historical record of why the five patterns were first observed together.

## Why
The original five patterns were genuinely independent: (1) startup latency from eager imports of heavy deps (`yaml`, `rich`, `litellm`, `openai`) paid even by hook bodies that never need them, with no shared thread-safe deferred-import primitive; (2) 237 hook scripts parsing untyped JSON dicts with manual key-fishing and no schema, so a typo like `tool_inpiut` silently returns `None`; (3) synchronous callers (hooks, CLI scripts) needing to invoke async MCP coroutines without unsafe loop reuse or wasteful fresh-loop-per-call; (4) Engram claims (ADR-287) having no machine-quality signal so all claims were equally retrievable regardless of completeness/relevance/clarity/accuracy; (5) no reflection primitive existing at all in the codebase for iterative critique of a draft response. Bundling them under one ADR number made the ADR-287 schema amendment invisible to readers tracing that ADR's lineage, and left two deferred-work items without reserved follow-up numbers.

## Consequences
The five original implementation modules (`lib/lazy_imports.py`, `lib/hook_event_types.py`, `lib/mcp_thread_bridge.py`, `lib/engram_wave3_schema.py`, `lib/agent_reflection.py`) still exist on disk unchanged; they are simply now owned by the successor ADRs rather than this one. Splitting cost nothing in code — only in bookkeeping — since each pattern was already a leaf module with no cross-imports between the five and each ships with its own focused unit test file.

## Status & current state
Superseded by ADR-292, ADR-293, ADR-294, ADR-295 as of 2026-05-13; `implementation_status: resolved`. All five underlying patterns were actually implemented and tested at the time of the original ADR (verification commands cover lazy-import thread-safety, hook-event dataclass parsing, MCP bridge exception/timeout propagation, quality-score determinism, and reflection min/max bounds) — the supersession is a documentation/traceability correction, not a rollback of functionality.
