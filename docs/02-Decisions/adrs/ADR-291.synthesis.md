## Decision
Build `packages/agent-service/` as a standalone FastAPI + Uvicorn HTTP service exposing the agent runtime: plain HTTP REST for request/response, Server-Sent Events for all streaming, Pydantic v2 models on every boundary (no untyped dicts), bearer-token auth via `COS_AGENT_SERVICE_TOKEN` compared with `secrets.compare_digest` (constant-time) on every endpoint except `/api/v1/health`, and a hard kill switch `COS_DISABLE_AGENT_SERVICE=1` that raises before any route registers. The endpoint surface is fixed at 26 operations (25 distinct paths) across health/metadata, agent config, oneshot, session lifecycle, workspace, and query-with-session; new endpoints require an ADR amendment.

## Why
Alternatives were rejected concretely: CLI-only API (process-spawn latency, no streaming primitive); sync-only REST (agent calls are multi-minute, can't represent partial tool output); gRPC (needs a browser proxy layer, mandatory codegen, harder to debug with curl); GraphQL (overkill for 26 stable-shape endpoints, adds a third transport for subscriptions); WebSocket (needs sticky sessions across load balancers, breaks through more proxies/CDNs, forces every client to implement reconnection). HTTP+SSE won because SSE is a W3C standard with native browser support, degrades to readable text under curl, and matches the natural request-shaped/event-shaped split of agent interactions. The Phase 1 `/csrf-token` placeholder was deliberately removed during the security pass because it emitted an unverified `secrets.token_urlsafe(32)` with no server-side store — "shipping no endpoint is honest; shipping a fake one is worse."

## Consequences
Positive: the agent runtime becomes addressable from any HTTP client without IDE coupling; the Phase 1 contract is deployable now so clients can build against a stable schema with deterministic 501s on unimplemented paths; OpenAPI/Swagger gives every client language a typed path for free. Negative: adds a new long-running process to the operational footprint when enabled; duplicates validation logic between this service and the in-harness agent path until the Phase 2 runtime adapter collapses them. Named risks: auth-bypass via misconfigured upstream proxy (mitigated by enforcing bearer auth inside the app, not relying on a gateway), and SSE keep-alive across proxies (mitigated in Phase 3; current query streams are bounded and close after the deterministic turn).

## Status & current state
Accepted but explicitly "not closed" per the ADR's own Wave 5 closure gate — the service still exposes typed stubs and lacks production runtime controls. Closed so far: file-backed JSON session lifecycle/event backend, the local synchronous `sessions/query`/`oneshot/query` adapter (via a deterministic runtime-lab mock runner, not the production agent runner), and runtime-lab query SSE streams. Of 26 operations, 15 are functional (health/version/agent-options plus 8 file-backed session endpoints, 2 local sync query endpoints, 2 runtime-lab SSE endpoints), 10 remain typed JSON 501 stubs, and 1 (`sessions/generate-summary`) is an SSE stub. Formal closure requires: replacing remaining 501s, wiring production model/runtime settings, real CSRF, rate limiting, workspace/search, sharing, abort semantics, and a JSON-to-SQLite migration, each with contract tests. Rate limiting is called out as a Phase 2 hard requirement before the in-process production agent runner can be wired — without it, a leaked bearer token becomes unlimited LLM consumption.
