## Decision
Build an offline enricher (`lib/skill_description_enricher.py`, CLI `scripts/cos-skill-description-enrich`) that, per skill, generates ~2 short natural-language utterances per target language (default en/es/pt/de/fr/it, so 12 entries per skill) via `lib/dispatch.py` (ADR-049 vendor-neutral, Qwen primary/Claude fallback) and merges them into SKILL.md frontmatter as `routing_intents` tagged `auto_generated: true`. Idempotency and human-curation protection rely on that tag: reruns without `--force` skip already-enriched skills, and existing untagged (human-curated) intents are never modified — new entries are appended after them. The LLM is prompted for a strict fixed-JSON shape; malformed responses are logged and the skill file is left untouched.

## Why
ADR-296 fixed the routing algorithm (Jaccard → multilingual FastEmbed) but not the underlying corpus quality — most skills still only had English descriptions to route on. ADR-297 (LLM-dispatch fallback) and ADR-298 (benchmark harness) provided the plumbing and measurement surface but neither closed the corpus-quality gap this ADR targets.

## Consequences
Positive: closes the SkillRouter description-only accuracy gap; enrichment is one-shot, version-controlled, and git-reviewable; no new dependencies (reuses `lib/dispatch.py`); auto-generated tag prevents the enricher from clobbering manual curation. Negative/trade-offs: one-time cost (~$2 for the full catalog, ~10 minutes wall-clock at 385 skills × 6 languages × ~$0.001/call); utterance quality is provider-dependent — the strict-JSON contract and audit trail mitigate but cannot guarantee semantic fidelity; running the full catalog enrich adds ~12 lines of frontmatter to ~385 SKILL.md files, producing a large but mechanically uniform diff. Cost/safety guards: `--cost-cap-usd` (default $5, halts gracefully with partial-progress save and an 80%-of-cap warning), `--rate-limit-per-minute` (default 60), `--dry-run`, and kill switch `COS_DISABLE_ENRICHMENT=1`.

## Status & current state
Accepted and implemented in the same change (2026-05-13). Every dispatch call is audited to `.cognitive-os/metrics/skill-enrichment.jsonl` (skill, languages, success, provider, cost_usd, latency_ms, error). Acceptance criteria include: unmarked unit tests pass; `--dry-run` runs without error; `scripts/cos-adr-implementation-audit.py --strict` shows 0 overclaims; idempotency verified by file-mtime assertions; the mock-dispatch "enriched corpus improves routing" test passes on a 5-skill held-out subset (architectural proof, not a live-LLM validation — the live-LLM oracle test is gated behind `@pytest.mark.enrichment` and excluded from default CI). Operators should re-run after large catalog changes (new/renamed skills) to maintain coverage; `COS_DISABLE_ENRICHMENT=1` makes the tool a safe no-op in CI.
