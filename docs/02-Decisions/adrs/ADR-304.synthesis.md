## Decision
A periodic telemetry aggregator with three independently-testable slices. Slice 1: `lib/telemetry_aggregator.py` reads SLO declarations from `manifests/observability-slo.yaml` (schema `observability-slo/v1`: source stream, metric type, optional filter/window, target, severity), evaluates each against its target, and emits one idempotent finding per breach (`stable_id = sha256(slo_id|hour_bucket|rounded_value)[:16]`) into the existing ADR-247/275 control-plane remediation queue; missing/empty streams emit `info`-level `telemetry-stream-missing` rather than crashing. Slice 2: a SessionStart banner (`lib/telemetry_banner.py`) surfaces the top 3 highest-severity findings from the latest snapshot (if <=2h old), silent otherwise. Slice 3: a self-tuning proposer suggests (never auto-applies) flipping a hook to async when the same SLO breaches across >=3 consecutive hourly windows AND the hook emits zero stdout — gated on a `stdout_bytes` field not yet emitted by `hook-timing-wrapper.sh`, so this slice is dormant by design until that field lands, with a test verifying the silent skip.

## Why
The control-plane already had the right consumer infrastructure (`scripts/cos-control-plane-audit`, hourly/pre-public lanes, `control-plane-remediation.jsonl`) — telemetry streams like `hook-timing.jsonl` (~73k records), `llm-dispatch.jsonl`, `llm-routing.jsonl`, `skill-enrichment.jsonl`, `skill-routing.jsonl`, and `startup-benchmark.jsonl` just had nothing reading them regularly (only `closure-trail.jsonl` had an existing consumer per ADR-275). The aggregator's job is purely to close that gap by fitting into the existing remediation-queue contract rather than inventing a new one.

## Consequences
Positive: every metrics emitter is now eligible for an SLO budget; adding a new SLO is one YAML entry with no code change; findings flow through the unchanged ADR-247/275 triage/dedupe workflow; the SessionStart banner closes the visibility loop without requiring the operator to remember to check a report. Risk accepted: aggregator windows apply after any declared filter (required for sparse events like `SubagentStart` inside large streams — tailing first would erase the signal and falsely report `no_data`), and large streams may need retention/rollup work as SLO coverage grows. Cost: one additional ~50ms hook in the hourly control-plane lane and one more manifest to maintain.

## Status & current state
Accepted, implemented 2026-05-13, classification basis states "no remaining in-scope work for this ADR." End-to-end verification on the real repo showed 5 evaluations / 3 breaches / 0 proposals on first run, and correct dedupe (0 appended, 3 deduped) on re-run. All three test suites pass (9+5+6 tests).
