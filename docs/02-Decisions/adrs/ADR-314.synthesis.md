## Decision
Adopt an evidence-weighted Primitive Scope Taxonomy Calibration Loop with two parts: (1) `scripts/primitive_scope_classifier.py`, which emits row-level hypotheses (`suggested_scope`: os-only/project/both/unknown) plus a safe `effective_scope` fallback (unknown maps to os-only until proven otherwise) from distribution/projection evidence — not grep-only source mentions; (2) an auditable iteration-control ledger (`docs/06-Daily/reports/primitive-scope-classifier-iteration-control-*.md`) governing manual review, one bucket at a time. Unknown rows flow through `scripts/primitive_scope_unknown_triage.py` before adjudication. No full-repo classifier run may directly drive marker rewrites — enforcement gates must use explicit `--paths` on changed/staged files only.

## Why
ADR-019's os-only/project/both taxonomy and ADR-306's projection audit left the *process for changing classification* ungoverned. The reverted commits' root cause was five compounding errors: treating source-repo path mentions as distribution proof, treating `both` as suspicious by default, conflating insufficient evidence with final os-only classification, missing package-skill coverage (`packages/*/skills/*/SKILL.md`) in the original classifier inventory, and mistaking full-repo classifier output for an instruction to mass-edit. Re-review evidence: a239dcff touched 156 files, only 155 classifiable, and among those 18 were genuinely `both` and 61 were `unknown` — not proven `os-only`. 33682e2e touched 26 files, 24 classifiable, with only 3 proven `os-only` and 21 unknown.

## Consequences
Positive: scope changes become auditable hypotheses instead of bulk edits; `unknown` prevents insufficient evidence from being mislabeled `os-only`; `both` remains valid when evidence/proof exist; package skills are now in the classifier inventory. Negative/trade-offs: full-repo counts create review backlog rather than a quick pass/fail; many rows need metadata/proof work before resolution; `project` still needs a stronger positive-evidence model and must not collapse into `both` or `os-only` without consumer-project-only proof; classifier will require ongoing calibration.

## Status & current state
Accepted and implemented, 2026-05-14. Verification commands run pytest across `test_primitive_scope_classifier.py`, `test_cos_init.py` (red-team portability), `test_primitive_scope_classification.py` (contracts), `test_primitive_scope_governance.py`, `test_scope_both_portability_audit.py`, plus a scoped classifier run with `--fail-contradictions`. Iteration 1 reviewed all `suggested_scope=both` rows (65 total): 48 confirmed `both`, 14 candidates with marker/proof gaps, 3 with fallback overrides but missing headers — no marker changes were made in Iteration 1 itself.
