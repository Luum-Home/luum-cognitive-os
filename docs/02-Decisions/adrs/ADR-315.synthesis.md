## Decision
Introduce a canonical primitive parser layer (`lib/primitive_parser.py`) that runs before scope classification. It produces a normalized, descriptive-only `PrimitiveContract` per primitive kind (skill, rule, hook, script, template — including `packages/*/skills/*/SKILL.md`), capturing `path`, `kind`, `is_primitive`, `scope_marker`, `title`, `summary`, `audience`, `activation`, `frontmatter`, `sections`, `structural_findings`, and `semantic_hints`. The parser must never decide final `SCOPE` — that remains owned by ADR-314's evidence model and manual calibration; the parser only feeds it cleaner facts. Family-specific contracts differ meaningfully: skills require YAML frontmatter with `name`/`version`/`description`/`triggers`; rules treat Markdown as portable source of truth with YAML frontmatter explicitly optional (only a `<!-- SCOPE: ... -->` marker, H1, and an opening section are required); hooks derive activation from event names, not prose triggers; scripts and templates expose CLI/manual activation and scope markers where present.

## Why
Without a parser layer, scope classification could regress into reading content directly and over-weighting OS-specific strings — the same failure pattern that had already caused commits to be reverted — because skills, rules, hooks, scripts, and templates each have structurally different authoring grammars that a single raw-grep heuristic cannot honestly distinguish.

## Consequences
Positive: scope classification starts from a typed primitive contract instead of loose grep; the system can explain why a primitive is structurally incomplete without pretending its scope is known; cross-IDE portability improves (author once in canonical format, project to Claude/Codex/Cursor/Copilot/OpenCode/future harnesses); package skills remain first-class parser targets. Negative: parser maintenance becomes another governed surface; some legacy primitives will show structural debt even when their current scope marker is correct; semantic hints remain heuristic and need manual calibration before influencing any gate.

## Status & current state
Accepted and implemented — 2026-05-14. `scripts/primitive_scope_classifier.py` now consumes `parse_primitive_file(...).scope_marker` instead of its own header parser; classifier output was kept stable (no mass marker edits performed). `manifests/primitive-structure-scopes.yaml` exists only for file formats where inline SCOPE comments would corrupt generated artifacts. ADR-315 explicitly does not replace `manifests/primitive-contracts.yaml` (ADR-256/257) — that remains the canonical portable behavior/projection registry; this parser is a broader structural-normalization layer feeding it.
