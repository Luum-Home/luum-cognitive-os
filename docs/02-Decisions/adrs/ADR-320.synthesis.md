## Decision
Treat the installer as having two real installed surfaces until a future ADR gives `project` and `both` separate executable semantics: (1) consumer filtered install — `project`/`both` are equivalent aliases, excluding top-level `os-only` primitives; (2) maintainer/self-hosting install — `all` installs the full surface including `os-only`, not a default recommendation for adopters. The three-value primitive SCOPE taxonomy (`os-only`/`project`/`both`) stays valid for classification; the debt is specifically in install-scope projection. `both` remains the default alias for backward compatibility. Protected-config safety claims must stay scoped to control-plane files — COS must not claim `.env` is blocked unless a later ADR adds `.env*` to `manifests/protected-config-write-policy.yaml` with passing tests. A projection consistency guardrail is also introduced: `settings hook reference ⊆ installed hook files ∩ SCOPE-allowed hook files`, enforced by `scripts/cos-install-projection-audit` and extended to a runtime dependency closure check via `scripts/runtime_hook_reality.py --dependency-closure`.

## Why
The install-scope smoke and manual review found `project` and `both` produce identical allow/block decisions in `scripts/cos_init.py::scope_allows()` and `skill_scope_allows()`, and that `all` demonstrably installs more files without proving a better developer outcome. Separately, a `.env` write probe was found to test an expectation not encoded in the `protected-config-write-guard` policy at all, since that guard protects `.claude/settings.json`, `.codex/**`, rules, hooks, and selected manifests — not `.env`.

## Consequences
- Product language must describe two installed surfaces, not three operational tiers.
- `all` remains useful for self-hosting/maintainer debugging but loses "more is better" framing.
- `.env` write protection must not be claimed until a control is actually wired and tested for writes.
- Debt register tracks: install-scope alias debt, naming debt (`both` as default alias not a tier), outcome debt (`all` unproven), and safety-claim debt (`.env` exclusion).

## Status & current state
Accepted and implemented. Implementation files include `install.sh`, `scripts/cos_init.py`, `scripts/generate-project-settings.sh`, `scripts/cos_install_projection_audit.py`, `scripts/cos-install-projection-audit`, `scripts/runtime_hook_reality.py`, plus behavior/integration/red-team/unit tests. Future options left open: keep two surfaces and deprecate `both`; make three surfaces real with separate outputs; or add secret write protection for `.env*` as a distinct policy decision.
