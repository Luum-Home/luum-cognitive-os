---

## Decision
Introduce an explicit AI Resource Economy control plane in five phases, canonically declared in `manifests/ai-resource-economy.yaml`. (1) Taximeter ledger: every AI-consuming work unit representable as JSONL with session_id, agent_id, task_id, model, tokens_in/out, estimated/actual cost, retry_count, tool_calls, reasoning_effort. (2) Budget preflight: before expensive tasks, estimate context size, file count, expected agents/tests, cost, and loop risk — degrade (split, cheaper model, local search first, ask for confirmation, plan-without-execute) when the estimate is high. (3) Language token economy: preserve Spanish for the user while keeping internal artifacts compact (summarize long transcripts, memory/local search before re-reading large histories) — the optimization layer is internal representation, not forcing English. (4) Local/open-source fallback: route grep/parsing/classification/inventories/report-generation/mechanical audits to scripts or local models before spending frontier-model calls. (5) Anti-loop/anti-slop: cap iterations per front, stop after a repeated failure, regenerate stale artifacts once, classify repeat failures as real contracts, avoid full-suite reruns until the cause is narrowed.

## Why
The explicit design constraint that Spanish must remain the user's working language while cost optimization happens at the internal-representation layer (compact fields, memory-first retrieval, no duplicate Spanish/English prose) is a direct, named rejection of the "force English-only to save tokens" alternative — because that would harm the user's actual workflow to optimize the wrong layer.

## Consequences
Positive: resource controls become inspectable/testable instead of conversational advice; Spanish collaboration stays first-class without wasting tokens internally; expensive tasks get an explicit preflight/degradation path; repeated validation loops become diagnosable economic incidents; public-facing work can distinguish product-quality artifacts from internal churn. Negative/trade-offs: more metadata to maintain; early estimates stay approximate until provider actual-cost APIs/events are normalized; strict blocking must phase in carefully to avoid stopping urgent repairs; local fallback is less semantically rich and must not be used for judgments requiring architectural review.

## Status & current state
Accepted; implementation_status: partial. Explicit "Wave 5 closure gate": ADR-325 is NOT closed while resource accounting remains advisory and partly estimated. Closed so far: Phase 1 (manifest/audit/preflight CLI/language-token-economy rule) and the initial bounded Phase 3 slice — `context-budget-meter` and `subagent-budget-enforcer` hooks now emit ADR-325 resource-ledger rows, and `token-budget-monitor` consults that ledger for hourly token enforcement. Remaining/open: provider actual-cost ingestion, ledger normalization/deduplication, preflight threshold enforcement, local fallback routing (Phase 4), and CI ratchets (Phase 5) that prove budget regressions are caught pre-merge.
