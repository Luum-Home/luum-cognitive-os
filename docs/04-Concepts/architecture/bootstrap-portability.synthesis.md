## What it is
Gap analysis and remediation plan for making Cognitive OS provider-agnostic at bootstrap, environment-resolution, and settings-projection time (not just at the execution-model layer), so Codex (and other harnesses) can host the system without Claude-specific shims.

## Key mechanics
- Already portable: `internal/provider/codex.go` (Codex provider adapter), `pkg/hook/context.go` (canonical provider-agnostic context model), ADR-008 (multi-tool support decision), `cross-tool-landscape.md`.
- Remaining lock-in: bootstrap paths, environment resolution, harness-specific settings projection, and assumptions that `.claude/` is the operational driver. Examples: `hooks/self-install.sh` previously resolved project only via `CLAUDE_PROJECT_DIR`; `lib/config_loader.py`, `lib/dispatch.py`, `lib/record_completion.py` relied on Claude-first env lookup; installer flows assumed `.claude/settings.json` as the primary projection target; behavior tests modeled only Claude-specific env vars.
- Minimum correction sequence (5 steps): (1) canonicalize env resolution precedence `COGNITIVE_OS_PROJECT_DIR -> CODEX_PROJECT_DIR -> CLAUDE_PROJECT_DIR -> cwd` and session `COGNITIVE_OS_SESSION_ID -> CODEX_SESSION_ID -> CLAUDE_SESSION_ID`, migrating self-install/session-init/config-loading/dispatch-metrics/completion-recording first; (2) make `.cognitive-os/` the runtime-truth center, `.claude/` a projection layer only; (3) per-harness settings driver (`.claude/settings.json` for Claude, `.codex/hooks.json` for Codex); (4) make `self-install` harness-aware (or split into core sync + harness projection); (5) rewrite critical behavior tests to exercise generic + Codex + Claude paths.
- Incremental progress already shipped (partial list): `self-install.sh`/`session-init.sh` accept/export `COGNITIVE_OS_PROJECT_DIR`/`CODEX_PROJECT_DIR`; `config_loader.py`/`dispatch.py`/`record_completion.py` use canonical resolution; `scripts/generate-project-settings.sh` and `scripts/cos-init.sh` are harness-aware; Codex projects native `.codex/hooks.json` (not wrapped in Claude's `hooks` object); `cos` installer registers hooks per-harness; `apply-efficiency-profile.sh`, `upgrade.sh`, `bin/cognitive-os.sh`, `cos-status.sh`, `uninstall.sh`, `cos-release-check.sh`, and several user-facing scripts (`component-lint.sh`, `startup-benchmark.sh`, `benchmark-hooks.sh`, `cos-usage-report.sh`, `cos-sessions.sh`, `engram-sync.sh`, `session-leak-diagnostic.sh`, `cos-update.sh`, `auto-update-projects.sh`) now use canonical project-root/settings-driver detection instead of assuming Claude; `cos-init.sh` records selected harness/driver in `.cognitive-os/install-meta.json`; `install.sh --harness` exposes the `cos_init.py` harness set beyond Claude/Codex (Cursor smoke test added); skills/rules canonical location is `.cognitive-os/{skills,rules}/cos`, with `.claude/{skills,rules/cos}` as Claude-only projections; `host-tool-doctor.sh` SessionStart advisory for both drivers; `manifests/harness-driver-capabilities.yaml` + `scripts/harness_parity_audit.py` separate Codex parity gaps from unsupported ones; memory lifecycle hooks follow the canonical precedence, with Codex covering SessionStart/UserPromptSubmit/Stop and Claude retaining richer PreCompact/PostToolUse coverage as a named driver advantage; `scripts/cos-doctor-memory-lifecycle.sh` proves the memory loop in an isolated scratch Codex project; ADR-140 container worker (`docker/cos-worker/`, `scripts/cos-cloud-worker-bootstrap.sh`) uses `/workspace/.cognitive-os/` as runtime center and account-agnostic `LLM_PRIMARY_API_KEY`/`LLM_FALLBACK_API_KEY`.
- Consumer packaging boundary: maintainer `.ai/` overlay (proof-oriented, generated from manifests) is a distinct artifact from a consumer `.ai/` package (README-first, adapter-installer-oriented); bootstrap still installs `.cognitive-os/` as runtime center then projects into driver files (`.claude/settings.json`, `.codex/hooks.json`, `.cursor/rules/...`, `.github/copilot-instructions.md`) plus optional `.ai/` views. Compiler entry point: `lib/adapter_compile.py`, `scripts/cos-adapter-compile`, `cos adapters compile`.
- Codex governed tool-layer: `scripts/cos_governed_runner.py --harness codex` runs synthetic Agent and Edit/Write hook chains for gaps Codex's native projection can't emit; lifecycle/Bash hooks stay native in `.codex/hooks.json`.
- Token telemetry: normalizes Claude/Anthropic, OpenAI/Codex, OpenCode, generic IDE usage into `token-usage-normalized.v1`; reports must show `providers_seen`/`harnesses_seen` rather than implying universal enforcement; runtime enforcement still varies (Claude-style hooks can block/warn, others get advisory-only projections).

## Status / caveats
Success condition (not yet fully met): Codex hosts the system without Claude-compatibility shims; `.cognitive-os/` is unambiguously the runtime center; settings files are projections not assumptions; critical behavior tests exercise more than one harness path. Remaining work explicitly named: removing duplicated bash harness list, making shell settings-driver helpers preserve structural harness metadata instead of falling back to Claude.
