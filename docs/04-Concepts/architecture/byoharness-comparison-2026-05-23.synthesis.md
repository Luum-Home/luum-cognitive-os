## What it is
Comparison of the external educational coding-agent harness `byo-coding-agent` against Cognitive OS's governance/projection product layer, concluding BYO is useful as a reference lab for ADR-291 runtime work, not a replacement for COS's hook-governance mesh.

## Key mechanics
- Source evidence: `betta-tech/byo-coding-agent`, commit `77aa4db3fa3f606e6605b4b3275852129e93be6f`, cloned to `/tmp/byo-coding-agent`; `go test ./...` passed locally.
- Architecture comparison highlights: BYO owns a full standalone agent loop (`internal/agent.Agent.Send`, `MaxTurns`), provider seam (`internal/provider.Provider` for Anthropic/OpenAI), typed tool registry (`internal/tool.Tool`), human-approval gate with unified-diff preview before writes, subagents as delegation tools, MCP client (`mcp.json`, stdio/http), file-backed memory (`.harness`, substring recall), pluggable compaction (none/sliding-window/model-summary/safe-split), and a Bubble Tea debug panel. COS today: no canonical standalone loop (hooks intercept host lifecycle events instead); provider abstraction means harness-hook-payload adapter (name collision risk vs. LLM provider); agentic primitives (skills/hooks/rules) projected via installers; Engram + metrics/changelogs for memory.
- 7 high-value patterns recommended to port: (1) small agent-loop reference implementation under a lab/`packages/agent-runtime` path (behind ADR-291); (2) distinct `internal/llm`/`packages/agent-runtime/.../llm` package separate from harness-driver `Provider`; (3) typed, deterministic (sorted) tool registry for service/headless tools (`read_file`, `write_file`, `bash`, `memory_recall`, `memory_save`, `delegate_*`, MCP wrappers); (4) diff-first write-mutation approval envelope; (5) safe compaction split invariant (`SafeSplitPoint`, never cut between `tool_use`/`tool_result`); (6) debug/event transcript panel for provider calls, tool dispatch, compaction, cost — feeding ADR-291 SSE and Surface 5; (7) subagent-as-governed-tool model with isolated context and resource budgets.
- Patterns to avoid/strengthen before adoption: BYO's interactive approval lacks COS-level blast-radius/license/credential/claim-validation/retry-exhaustion policy; its memory is simpler than Engram v3 goals (evidence-grounded claims, safe writes, BM25, bundle portability); no central config contract (COS should keep `cognitive-os.yaml`/manifests/ADRs); tool execution needs policy/sandbox/audit/rollback wrapping; provider naming must stay disambiguated (BYO "provider" = LLM backend, COS "provider" = host harness adapter).
- 5 suggested COS slices: A) Runtime Vocabulary and Boundary Doc (harness-driver provider vs LLM provider vs tool registry vs agentic primitives); B) Minimal COS Agent Runner Lab (Agent loop + LLMProvider + Tool interfaces + mock provider; acceptance: mock provider can request/consume tool result, max-turn exhaustion explicit, tool errors returned not panicked, no mutation tool without approval interface); C) Agent-Service Runtime Adapter replacing deterministic sync responses in `packages/agent-service/src/agent_service/runtime.py` (acceptance: `/api/v1/oneshot/query` runs against mock provider in tests, SSE stubs emit real tool-request/final-answer events, bearer auth/kill switch unchanged, mutations go through policy/approval envelope); D) Debug/Event Schema (model request/response, tool request/result, policy decision, memory save/recall, compaction before/after, token/cost — feeding ADR-291 SSE + Surface 5 TUI); E) Runtime Tool Policy Contract (static policy -> workspace/path boundary -> diff preview -> human approval -> execution -> audit event -> rollback/checkpoint).
- **Implemented slice (2026-05-23):** `packages/agent-service/src/agent_service/runtime_lab/` wired into `runtime.py`; delivered `runtime_lab.llm.LLMProvider`/`MockLLMProvider`, `runtime_lab.tools.ToolRegistry`, diff-first `WriteFileTool`, `safe_split_point`/`SafeSlidingWindow`, `runtime_lab.subagents.SubagentTool`, `EventRecorder` + SSE events (`llm.request`, `llm.response`, `agent.final`), `runtime_lab.mcp.MCPToolWrapper` (scoped to service/headless runtime, not a replacement for host MCP). Validated via `cd packages/agent-service && uv run --extra testing pytest tests/test_runtime_lab.py tests/test_sessions.py tests/test_sse.py tests/test_contract.py -q` — 38 passed.
