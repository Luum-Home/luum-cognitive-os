## What it is
Rationale document explaining why Cognitive OS has the shape it has: the system externalizes a single maintainer's ongoing judgment (a "cognitive prosthesis") rather than shipping features for a generic audience, and its gates/doctrine are the same filter the maintainer applies to himself.

## Key mechanics
- Companion to `boring-reliability-control-plane.md` (the operational doctrine: real/measurable/reversible/honest/evidence-backed); this doc explains *why* that doctrine exists, per multi-surface note in ADR-172 (UI surfaces must prove they're real, working artefacts before being built).
- "The system is a mirror, not a metaphor": the REAL/DORMANT/ASPIRATIONAL taxonomy in `scripts/aspirational_audit.py` mirrors the maintainer's own informal filter for whether a decision has landed or is wishful thinking; idiosyncratic-looking doctrine usually has a one-line internal rationale — surprising decisions should prompt "what filter is being applied?" not "is this arbitrary?"
- Three "cognitive prosthesis" components (externalize thinking, not ship features): Engram (long-term memory, decay/reinforcement, survives compaction/sleep); ADRs (medium-term reasoning, version-controlled, cross-linked); `cos-boring-reliability` dashboard (surfaces false-positive counts, runtime coverage, WIP safety, recovery drill pass rate). Treated as load-bearing, not optional.
- Guardrails against "tired-self": hooks `destructive-git-blocker`, `secret-detector`, `concurrent-write-guard`, `orchestrator-claim-gate`, `safe-worktree-remove`, `lethal-trifecta-gate` exist as explicit fences against known fatigue-driven failure modes (pushing to main unthinkingly, leaking credentials, destroying in-flight work, merging unverified claims). Bypass requires deliberate action: `COS_ALLOW_DESTRUCTIVE_GIT=1`, `--no-verify`, `--allow-destructive` token.
- "Dogfood, not consumable": no dev/staging/prod separation; maintainer is simultaneously first user, last QA, and adversary; false-positive rate measured by `cos-false-positive-ledger`. New contributors should expect to be blocked by gates, not treat that as removable friction.
- "Subtraction + maturity-driven, not addition-driven": `rules/phase-aware-agents.md` declares current phase `reconstruction` (rewrite substandard code, demote non-conforming primitives, no deferred "future work"). Evidence: ADR-130/131 removed 11 workflows via `.disabled` rename rather than adding new ones; `cos-default-visible-reducer` (proposes demotions) and `cos-silent-failure-audit` (prevents silent growth) are the control-plane's core mechanisms; `manifests/governance-maturity.yaml` labels gates `advisory`/`observe` rather than upgrading to `blocking` without evidence. Rule of thumb: net-new surface without demoting something existing probably belongs in `lab`, not default profile.
- "Single-maintainer calibration": system sized to 162 skills, 116 hooks, 1,580 classified silent-failure occurrences — one attentive brain's capacity given the externalization infrastructure; named as deliberate scope in ADR-132, which also lists trigger conditions for re-shaping toward multi-maintainer (sustained second contributor, or external org requesting unmediated consumption) and 5 provisional constraints (hook portability declaration, evidence-blocks for tier claims, Engram topic-key namespacing, no hard-coded filesystem assumptions, progressive externalization of the maintainer's mental cache).
- "Two maturity stages": Stage 1 "works when it works" (capabilities ship, failure evidence anecdotal, doctrine aspirational) vs Stage 2 "knows when it doesn't work" (every capability ships with falsifiable failure conditions) — a one-way ratchet. Stage-2 mechanisms enumerated: demotion as first-class op (ADR-126, `demotion_evidence`/`sunset_criteria`, first demotion was `hooks/task-completed.sh`); maturity labels with no shortcut to "blocking" (`manifests/governance-maturity.yaml`, e.g. `trust-score-validator`/`blast-radius`/`review-spawner` explicitly non-blocking); silent-failure classified surface (`manifests/silent-failure-allowlist.yaml`, every `|| true`/`|| :`/`2>/dev/null` needs rationale + `max_occurrences`); aspirational audit (`scripts/aspirational_audit.py`, REAL/DORMANT/ASPIRATIONAL tags, drift reported both directions); false-positive ledger (`cos-false-positive-ledger`, gates measured, bad gates get demoted not tightened); propose-only default (ADR-134, ADR-135: self-improvement/doctrine-proposer loops generate proposals only, `human_approval_required: true` hardcoded, blocked actions include `auto_merge`/`auto_promote_core_or_team`/`invent_roi_evidence`); anti-self-validation (`manifests/external-adoption-evidence.yaml`, requires `maintainer_owned: false`/`same_machine: false`/`same_repo: false`/`self_reported: false`; first cross-instance drill disqualified its own output as adoption evidence); runway with observable triggers (ADR-136, Shape B infra built/rehearsed via `cos-cross-instance-drill` but not activated; 6 triggers in `manifests/federation-triggers.yaml`); falsifiable claims as release artefact (CHANGELOG v0.24).
- Test for default-profile inclusion: not just "does it work?" but "how would I know, mechanically, when it stops working?" — no answer means the capability hasn't finished landing.
