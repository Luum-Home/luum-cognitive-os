## What it is
Contract distinguishing SO-local (maintainer-repo) primitive evidence from primitives actually installed/projected into downstream consumer projects — a primitive is consumer-accessible only when an install/profile/settings-driver/package proves it was projected for a declared harness.

## Key mechanics
- Automated proof: `python3 -m pytest tests/behavior/test_consumer_project_projection.py -q` runs `scripts/cos_init.py --default --harness <harness>` in temp consumer projects and verifies each `implemented` harness gets its declared projection surface. Native lifecycle harnesses (`claude`, `codex`) get hook/rule/skill projection + settings; structural harnesses get instruction/config/context files, MCP placeholders, or shell/CI command/workflow projection.
- Proof currently covers: native/settings (`claude`, `codex`); AGENTS/instruction-file structural (`agents-md`, `kimi-code`, `warp`, `amp-code`, `qoder`, `goose`, `aider`); IDE/config structural (`opencode`, `vscode-copilot`, `cursor`, `qwen-code`, `gemini-cli`, `jetbrains-junie`, `factory-droid`, `cline`, `continue-dev`, `kilo-code`, `zed-ai`, `augment-code`); shell/CI structural (`shell-ci`). ACC pipeline (`scripts/acc_pipeline.py --project-dir . --refresh`) additionally runs implemented harness/profile checks; structural projection proves files generated, not runtime-enforcement parity.
- Ledger regeneration commands: `python3 scripts/primitive_readiness_ledger.py --project-dir . --fail-low-confidence` and, per family, `python3 scripts/primitive_family_readiness_ledger.py --project-dir . --target-family {hooks,skills,rules}`. Outputs: `docs/06-Daily/reports/primitive-readiness-ledger-{scripts,hooks,skills,rules}-latest.json`, each row carrying `consumer_accessibility` and `consumer_access_next_action`. Statuses `so-local-only`, `repo-skill-not-projectable`, `skill-referenced-not-projectable` are treated as unavailable to consumers until an install path proves otherwise.
- `manifests/primitive-consumer-availability.yaml` classifies lifecycle candidates with 4 allowed statuses: `shell-ci-candidate` (needs shell/CI projection proof, resolved via `manifests/shell-ci-projection.yaml` + `scripts/project_shell_ci.py` -> `.cognitive-os/scripts/cos/`, `scripts/` symlinks, `.github/workflows/cognitive-os-shell-ci.yml`), `projectable-needs-driver` (no harness/profile driver yet), `maintainer-only` (counts as aligned), `so-local-only` (counts as aligned). Only the first two remain "partial."
- Harness registry: `manifests/harness-projection.yaml` is authoritative; ACC treats only `status: implemented` as executable proof, `planned` stays visible as `unverified`.
- Harness support matrix (safe claims per harness): Claude Code and OpenAI Codex = native lifecycle/settings projection (hooks, rules, skills, `.claude/settings.json` or `.codex/hooks.json`); Cursor/VS Code Copilot/Agents.md-native/OpenCode/Qwen Code/Kimi Code/Gemini CLI/Warp/Amp/Qoder/Factory Droid/Cline/Continue/Kilo/Zed/Augment/Goose/Aider = structural projection only (project-local instruction/config files, no runtime-enforcement parity claimed; OpenCode additionally has a separate signed plugin smoke for a runtime subset); Shell/CI = structural command/workflow projection; Devin/Google Antigravity/MiniMax MaxClaw/DeepSeek/Kiro = planned, no consumer availability inherited.
- 5 acceptance criteria for future "available to consumer projects" claims: lifecycle or explicit package/profile projection metadata exists; row declares supported harnesses or documented fallback; a temp consumer project proof installs/projects the primitive/family; readiness ledger no longer marks it SO-local-only; documentation names the exact proved harnesses, not "all IDEs."
- Generated documentation-truth block (as of doc snapshot): 22 implemented harnesses (agents-md, aider, amp-code, augment-code, claude, cline, codex, continue-dev, cursor, factory-droid, gemini-cli, goose, jetbrains-junie, kilo-code, kimi-code, opencode, qoder, qwen-code, shell-ci, vscode-copilot, warp, zed-ai); projection fidelity summary: aligned=2040, contracts=340, gaps=0, pending_runtime_smoke=0, projection_rows=2040, unknown=0. Sources: `manifests/harness-projection.yaml`, `docs/06-Daily/reports/primitive-projection-fidelity-latest.json`.
