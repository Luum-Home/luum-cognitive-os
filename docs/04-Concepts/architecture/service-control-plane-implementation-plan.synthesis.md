## What it is
A staged proof-ladder implementation plan that turns service-control-plane research into a concrete build path toward a future `cosd` boundary, emphasizing propose-only automation, adapter isolation, and evidence before autonomy.

## Key mechanics
- Target architecture: operator/trigger/scheduled-event -> cosd task admission -> task queue -> scheduler+lease manager -> cos-worker (container or subprocess) -> provider executor adapter -> Claude Code/Codex/API/gateway; parallel paths to Engram Cloud and artifact/evidence store -> patch bundle/PR proposal -> human approval gate.
- 7 principles: propose-only first (merge/push/publish stays human-gated); no credential scraping; adapter isolation (provider auth/parsing/events live in executor adapters); evidence over dashboard; crash visibility before autonomy; lab-first providers (Kimi/MiniMax/DeepSeek until proof drill); maintainer economics (prefer official account-backed CLIs over direct API-key execution where safe).
- ADR-161 defines `cosd` as a **remote ingress adapter only**: authenticate, allowlist, normalize, rate-limit, enqueue — it does not own model credentials or execute tools directly.
- 7 phases, each with a stated implementation status: **Phase 0** contract/proof skeleton (manifests + `test_service_control_plane_contracts.py`); **Phase 1** local `cosd` minimal queue — *implemented as a Phase 1 local proof, not a long-running scheduler* (`scripts/cosd`, `cos-task-submit`, `cos-worker-run-once`, `cos-queue-drain`; JSONL/SQLite queue with atomic append, lease expiry, idempotent task IDs); **Phase 2** worker execution surface (temp workspace/worktree, deterministic no-model command first, `--keep` debug flag, no credentials required); **Phase 3** provider executor adapters — *implemented only to auth-probe plus host-adapter dry-run skeleton*; real calls gated behind `--allow-provider-call`, Claude execution still blocked pending a non-invasive account-session probe; adapter order local-command -> host-cli -> container-cli -> api-key/provider-cloud/proxy-gateway (table lists `codex-cli-host`, `claude-cli-host`, `codex-cli-container`, `claude-cli-container`, `proxy-gateway`; later lab adapters `kimi`/`minimax`/`deepseek`); required command `scripts/cos-auth-probe --provider <p> --mode <m> --json` returning `ready`/`auth_required`/`unsupported`/`unsafe`; **Phase 4** crash/resume and WIP safety — *partially implemented* for the local proof (lease heartbeat, stale-lease requeue, artifact append-only logs, `needs_human` marking); **Phase 5** PR/propose-only output (allowed: patch.diff, temp/fork branch, draft PR; blocked: direct push to protected main, force-push, unapproved merge, credential/secret leakage); **Phase 6** Compose + local Kubernetes (Docker Compose -> kind/k3d/minikube -> provider overlays; cloud explicitly out of scope until local K8s proves readiness/no-duplicate-execution/crash-restart/evidence-persistence/credential-redaction).
- Credential matrix by runtime shape: local maintainer host prefers `account-session` official CLI; personal VM prefers `account-session`/`device-login`; Docker on trusted host needs explicit device/OAuth/API/provider-cloud/mounted-credential auth; CI/headless needs API key/provider-cloud/OAuth/proxy; hosted/team/multi-tenant needs provider-cloud/OAuth/API-key/proxy (personal CLI sessions are not a safe multi-user boundary). Every executor contract declares `cost_mode`, `credential_mode`, `allowed_runtime`.
- 4 local/VM/container service shapes: A Host CLI service (first economically meaningful shape); B Personal VM service; C Docker sidecar CLI (no opaque credential-folder copying, needs proof drill per provider); D Hosted/team service (cloud-shaped, API-key/provider-cloud/OAuth/gateway).
- Explicitly NOT built yet: general multi-tenant hosted service, distributed locks across maintainers, full Engram consensus, always-on autonomous merge, unofficial account-token-reuse hacks.
- First implementation slice, **now implemented for `local-command`**: manifest contracts -> local JSONL queue -> local-command executor -> artifact bundle -> crash-safe lease proof. The first model-backed slice should be host CLI, not API key, unless the operator explicitly requests cloud/CI semantics.

## Status / caveats
Deliberately a proof ladder, not a finished product. Phase 1, Phase 3, and Phase 4 are explicitly partial/skeleton implementations as noted per-phase above; Claude CLI provider execution remains blocked pending an account-session status probe.
