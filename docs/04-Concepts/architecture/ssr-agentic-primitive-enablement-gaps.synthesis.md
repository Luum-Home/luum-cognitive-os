## What it is
Gap backlog (12 gaps, G1-G12) identifying why a senior/SSR developer without deep COS architecture knowledge cannot easily turn conversation, failure, or learning into a governed reusable agentic primitive.

## Key mechanics
- Current supported path (exists but fragmented): conversation/task/failure/learning -> prompt capture + metrics + Engram/session learning -> `primitive-harvester`/`analyze-improvements`/`product-answer` -> draft proposal -> primitive-fitness + governed self-improvement evaluation -> human-approved promotion -> reuse + measurement.
- 12 gaps (ID / impact / related primitive / priority): **G1** no single question-router for "which COS primitive answers my question" (P0); **G2** docs organized by artifact family, not developer job-to-be-done (P0); **G3** conversation-to-primitive is advisory only, not routinely triggered (P1); **G4** governed self-improvement feels less automatic than Agent Zero/OpenClaw/Hermes, risking misread as autonomous mutation (P0); **G5** "Key Learning" is evidence, not runtime behavior — easy to conflate (P1); **G6** primitive fitness ledger can be under-populated (P1); **G7** skill catalog is list-based, not task-centric (P0); **G8** harness parity nuance not surfaced per-answer (P1); **G9** `product-answer` lacks a "how does this help me as a dev" question-bank entry (P0); **G10** no owner cadence for reviewing accumulated proposals (P1); **G11** harvester output doesn't link directly to an authoring/test/registry checklist (P1); **G12** some docs read as implementation inventory rather than safe claims, risking overclaim (P0).
- Recommended additions: a new `cos-question-router` primitive returning {recommended skill, backing script, approved docs, question category, confidence + trust report}; a task-centric catalog view generated from skill frontmatter/routing patterns; targeted adjustments to `product-answer`, `primitive-harvester`, `primitive-authoring`, `analyze-improvements`, `catalog-full`; new scripts `cos-question-router`, `cos-skill-task-index`, `cos-primitive-gap-report`, `cos-harvest-current-thread` (must stay propose-only); new docs `primitive-enablement-for-developers.md`, `which-primitive-should-i-use.md`, periodic gap-review reports; new tests (Spanish-question routing, product-answer evidence/unsafe-claim contract, question-router fail-closed smoke, harvester regression for "can this be automatic?" questions).
- Safe external answer boundary (verbatim): "Cognitive OS helps developers turn repeated agent work into governed, tested, reusable agentic primitives. It can detect and propose improvements from conversations and telemetry, but promotion remains evidence-gated and human-approved unless a project explicitly opts into narrower automation." 4 phrases explicitly listed to avoid: autonomous self-rewrite from chat, identical cross-harness primitive behavior, all repeated requests auto-becoming skills, a Key Learning being an instant runtime behavior change.
