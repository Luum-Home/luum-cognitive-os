## What it is
Architecture note mapping the missing "runtime adapter" layer between COS's control-plane skeleton (`cosd`, `packages/agent-service/`) and a full autonomous coding-agent loop, evaluating Pi, Goose, OpenCode, Hermes, Aether, Gollem/Fugue, Hector, LangDAG, thClaws, holaOS, and aictl as candidate runtime backends or pattern sources.

## Key mechanics
- Current gap chain: client/UI/scheduler/webhook -> `agent-service` HTTP+SSE (ADR-291 skeleton) -> `cosd` control plane/queue/task admission -> **runtime adapter (missing)** -> model/tool loop (missing) -> filesystem/git/shell/MCP/browser tools -> COS gates/audit/memory/cost/trust evidence. `cosd` is described as closer to a control-plane/task-API/operational daemon than a full autonomous runtime.
- Minimal `RuntimeAdapter` interface proposed: `start_session`, `run_turn`, `stream_events`, `abort`, `list_tools`, `get_state` — must expose pre/post-tool, provider request/response, session start/end, compaction/checkpoint, streaming, and abort/retry hooks.
- **Pi/pi-mono**: closest to a ready coding-agent runtime (agent loop, typed tools, sessions, compaction, provider/auth); `beforeToolCall`/`afterToolCall` map directly to COS PreToolUse/PostToolUse. Explicit mapping table (skills -> `resources_discover.skillPaths`, rules -> context injection, `SessionStart` -> `session_start`, `Stop` -> `agent_end`, etc.). Safe claim: "COS primitive contract -> Pi extension -> Pi runtime execution -> normalized COS evidence" — **not** "Pi primitive = COS primitive."
- **OpenCode**: treated as a harness/projection target (native enforcement via `tool.execute.before/after` plugin hooks), not an internal COS runtime, until a plugin adapter + runtime smoke is signed.
- **Hermes**: a separate Python product runtime (not Pi-based) — reference for the native-runtime path, not embeddable.
- **OpenClaw**: evidence that "product/gateway built on top of Pi" is viable; not proof COS should migrate to Pi.
- **holaOS** (ADR-259): patterns-only reference — source, identifiers, comments, fixtures, docs text, and directory structure are blocked for adoption; only ideas/policies/state-machines/algorithms/behaviors may be reimplemented via the clean-room process.
- Go/Rust alternatives table: Rust = Goose (strong safety/interop runtime candidate), aictl (lightweight, license-blocked reference), Aether (strong Rust harness/library candidate — ACP + headless + MCP-only tools + provider traits), thClaws (broad Rust product/workspace, Claude Code auth via Agent SDK); Go = Hector (service/framework), trpc-agent-go (framework, direct pre/post callback mapping), LangDAG (conversation-runtime/DAG persistence), Gollem/Fugue (strong embedded runtime — durable execution, tool approval, event bus).
- Gollem/Fugue "coding-agent maturity" checklist (5 items: full filesystem/code tool suite, resumable session model, permission/approval policy, headless + IDE surfaces, COS adapter compiler) plus a concrete minimum spike acceptance test: clone a repo, edit safely, run tests, block one destructive tool before execution, stream events, resume after forced interruption, emit `.cognitive-os/metrics/primitive-interventions.jsonl`, produce a projection fidelity row.
- Primitive-ontology-mismatch: COS primitives are governed/evidence-producing/projectable constructs; runtime primitives (Pi tools, Goose extensions, Gollem middleware, etc.) are execution constructs only. Explicit "not allowed" claim examples given: "COS primitives are Pi tools" / "are Gollem middleware" / "are Hector tasks."
- Construction-mechanics comparison across 8 axes (definition locus, registration, schema, activation, execution boundary, interception points, persistence, evidence surface), plus a source-backed 2026-05-14 pass citing concrete files per runtime (e.g. Pi `packages/agent/src/agent-loop.ts`; Goose `tool_inspection.rs`/`tool_monitor.rs`; Aether `agent_spec.rs`; thClaws `skills.rs`/`hooks.rs`; Gollem `core/tool.go`/`core/hooks.go`).
- Construction-compatibility scoring: Gollem/Fugue, Aether, Pi, and trpc-agent-go rated cleanest for adapter proof (low-medium risk); Hector clean for service delegation only; thClaws/Hermes/OpenClaw too product-shaped (high risk); aictl reference-only (license-blocked).
- COS adapter construction contract: a YAML manifest mapping each COS primitive to `runtime_object`, `activation`, and `evidence` path, with a 6-item minimum adapter proof (list primitives projected; name the runtime object; name the trigger/activation rule; name the interception point; name the evidence row/event written back to COS; prove deletion/disable semantics so stale runtime objects don't outlive COS source-of-truth changes).
- Standards landscape: `AGENTS.md` (repo instructions only), `SKILL.md`/Agent Skills (packaging/progressive disclosure), MCP (tools/resources/prompts transport), ACP (agent-client/editor session protocol) — none defines a full governed primitive IR with lifecycle/scope/evidence/projection-fidelity. COS should promote `manifests/primitive-contracts.yaml` to the explicit canonical Primitive Contract/IR v1, referencing these standards as projection formats rather than inventing replacements.
- COS-vs-standards review table cites: `manifests/harness-projection.yaml`, `scripts/cos_init.py`, native-lifecycle marking (Claude/Codex) vs. structural (Cursor/Copilot/OpenCode), `skills/*/SKILL.md`, `manifests/primitive-authority.yaml`, `manifests/primitive-contracts.yaml` (already exists — a 2026-05-14 local run of `scripts/primitive_projection_fidelity.py` reported 340 contracts, 2,040 projection rows, 0 gaps), `packages/opencode-adapter/plugins/cos-primitive-guard.js` (OpenCode `tool.execute.before/after` smoke, writes `primitive-interventions.jsonl`).
- Design correction: reject "same file text everywhere = same primitive behavior everywhere"; require "same canonical spec + target projection manifest + target artifact + runtime evidence = measured fidelity per target." A Primitive IR field example (id/kind/version/source/standard_projection/semantics/projection_requirements) and a projection manifest example (per-capability `fidelity`: lossless/unsupported/adapter-required/advisory-only, plus `drift_policy`: target_edits forbidden, regeneration_required, stale_artifact_action=disable) are both given.
- Required 6-layer separation: canonical primitive spec / Primitive IR / projection manifest / target artifact / runtime event-result / normalized evidence — only the target artifact and runtime event are mutable by the IDE/runtime; everything else is COS-owned.
