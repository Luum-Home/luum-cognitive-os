## 2. El criterio, escrito para que otro lo aplique

Un doc es **borrable** solo si pasa las tres:

1. **Sin lector** — ninguna superficie lo alcanza (§3). Verificable:
   `python3 scripts/docs_reader_audit.py --path <doc>` devuelve `unread`.
2. **Sin referente vivo** — describe código/config que ya no existe, y la
   ausencia no se explica por un rename. Verificable: los paths que cita no
   resuelven bajo ningún prefijo actual.
3. **Sin valor de registro** — no es una medición fechada, un postmortem, una
   decisión, ni trabajo pendiente. Un informe con fecha es correcto para su
   fecha aunque el número haya cambiado; **es el registro de auditoría, no deuda.**

Fallar cualquiera de las tres ⇒ **se propone, no se ejecuta**.

Y una regla de forma: **el nombre del archivo no es evidencia.** `archive/`,
`-old`, `-deprecated` describen la intención de quien lo nombró, no el estado
actual. En este repo se midió hoy que 189 de 256 hooks se llaman como una clase
que no tienen; `docs/99-Archive/` resultó tener tests que lo asertan (§4.3).

## 3. La evidencia ejecutable: `scripts/docs_reader_audit.py`

Índice inverso: dado un doc, quién lo alcanza. Read-only, determinista, exit
0/1/2. Complementa a `scripts/cos_doc_path_audit.py`, que camina en la dirección
opuesta (referencias → paths faltantes).

Superficies que consulta, todas las que pedía el encargo:

| Señal | Qué detecta | Fuerza |
|---|---|---|
| `explicit-path` | un archivo trackeado nombra `docs/a/b/c.md` | fuerte |
| `relative-link` | un doc vecino lo linkea `](./c.md)` | fuerte |
| `dir-consumer` | código/hook/manifiesto/test/skill/rule consume el **directorio padre** | fuerte |
| `synthesis-pair` | `context_injector.py` sirve uno en lugar del otro | transitiva |
| `dir-mention` | prosa que menciona el directorio | débil |
| `basename-only` | alguien nombra el archivo pelado | débil |

Barre: MOCs, `docs/00-MOCs/entrypoints/`, `INDEX.md`, `skills/**`, `rules/**`,
`manifests/*.yaml`, `scripts/ lib/ cos_lib/ hooks/ cmd/ packages/`, `tests/`,
ADRs (como lectores), `CLAUDE.md`/`README.md`/`AGENTS.md`.

```bash
python3 scripts/docs_reader_audit.py --path docs/99-Archive/archive/benchmark-results.md
python3 scripts/docs_reader_audit.py --json          # barrido completo
python3 scripts/docs_reader_audit.py --unread-only   # solo huérfanos
```

Determinismo verificado: dos corridas seguidas dan el mismo md5
(`7f1a0d57cf414b5ef002234be4bcf311`).

### 3.1 El verde barato del propio script, y cómo se apagó

La primera versión devolvió **1328 read / 0 unread**. Era falso por tres
defectos, los tres del mismo tipo — una señal demasiado laxa que resucita todo:

1. **`dir-consumer` caminaba todos los ancestros.** Una mención en prosa de
   `docs/06-Daily` marcaba los 364 informes como leídos. *Corregido*: solo el
   directorio padre inmediato, y solo si el lector es maquinaria (código, hook,
   manifiesto, test, skill, rule). La prosa bajó a `dir-mention`, señal débil.
2. **`synthesis-pair` era mutua.** `X.md` declaraba lector a `X.synthesis.md` y
   viceversa: una isla huérfana se avalaba sola. *Corregido*: la pareja ya no es
   evidencia independiente; se resuelve transitivamente propagando el veredicto
   más fuerte (`resolve_synthesis()`).
3. **`dir-consumer` contaba como señal fuerte sin filtro de lector.**

Tras corregir los tres, el resultado es el mismo número pero ahora es honesto:

```
python3 scripts/docs_reader_audit.py --json
→ total 1328  read 1323  weak 5  unread 0
```

**Cero docs sin lector, con el clasificador endurecido.** Los 5 `weak` son
justamente los que el encargo advertía que no se tocan (§4.2).

## 4. Lo que se salvó de ser borrado (y por qué)

### 4.1 Los 419 `*.synthesis.md` no son duplicados

Son la página **preferida**. `cos_lib/context_injector.py` sirve
`X.synthesis.md` en lugar de `X.md` cuando existe, y excluye las synthesis del
scoring para no contarlas dos veces:

```bash
grep -n 'synthesis' cos_lib/context_injector.py | head
# 213: exclude ``*.synthesis.md`` from scoring so pages are never double-counted
# 317: SERVES the sibling ``*.synthesis.md`` page via _prefer_synthesis
```

Con cobertura de test en `tests/integration/test_query_tailored_context.py:265`,
que asserta que se sirve la synthesis y **no** el `.md` crudo. Borrar la mitad
"duplicada" —cualquiera de las dos— rompe ese test y degrada la inyección de
contexto. **419 archivos, el 31% del territorio, salvados por leer el consumidor
antes de borrar.**

### 4.2 Los tres runbooks de hoy con parches pendientes

Los únicos 5 docs que no son `read` son `weak`, y tres son exactamente los que
el encargo protegía:

```
docs/05-Methodology/runbooks/error-pipeline-type-contract-2026-08-15/README.md
docs/05-Methodology/runbooks/gate-exit-code-contract-2026-08-15/README.md
docs/05-Methodology/runbooks/skill-routing-gaps-instrument-2026-08-15/README.md
docs/06-Daily/reports/external-tools-deep-dive/README.md
docs/06-Daily/reports/external-tools-deep-dive/_template.md
```

Los cuatro `README.md` solo se alcanzan por `basename-only` — se llaman
`README.md`, así que el nombre pelado matchea 406 archivos y no dice nada. **El
doc menos referenciable del repo es el que contiene trabajo pendiente del
operador.** Es la refutación más limpia de "sin lector ⇒ borrable".

### 4.3 `docs/99-Archive/` — el blanco de manual, y es load-bearing

## 5. El segundo test: ¿hay docs de código que ya no existe?

Es la definición dura de "deprecado". Se midió el ratio de referencias a código
muerto por doc:

```
total de referencias a código en docs no-ADR: 21302
faltantes:                                     4157  (19.5%)
  recuperables como rename lib/ -> cos_lib/:   3352  (80.6% de las faltantes)
```

**El 80.6% de la "documentación de código que ya no existe" es un rename de
prefijo.** Verificado a mano sobre 18 módulos: 17 existen bajo `cos_lib/`.

```bash
for m in rate_limiter queue_drainer dispatch model_router sdd_resume; do
  test -f "cos_lib/$m.py" && echo "cos_lib/$m.py EXISTE (el doc dice lib/$m.py)"
done
```

Los 14 docs con 100% de refs "muertas" —el pico de la lista— son todos casos de
esto. `docs/05-Methodology/guides/queue-classes-routing.md` cita 7 módulos, los
7 "faltan", los 7 existen bajo `cos_lib/`. **No es un doc deprecado: es un doc
correcto con el prefijo viejo.**

Prueba adicional de que este test mide calidad y no borrabilidad:
`docs/00-MOCs/entrypoints/faq.md` sale con 92% de refs muertas y es un
**entrypoint**. Es deuda de redacción, no material a borrar.

El residuo real es 4157 − 3352 = **805 refs muertas** repartidas en
`tests/` (281), `hooks/` (147), `rules/` (78), `skills/` (72), `scripts/` (59).
Disperso, sin concentrarse en ningún doc: no define una población deprecada.

## 8. Qué del encargo era falso

1. **«Tu territorio son los ~1343 restantes» como población a podar.** El
   territorio existe, pero es casi todo material vivo. La población deprecada
   medida es **0 por el test de lector** y **0 concentrada por el test de
   código muerto**.
2. **La sugerencia implícita de que `docs/99-Archive/` es candidato natural.**
   Es de lo más asertado del repo: dos tests y un entrypoint.
3. **«Duplicados donde una versión reemplazó a otra sin borrar la vieja».**
   Los 419 pares que encajan en esa descripción son un mecanismo activo de
   inyección de contexto, con test.
4. **El encargo acertó de lleno** en tres cosas: los informes fechados son
   bitácora (y el repo lo tiene en código), los runbooks de hoy tienen trabajo
   pendiente (y son justo los peor referenciados), y el nombre de archivo miente.

**Se borraron 0 archivos. No hubo commit de borrado.** El único archivo nuevo es
`scripts/docs_reader_audit.py`, que responde la pregunta la próxima vez en 2
segundos.
