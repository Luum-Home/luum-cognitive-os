## What it is
A generated, machine-produced matrix (`schema: capability-coverage/v1`) mapping each recent ADR (ADR-230 through ADR-252) to a capability ID, its reality status, public-claim status, a numeric score, and counts of implementation/consumer/test/receipt evidence, plus known gaps.

## Key mechanics
- 23 capabilities listed, one row per ADR (ADR-230 to ADR-252), each with: capability id + short description, ADR number, Reality (`REAL`, `PARTIAL`, or `RESOLVED`), Public (all `false`), Score, Impl/Consumers/Tests/Receipts-Audits counts, and a "Known gaps" free-text column.
- Score distribution: most `REAL` capabilities score 100; `PARTIAL` capabilities score 95 and always carry a known-gap note (e.g. `mcp-server-surface` — "streamable-http-transport-and-external-registration-remain-opt-in"; `sandbox-adapter-tiers` — "microvm-and-contree-adapters-are-not-default"; `approval-policies-as-code` — "not-all-legacy-hooks-migrated-to-policy-yaml"; `detached-agent-daemon` — "launchd-systemd-activation-is-opt-in"; `deferred-tool-loading-toolsearch` — "provider-native-defer-loading-depends-on-provider-api"; `consolidated-bypass-allowlist` — "broad-ecosystem-bypass-consolidation-remains-future-expansion"). `tier-1-4-followup-bug-tracking` (ADR-238) is `RESOLVED` at score 90.
- Summary JSON block: `capabilities: 23`, `coverage_min: 230`, `coverage_max: 252` (ADR number range covered), `real: 16`, `partial: 6`, `findings: 0`, `block: 0`, `warn: 0`, `public_claims: 0`.
- File header explicitly states "Do not edit by hand" — it is regenerated by the `cos-capability-matrix` script.

## Relations & where used

## Status / caveats
Purely a generated, point-in-time ledger (not hand-authored narrative) — content is expected to change every time `cos-capability-matrix --write` reruns as new ADRs land or PARTIAL items close their gaps. No `public_claims` are recorded in this snapshot (all Public = false), so nothing here is presented as an external commercial claim.
