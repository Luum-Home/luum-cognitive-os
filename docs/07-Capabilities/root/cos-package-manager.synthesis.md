## What it is
A comprehensive design document (v1.0, 2026-03-27) for `cos`, a package manager for agentic primitives (skills, rules, hooks, templates) that lets AI coding agents install, publish, version, and discover reusable components across IDEs — "npm for AI coding agents."

## Key mechanics
- Core principles: IDE-agnostic manifest with a `platform.ide` field; Go-style domain-based naming (`github.com/org/pkg`) with optional `@org/pkg` scoped aliases resolved via a centralized index; namespace coexistence (`cos/@org/pkg/` subdirectories that never overwrite user files); Minimum Version Selection (MVS, Go's algorithm) for deterministic dependency resolution; pub.dev-style 0-100 quality scoring; `cos.lock` for reproducible, integrity-hashed installs.
- Architecture: a separate Go module (`cmd/cos/`, matching the `cmd/cos-test/` pattern) using Cobra (CLI), Lipgloss/Bubbletea (TUI), `gopkg.in/yaml.v3`, organized into `manifest/`, `resolver/` (MVS + feature unification + conflict detection), `registry/` (GitHub-based + centralized index + cache), `lockfile/`, `installer/` (coexistence + catalog updates + hook registration), and `scorer/` packages.
- Six-phase implementation plan: Phase 1 Foundation (types/parse/validate/`cos init`), Phase 2 Local Operations (`cos list`/`cos score`/`cos link`/`cos tree`), Phase 3 Registry+Install (GitHub-based fetch/cache/install/uninstall/lockfile), Phase 4 Resolution (MVS graph/conflict detection/`cos resolve`/`cos why`), Phase 5 Publishing (`cos pack`/`cos publish`/`cos audit`, min publish score 40/100), Phase 6 Advanced (workspaces, search, `cos outdated`, self-update, TUI dashboard) — each phase's tasks carry explicit acceptance criteria.
- Full `cos-package.yaml` schema documented field-by-field (identity, provides, exports with hook_event/hook_matcher, dependencies with semver-range syntax, groups for conditional install, features with default/non-default exports, lifecycle scripts, workspace monorepo support, platform requirements, publish include/exclude globs) plus a validation-rules table and minimal/bundle example manifests.
- `cos.lock` spec: `version`, `content_hash` (SHA-256 of the manifest, detects drift), and a `packages` map with `version`/`source`/`ref`/`integrity`/`features`/`dependencies` per locked package; lock-file operation table for install/add/uninstall/`--force` scenarios.
- Registry model: primary GitHub-based registry (clone-by-tag, cached under `~/.cos/cache/`, TTL 24h for release tags / 1h for branches, delegates auth to `git`); a future centralized index (`github.com/luum/cos-index`) resolving `@scope/name` -> `github.com/org/repo`, explicitly modeled on Agent Zero's `a0-plugins` marketplace pattern but adding semver/scoring/dependency-graph/CI-validated-PR features Agent Zero's pattern lacks; checksum verification (SHA-256) flags supply-chain tampering.
- Full CLI reference (`cos init/validate/install/uninstall/list/search/score/tree/why/outdated/audit/link/unlink/resolve/pack/publish/status/release/release-all/workspace`) with flags, exit codes, and example transcripts; `cos audit` enforces `rules/license-policy.md` (MIT/BSD/Apache=SAFE, LGPL/MPL=CAUTION, AGPL/SSPL/BSL/ELv2=BLOCKED, Unknown=BLOCKED); `cos release`/`cos release-all` support scoped per-package git tags (`@luum/quality-gates@1.0.0`) for independent in-monorepo versioning.
- Section 8 integration contract with the existing COS repo: coexists with `self-install.sh` symlinks by writing only under `cos/` subdirectories; `cos score` reuses `hooks/component-lint.sh` logic; auto-updates a bounded `## cos-installed skills`/`## cos-installed rules` section of `CATALOG.md`/`RULES-COMPACT.md`; auto-registers/deregisters hooks in `.claude/settings.json` by `cos/` path-prefix identification only, never touching non-cos entries.
- Section 12 "Universal Standard" positions `cos-package.yaml` as a transpilation source (like Babel) that `cos install` can project into 10+ IDE-specific formats (`.claude/`, `GEMINI.md`, `.cursor/rules/`, `.devinrules`, `.clinerules`, `AGENTS.md`, `.roo/`, `.continue/rules/`, `.augment/rules/`) via compatibility tiers (Full / Rules+MCP / Rules-only / None), and frames `cos` as complementary to MCP ("MCP: what tools can the AI use; cos: how should the AI behave").
- Appendices document the MVS algorithm (single-pass max-of-minimums, no backtracking, contrasted with SAT-based npm/pip/cargo resolution), the feature-unification algorithm (union of requested features across dependents, with a feature-export-collision error case), and a glossary of package-manager terms.
- Section 11 explicitly enumerates 10 "known issues" (no private registry server, no automatic conflict resolution, no binary distribution, no sandboxed script execution, no automatic hook ordering, no rollback on failed install, no cross-IDE package format beyond Claude Code, no signed packages, no dependency vendoring, no workspace hoisting) and a security-considerations table (malicious postinstall scripts, tag rewriting, typosquatting, dependency confusion, supply-chain attacks) with mitigations.

## Relations & where used
Explicitly modeled on npm, Go modules, Cargo, pip, pub.dev, Homebrew, and Nix (each source's specific contribution is tabulated in Section 9). References `cmd/cos-test/` as the sibling Go-module pattern, `rules/license-policy.md` for audit bucketing, and `hooks/component-lint.sh` for scoring logic.

## Status / caveats
This is a design document, not an implementation report — the document header itself labels it "Design Document v1.0," and every phase in Section 3 is framed as planned work with acceptance criteria to be met, not as completed. Section 11 "Known Issues and Limitations" and the "Future Enhancements (Not In Scope)" table make clear that most of this (registry server, package signing, IDE adapters beyond Claude Code, dependency vendoring, transactional installs) is explicitly deferred to later phases, not built.
