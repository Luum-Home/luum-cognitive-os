## What it is
The authoritative supply-chain hygiene reference for `luum-agent-os`: SBOM generation, dependency inventory, license classification, per-language pinning/provenance verdicts, and the security-vulnerability disclosure process. Scoped to the project's own runtime/dev dependencies (Python, Go, Node); third-party Claude plugins, vendored `reference/`, `dist/`, and examples are explicitly out of scope.

## Key mechanics
- **SBOM:** `sbom.json` at repo root, CycloneDX 1.6 JSON, generated by `syft 1.44.0`. Snapshot (2026-05-08): 241 raw / 205 deduped components, sha256 `5b5bf030...`. Byte-identical reproduction isn't expected (syft mints a fresh `serialNumber`/timestamp per run) — verify dependency-closure equality instead via deduped `(purl, version)` tuples. Regeneration command uses `syft scan dir:.` with an explicit exclude list (`.venv`, `node_modules`, `.git`, `dashboard/.next`, `.engram`, caches, `examples/`, `.claude/`, `reference/`, `dist/`). `grype sbom:./sbom.json` runs the vuln scan against the same SBOM.
- **Dependency inventory sources of truth:** `pyproject.toml`/`requirements.txt` (Python), `go.mod`/`go.sum` per Go module (root, `cmd/cos`, `cmd/cos-test`), `package.json` per Node root (root has no runtime deps — postinstall + bin shim only), `manifests/dependencies.yaml` (third-party CLIs). Heavy AI/ML extras (opik, langfuse, mlflow, cognee, memu, nemoguardrails, crawl4ai, litellm, deepeval, ragas, jupyter) are adoption-track, not installed by default.
- **License policy (4 buckets):** OK (MIT/BSD/Apache-2.0/ISC/MPL-2.0/PSF/Unlicense/CC0/FSL-1.1), REVIEW (LGPL/GPL — maintainer review + linkage documentation), UNKNOWN (missing metadata — manual classification), BLOCKED (AGPL/SSPL/BUSL — release blocker). Snapshot (post-H3 resolution, 2026-05-08): 0 BLOCKED, 15 REVIEW, 0 UNKNOWN, 186 OK, 201 total.
- **REVIEW entries (14 listed in table, doc also references "15" in the snapshot table):** all are platform-specific `@img/sharp-libvips-*` LGPL-3.0 binary variants pulled transitively into the optional `dashboard/` Next.js package. Disposition: APPROVED — libvips is dynamically linked, satisfying LGPL-3.0 §4; the dashboard is optional and not a runtime dependency of the core package.
- **UNKNOWN resolution:** originally 100 entries (39 PyPI, 57 Go, 3 GitHub Actions, 1 npm first-party) were all metadata-discovery gaps, not real ambiguity — individually resolved in `docs/09-Quality/legal/h3-unknown-license-resolution.md` to 99 OK / 1 REVIEW (`chardet`, LGPL-2.1-or-later) / 0 BLOCKED.
- **Pinning verdicts by stack:** Python `uv.lock` (pinned, ≥1200 sha256 hashes, `uv sync --locked`), Go `go.sum` per module (pinned, `go mod verify`), Bun/JS `bun.lock` per dependency root (pinned, `--frozen-lockfile --ignore-scripts`), root `package.json` (n/a — no lockfile by design), third-party CLIs (partial — named version, no digest pinned by the project), GitHub Actions (partial — floating major-version tags, not full-SHA).
- **Bun install policy:** every tracked JS root must set `bunfig.toml` `[install] ignoreScripts = true` (malware-prevention default blocking `preinstall`/`install`/`postinstall`/`prepare`); npm/pnpm/yarn lockfiles are forbidden in tracked roots. Audited by `scripts/check_bun_install_policy.py --json`.
- **Aspirational (§4.2, not yet enforced):** Sigstore/cosign signing (see `release-signing.md`), detached SBOM signature, SLSA provenance attestations (deferred to v1.0), reproducible builds.
- **Third-party CLI tool table (§4.3):** lists install path + operator-side verification per tool (jq, git, uv, python3, engram, gh, docker, aguara, mcp-scan, git-filter-repo, semgrep, parry-guard, promptfoo, garak, goreleaser, syft, grype) by criticality. Explicit gap: the project does not ship a frozen-digest manifest for these CLIs (tracked under ADR-238).
- **GitHub Actions pinning:** `.github/workflows/cos-binary-release.yml` currently pins floating major tags (`actions/checkout@v6`, etc.), not full commit SHAs — called out as a known, accepted-for-now gap (first-party/maintainer-trusted actions), tracked under ADR-238 for migration.
- **Vulnerability disclosure:** email `security@luum.home` or GitHub private vulnerability report; response SLA table by severity (Critical: 48h ack / 14d patch target through Low: 10 business days ack / next minor release); explicit in/out-of-scope component list; safe-harbor clause for good-faith research.

## Status / caveats
- Explicitly dated point-in-time snapshot ("Last regenerated: 2026-05-08"); the doc itself states the SBOM must be regenerated on any manifest change or quarterly, whichever comes first — treat counts (241/205/201/186/15/etc.) as of that date, not current.
- Internal inconsistency to flag: §3.2's summary table states "REVIEW: 15" and "TOTAL: 201," but §3.4's "REVIEW — 14 entries" heading lists exactly 14 rows in its table, and §3.6 is headed "OK — 91 entries" while listing counts that sum to 93 (49+22+13+3+3+1+1+1). These are source-document numbering inconsistencies, not fixed here per instructions — flagging for the final report.
- §3.2 also notes a *second*, fresher syft snapshot with a different raw-UNKNOWN count (186 raw / 157 unique) for the same "identical" 0-BLOCKED posture — two snapshot vintages are referenced in the same section without full reconciliation.
- CI enforcement of "SBOM regenerated on manifest change" is called out as not yet implemented ("tracked as a follow-up").
